## 五、核心文件职责说明

### 后端核心文件

| 文件路径 | 职责 |
|---------|------|
| `app/main.py` | FastAPI应用初始化、中间件配置、路由挂载 |
| `app/core/retrieval/router.py` | 查询路由分发（快车道/慢车道判断） |
| `app/core/retrieval/fast_lane.py` | 快车道检索（查询扩展+三路召回+重排+充分性判断+二次检索） |
| `app/core/retrieval/slow_lane.py` | 慢车道检索（工具调用循环，多跳推理，含3个检索工具） |
| `app/core/retrieval/sufficiency.py` | 召回充分性判断（决定是否触发二次检索） |
| `app/core/generation/generator.py` | 调用LLM生成答案，引用溯源 |
| `app/core/preprocessing/query_optimizer.py` | 提问优化（笼统度判断、澄清对话生成） |
| `app/core/preprocessing/query_rewriter.py` | 查询改写与扩展（HyDE、多Query生成） |
| `app/core/preprocessing/metadata_extractor.py` | 元数据提取（从查询提取过滤条件） |
| `app/core/embedding/embedder.py` | 文本向量化（稠密向量+稀疏向量） |
| `app/storage/vector_store.py` | Qdrant向量库操作（写入、混合检索、过滤） |
| `app/storage/cache.py` | Redis多级缓存（L1本地+L2/L3 Redis） |
| `app/db/models.py` | SQLAlchemy ORM模型定义 |
| `app/schemas/query.py` | 查询请求/响应的Pydantic模型 |
| `app/tasks/document_tasks.py` | 异步文档处理任务（解析、分块、入库） |
| `app/tasks/loop_engineering_tasks.py` | 闭环优化任务（Prompt迭代、术语扩展、难例分析、A/B决策） |

### 前端核心文件

| 文件路径 | 职责 |
|---------|------|
| `src/main.tsx` | 应用入口，挂载React根组件 |
| `src/App.tsx` | 根组件，配置路由和全局状态 |
| `src/api/client.ts` | Axios实例配置（拦截器、认证、错误处理） |
| `src/components/search/SearchBox.tsx` | 搜索框组件（输入、补全提示） |
| `src/components/search/ClarifyDialog.tsx` | 澄清对话组件（多级交互） |
| `src/components/result/AnswerCard.tsx` | 答案展示（Markdown渲染、引用标注） |
| `src/store/slices/querySlice.ts` | 查询状态管理（Redux Slice） |
| `src/hooks/useQuery.ts` | 查询逻辑封装（发起查询、处理响应） |
| `src/hooks/useWebSocket.ts` | WebSocket连接（流式输出） |

### 数据流水线核心文件

| 文件路径 | 职责 |
|---------|------|
| `dags/document_ingestion.py` | 文档入库流程编排（解析→分块→向量化→入库） |
| `dags/loop_engineering.py` | 闭环优化任务（Prompt迭代、术语扩展、难例分析） |
| `processors/pdf_parser.py` | PDF解析（PyMuPDF + OCR + 版面分析） |
| `processors/chunker.py` | 智能分块（父子块机制、条款/知识点分块） |
| `processors/metadata_extractor.py` | 元数据提取（标准号、版本、分类、电压等级） |

## 七、数据库表结构（核心）

```sql
-- 文档表
CREATE TABLE documents (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    title VARCHAR(500) NOT NULL,
    doc_type ENUM('standard', 'textbook', 'manual'),
    standard_no VARCHAR(100),
    version VARCHAR(50),
    publish_date DATE,
    status ENUM('valid', 'expired', 'draft'),
    file_path VARCHAR(500),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_standard_no (standard_no),
    INDEX idx_doc_type (doc_type)
);

-- 文档块表
CREATE TABLE chunks (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    document_id BIGINT NOT NULL,
    parent_chunk_id BIGINT,
    content TEXT NOT NULL,
    chunk_type ENUM('parent', 'child'),
    vector_id VARCHAR(100),
    metadata JSON,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (document_id) REFERENCES documents(id),
    INDEX idx_vector_id (vector_id)
);

-- 查询日志表
CREATE TABLE query_logs (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT,
    query TEXT NOT NULL,
    lane ENUM('fast', 'slow'),
    recall_success BOOLEAN,
    response_time INT,
    retry_count INT DEFAULT 0,        -- 二次检索次数
    vagueness_score FLOAT,            -- 笼统度评分（提问优化）
    strategy VARCHAR(30),             -- 提问优化策略 none/suggest/clarify_*
    feedback_score INT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_user_id (user_id),
    INDEX idx_created_at (created_at)
);

-- 澄清对话日志表（Loop Engineering闭环1、2依赖）
CREATE TABLE clarification_logs (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    original_query TEXT NOT NULL,
    strategy VARCHAR(30),             -- clarify_optional/clarify_required
    user_choice VARCHAR(100),         -- 用户选择的选项/custom_input/skip
    user_input TEXT,                  -- 用户自定义输入（用于术语挖掘）
    final_recall_success BOOLEAN,     -- 澄清后是否召回成功
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_user_choice (user_choice),
    INDEX idx_created_at (created_at)
);

-- 难例追踪表（Loop Engineering闭环3、4依赖）
CREATE TABLE badcase_tracking (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    query TEXT NOT NULL,
    expected_doc VARCHAR(200),        -- 期望命中的文档
    retrieved_docs JSON,              -- 实际召回的文档
    root_cause ENUM('chunking', 'embedding', 'reranking', 'missing_doc'),
    status ENUM('pending', 'fixed', 'ignored') DEFAULT 'pending',
    fixed_at TIMESTAMP NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_root_cause (root_cause),
    INDEX idx_status (status)
);
```
