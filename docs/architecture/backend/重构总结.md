## 二、重构内容

### 2.1 架构调整

**重构前**：
```
QueryService
  ↓
Preprocessor（包含所有预处理逻辑）
  ├─ TermNormalizer ✅
  ├─ QueryOptimizer ✅
  ├─ QueryRewriter ❌ 应该在 FastLane
  └─ MetadataExtractor ❌ 应该在 FastLane
```

**重构后**：
```
QueryService
  ↓
Preprocessor（仅核心预处理）
  ├─ TermNormalizer ✅
  └─ QueryOptimizer ✅
  ↓
Router（路由决策）
  ↓
FastLane（快车道）
  ├─ QueryRewriter ✅
  ├─ MetadataExtractor ✅
  ├─ 三路召回（TODO）
  └─ 两阶段重排（TODO）
  ↓
SlowLane（慢车道）
  └─ 工具调用循环（TODO）
```

## 四、代码位置说明

**重要说明**：
- `QueryRewriter` 和 `MetadataExtractor` 保留在 `preprocessing/` 目录（代码位置）
- 但它们**逻辑上属于快车道**，由 `retrieval/fast_lane.py` 调用
- 从 `preprocessing/__init__.py` 中移除了这两个组件的导出
- 这样做的原因：
  1. 最小化文件移动，降低重构风险
  2. 保持代码组织的相对稳定
  3. 通过导入关系明确逻辑归属

## 五、兼容性影响

### 5.1 Breaking Changes

1. **PreprocessingOutput 字段变更**
   - 移除：`expanded_queries`, `filters`, `metadata`
   - 这些字段现在在 `FastLaneResult` 中返回

2. **PreprocessingInput 字段变更**
   - 移除：`enable_expansion`, `max_expansions`
   - 这些参数现在在路由策略参数中控制

3. **模块导出变更**
   - `from app.core.preprocessing import QueryRewriter` ❌ 不再导出
   - `from app.core.preprocessing import MetadataExtractor` ❌ 不再导出

### 5.2 需要更新的代码

1. **测试文件**
   - `backend/test_preprocessing.py` - 需要更新测试用例

2. **API 响应**
   - `backend/app/api/v1/endpoints/query.py` - 已自动适配（通过 query_service）
