# 数据库设计文档

## 一、数据库选型

### 1.1 数据库架构

本系统采用**多数据库协同架构**，针对不同数据特性选择最优存储方案：

| 数据库 | 类型 | 用途 | 选型理由 |
|-------|------|------|---------|
| MySQL 8.0 | 关系型数据库 | 结构化数据、元数据、用户数据 | 成熟稳定、事务支持、丰富的查询能力 |
| Redis 7.x | 键值数据库 | 缓存、会话、队列 | 高性能、支持多种数据结构 |
| Qdrant | 向量数据库 | 文档向量、混合检索 | 原生混合检索、Payload过滤强大 |
| Elasticsearch 8.x | 全文检索引擎 | 全文检索、日志分析 | BM25算法、自定义分词 |
| MinIO | 对象存储 | 原始文件、图片 | S3兼容、私有化部署 |

    DEFAULT CHARACTER SET utf8mb4

### 2.2 核心表结构（共12张表）

本系统设计了12张核心表，支持完整的RAG业务流程和Loop Engineering闭环优化：

| 表名 | 用途 | 关键特性 |
|------|------|---------|
| **documents** | 文档元数据 | 版本管理、替代关系追踪、扫描件支持 |
| **chunks** | 文档分块 | 父子块结构、支持图片描述/表格摘要类型 |
| **images** | 图片元数据 | 关联VLM描述Chunk，支持图文检索 |
| **tables** | 表格元数据 | 关联摘要Chunk，支持表格检索 |
| **users** | 用户管理 | 角色权限、统计信息 |
| **query_logs** | 查询日志 | 完整查询链路、答案存储 |
| **clarification_logs** | 澄清对话 | 支持闭环1、2（Prompt优化、术语扩展） |
| **badcase_tracking** | 难例追踪 | 支持闭环3、4（难例分析、测试集扩充） |
| **term_dictionary** | 术语词典 | 来源追踪、自动挖掘 |
| **test_cases** | 测试用例 | 评测任务、回归测试 |
| **clause_references** | 条款引用关系 | 自动展开关联条款 |
| **ab_experiments** | A/B测试 | 支持闭环5（自动决策） |

#### 2.2.2 文档块表 (chunks)

存储文档分块信息，支持父子块结构。

**表结构**：

| 字段名 | 类型 | 约束 | 说明 |
|-------|------|------|------|
| **id** | BIGINT UNSIGNED | PK, AUTO_INCREMENT | 块ID |
| **document_id** | BIGINT UNSIGNED | NOT NULL, FK | 文档ID |
| **parent_chunk_id** | BIGINT UNSIGNED | FK | 父块ID（子块时有值） |
| **内容字段** | | | |
| content | TEXT | NOT NULL | 文本内容 |
| content_hash | VARCHAR(64) | NOT NULL | 内容哈希（跨文档允许重复，复合唯一） |
| chunk_type | ENUM | NOT NULL, DEFAULT 'parent' | parent/child |
| content_type | ENUM | NOT NULL, DEFAULT 'text' | text/image_description/table_summary |
| related_resource_id | BIGINT UNSIGNED | | 关联资源ID（图片ID或表格ID） |
| related_resource_type | VARCHAR(20) | | 关联资源类型：image/table |
| **向量信息** | | | |
| vector_id | VARCHAR(100) | | Qdrant中的向量ID |
| has_dense_vector | BOOLEAN | DEFAULT FALSE | 是否有稠密向量 |
| has_sparse_vector | BOOLEAN | DEFAULT FALSE | 是否有稀疏向量 |
| **位置信息** | | | |
| page_start | INT | | 起始页码 |
| page_end | INT | | 结束页码 |
| chapter | VARCHAR(200) | | 章节号 |
| section | VARCHAR(200) | | 节号 |
| clause | VARCHAR(200) | | 条款号 |
| position_in_doc | INT | | 在文档中的位置序号 |
| **元数据** | | | |
| metadata | JSON | | 扩展元数据 |
| related_chunk_ids | JSON | | 关联块IDs（引用的其他条款） |
| **统计信息** | | | |
| token_count | INT | | Token数量 |
| char_count | INT | | 字符数 |
| **时间戳** | | | |
| created_at | TIMESTAMP | DEFAULT CURRENT_TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | ON UPDATE | 更新时间 |

**索引**：
- `idx_document_id` (document_id)
- `idx_parent_chunk_id` (parent_chunk_id)
- `idx_vector_id` (vector_id)
- `idx_chunk_type` (chunk_type)
- `idx_content_type` (content_type)
- `idx_clause` (clause)
- `uk_doc_content_hash` (document_id, content_hash) UNIQUE — 同文档内去重，跨文档允许重复

**外键**：
- `document_id` → `documents(id)` ON DELETE CASCADE
- `parent_chunk_id` → `chunks(id)` ON DELETE CASCADE

<details>
<summary>📝 SQL建表语句（点击展开）</summary>

```sql
CREATE TABLE chunks (
    id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    document_id BIGINT UNSIGNED NOT NULL,
    parent_chunk_id BIGINT UNSIGNED,
    
    content TEXT NOT NULL,
    content_hash VARCHAR(64) NOT NULL,
    chunk_type ENUM('parent', 'child') NOT NULL DEFAULT 'parent',
    content_type ENUM('text', 'image_description', 'table_summary') NOT NULL DEFAULT 'text',
    related_resource_id BIGINT UNSIGNED COMMENT '关联资源ID（图片/表格）',
    related_resource_type VARCHAR(20) COMMENT '关联资源类型：image/table',
    
    vector_id VARCHAR(100),
    has_dense_vector BOOLEAN DEFAULT FALSE,
    has_sparse_vector BOOLEAN DEFAULT FALSE,
    
    page_start INT,
    page_end INT,
    chapter VARCHAR(200),
    section VARCHAR(200),
    clause VARCHAR(200),
    position_in_doc INT,
    
    metadata JSON,
    related_chunk_ids JSON COMMENT '关联块IDs',
    token_count INT,
    char_count INT,
    
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    FOREIGN KEY (document_id) REFERENCES documents(id) ON DELETE CASCADE,
    FOREIGN KEY (parent_chunk_id) REFERENCES chunks(id) ON DELETE CASCADE,
    
    INDEX idx_document_id (document_id),
    INDEX idx_parent_chunk_id (parent_chunk_id),
    INDEX idx_vector_id (vector_id),
    INDEX idx_chunk_type (chunk_type),
    INDEX idx_content_type (content_type),
    INDEX idx_clause (clause),
    UNIQUE KEY uk_doc_content_hash (document_id, content_hash)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='文档块表';
```
</details>

## 八、性能优化建议

### 8.1 MySQL 优化

1. **索引优化**：根据查询模式调整索引
2. **分区表**：query_logs 按月分区
3. **读写分离**：主库写，从库读
4. **连接池**：SQLAlchemy pool_size=10, max_overflow=20

### 8.2 Redis 优化

1. **内存淘汰**：maxmemory-policy allkeys-lru
2. **持久化**：RDB + AOF
3. **集群化**：哨兵模式（1主2从）

### 8.3 Qdrant 优化

1. **量化**：Scalar Quantization 节省内存
2. **分片**：数据量大时启用分布式模式
3. **批量操作**：批量插入向量（batch_size=100）
