# 多轮对话设计

## 1. 现状分析

### 1.1 已有基础

`conversation_id` 字段贯穿整个调用栈，但只做"透传存储"，没有任何读取逻辑：

| 位置 | 现状 |
|------|------|
| `schemas/query.py` | `QueryRequest.conversation_id: Optional[str]` — 字段存在 |
| `api/v1/endpoints/query.py` | 透传给 `QueryService.execute_query()` |
| `services/query_service.py` | 透传进 `user_context`，最终写入 `QueryLog.conversation_id` |
| `db/models.py:QueryLog` | 存有 `conversation_id`、`query`、`normalized_query`、`answer`、`citations` |
| `db/models.py:QueryLog` | 索引 `idx_conversation_id` 已创建 |

### 1.2 缺失部分

1. **历史读取**：`execute_query()` 没有根据 `conversation_id` 查询历史轮次
2. **指代消解**：不处理"它/该标准/上面提到的"等上文引用
3. **Prompt 注入**：`generator.py::build_prompt()` 签名无 `history` 参数
4. **上下文感知路由**：路由器不了解对话语境，可能将追问错误路由到慢车道

---

## 2. 设计目标

- 支持同一 `conversation_id` 下的追问与上下文关联
- 指代消解：将指代词替换为明确实体，再进入正常检索流程
- 历史注入：在生成阶段提供最近 N 轮对话作为上下文
- 不改变数据库 schema（`QueryLog` 已足够）
- 不影响单轮查询性能（`conversation_id=None` 时完全 bypass）

---

## 3. 架构设计

### 3.1 整体流程

```
QueryRequest(query, conversation_id)
        │
        ▼
[服务层] 按 conversation_id 查最近 K 轮历史（QueryLog 在请求末尾写入，无读到自身风险）
        │
        ▼  history = [{query, answer}, ...]
[指代消解] 若检测到指代词 → LLM 改写 query → resolved_query
        │  否则直接透传
        ▼  resolved_query
[预处理 → 路由 → 快/慢车道]  (resolved_query 作为输入，不影响现有流程)
        │
        ▼  retrieval_result
[生成] build_prompt(resolved_query, chunks, history)
        │
        ▼
[存储] QueryLog.query          = query (原始用户输入，保留不变)
       QueryLog.normalized_query = optimized_query (经指代消解+预处理后的最终形式)
       QueryLog.conversation_id  = conversation_id
```

### 3.2 历史窗口策略

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `MAX_HISTORY_TURNS` | 5 | 最多注入最近 5 轮（query+answer 对） |
| `MAX_HISTORY_TOKENS` | 2000 | Token 预算超出时从最早轮次截断 |
| `HISTORY_RELEVANCE_THRESHOLD` | — | 暂不做相关性过滤，按时间倒序取 K 轮 |

超出 token 预算时按从旧到新的顺序丢弃，优先保留最近轮次。

## 4. 实现方案

### 4.1 历史查询 — `db/repositories/query_repo.py`

`QueryLog` 在请求末尾写入，加载历史时当前请求的 log 还不存在，无需任何排除逻辑。
`order_by` 加 `id.desc()` 作为同毫秒时间戳的稳定排序保障。

```python
def get_conversation_history(
    self,
    conversation_id: str,
    limit: int = 5,
) -> List[Dict[str, str]]:
    """
    返回格式: [{"query": "...", "answer": "..."}]，按 created_at 升序（旧→新）
    """
    stmt = (
        select(QueryLog.query, QueryLog.answer)
        .where(
            QueryLog.conversation_id == conversation_id,
            QueryLog.answer.isnot(None),
        )
        .order_by(QueryLog.created_at.desc(), QueryLog.id.desc())
        .limit(limit)
    )
    rows = self.db.execute(stmt).all()  # 同步 Session，非 async
    return [{"query": r.query, "answer": r.answer} for r in reversed(rows)]
```

### 4.2 指代消解 — `core/preprocessing/coreference_resolver.py`

`CoreferenceResolver` 是同步类（`LLMClient.chat()` 为阻塞调用），不带 `async`。
实例化为 `QueryService` 成员变量，避免每次请求新建。

```python
class CoreferenceResolver:
    _COREFERENCE_SIGNALS = re.compile(
        r'(它|该|此|这个|上述|上面|前面|之前提到|刚才说的|其中|其(?![他]))'
    )
    _ELLIPSIS_SIGNALS = re.compile(
        r'^(还有|另外|此外|同时|以及|那么|那)(哪些|什么|怎么|如何|是否|有没有)'
    )

    def resolve(self, query: str, history: List[Dict[str, str]]) -> str:
        """返回消解后的 query；无需消解或发生异常则原样返回（降级）。"""
        from app.config import settings
        if not settings.COREFERENCE_RESOLUTION_ENABLED or not history:
            return query
        if not self._needs_resolution(query):
            return query
        try:
            return self._llm_resolve(query, history[-2:])
        except Exception as e:
            logger.warning(f"[CoreferenceResolver] 降级使用原始 query: {e}")
            return query

    def _needs_resolution(self, query: str) -> bool:
        return bool(
            self._COREFERENCE_SIGNALS.search(query)
            or self._ELLIPSIS_SIGNALS.match(query)
        )

    def _llm_resolve(self, query: str, recent: List[Dict]) -> str:
        from app.core.generation.llm_client import get_llm_client
        history_text = "\n".join(
            f"用户：{h['query']}\n助手：{h['answer'][:300]}"
            for h in recent
        )
        prompt = (
            f"以下是对话历史（最近几轮）：\n{history_text}\n\n"
            f"当前用户问题：{query}\n\n"
            "请将当前问题中的指代词替换为明确的实体名称，使问题可以独立理解。"
            "只输出改写后的问题，不要任何解释。如果问题已经足够明确，原样输出。"
        )
        # LLMClient.chat() 是同步阻塞调用（非 async）
        return get_llm_client().chat(
            messages=[{"role": "user", "content": prompt}],
            max_tokens=200,
            temperature=0.0,
        ).strip() or query
```

### 4.3 服务层集成 — `services/query_service.py`

`CoreferenceResolver` 作为 `QueryService` 成员变量（`__init__` 初始化），不在每次请求中新建。
`resolve()` 是同步调用，不带 `await`。

```python
def __init__(self, db=None):
    ...
    self.query_log_repo = QueryLogRepository(db) if db else None
    self.coreference_resolver = CoreferenceResolver()

async def execute_query(self, query, ..., conversation_id=None, ...):

    # ── 多轮对话：加载历史 ──────────────────────────────────────────
    conversation_history: List[Dict[str, str]] = []
    if conversation_id and self.query_log_repo:
        conversation_history = self.query_log_repo.get_conversation_history(
            conversation_id, limit=settings.MAX_HISTORY_TURNS
        )

    # ── 指代消解（仅在有历史时触发，澄清流程跳过） ─────────────────
    resolved_query = query
    if conversation_history and refined_query is None:
        resolved_query = self.coreference_resolver.resolve(query, conversation_history)
        if resolved_query != query:
            logger.info(f"[MultiTurn] 指代消解: {query!r} → {resolved_query!r}")

    # resolved_query 进入预处理；query（原始输入）写入 QueryLog.query
    ...

    # ── 生成阶段注入历史 ────────────────────────────────────────────
    generation_result = await self.generator.generate(
        query=preprocessing_output.optimized_query,
        chunks=chunks_for_generation,
        history=conversation_history if conversation_history else None,
    )

    # ── L4 缓存：多轮对话时跳过缓存（conversation_id 传入决策） ────
    cached_gen = cache.get_generation(query, chunk_contents, conversation_id)
    ...
    cache.set_generation(query, chunk_contents, {...}, conversation_id)
```

### 4.4 生成层集成 — `core/generation/generator.py`

`build_prompt()` 新增 `history` 参数，内置 token 预算截断（从最旧轮次丢弃）。
`history[-settings.MAX_HISTORY_TURNS:]` 的冗余切片已去除（历史加载时已限制数量）。

```python
def build_prompt(
    self,
    query: str,
    chunks: List[RerankResult],
    history: Optional[List[Dict[str, str]]] = None,
) -> str:
    ...
    history_section = self._build_history_section(history)
    ...

def _build_history_section(self, history) -> str:
    """按 MAX_HISTORY_TOKENS 预算从旧到新截断，每轮 answer 限 500 字符。"""
    if not history:
        return ""
    MAX_ANSWER_CHARS = 500
    turns = [{"query": h["query"], "answer": h["answer"][:MAX_ANSWER_CHARS]} for h in history]
    token_budget = settings.MAX_HISTORY_TOKENS
    while turns:
        total_chars = sum(len(t["query"]) + len(t["answer"]) for t in turns)
        if int(total_chars / 1.5) <= token_budget:
            break
        turns.pop(0)  # 丢弃最旧一轮
    if not turns:
        return ""
    lines = [line for t in turns for line in (f"用户：{t['query']}", f"助手：{t['answer']}")]
    return "\n\n对话历史（仅供理解上下文，不作为答案依据）：\n" + "\n".join(lines)
```

## 5. 数据库变更

**无需改动 schema。**

`QueryLog` 表已具备：
- `conversation_id`（已有索引）
- `query`、`answer`（历史读取的两个核心字段）
- `created_at`（用于按时间排序）

## 6. API 变更

**无需改动接口签名。**`QueryRequest.conversation_id` 字段已存在，前端只需在追问时带上同一 `conversation_id` 即可。

前端约定：
- 新会话：不传 `conversation_id`，或生成新 UUID
- 追问：复用上一轮响应中携带的同一 `conversation_id`
- 查询历史记录：`GET /api/v1/query/logs?conversation_id=xxx`（接口已实现）

## 7. 边界条件与风险

| 场景 | 处理方式 |
|------|---------|
| `conversation_id=None` | 完全跳过历史加载和指代消解，行为与现在相同 |
| 历史为空（首轮） | 跳过指代消解，`history_section` 为空 |
| LLM 指代消解失败/超时 | 降级：直接使用原始 query，记录 warning |
| 历史 answer 极长 | `_build_history_section` 截断至前 500 字符再拼 prompt |
| 同一 conversation_id 并发请求 | QueryLog 在请求末尾写入，加载历史时不存在读到自身风险 |
| 多轮对话 L4 生成缓存 | `get_generation`/`set_generation` 传入 `conversation_id`，非 None 时跳过缓存 |
| Redis session（06-数据模型） | Redis session 存储澄清状态等短期数据；MySQL query_logs 存历史轮次，两者职责不重叠 |

### 7.1 L4 缓存失效处理

多轮对话下相同的 query + chunks 可能因历史不同而答案不同。最简且正确的策略：**有 `conversation_id` 时完全跳过 L4 缓存**，避免不同历史状态下命中错误缓存。

```python
# cache.py — get_generation / set_generation
def get_generation(self, query, chunk_contents, conversation_id=None):
    if not settings.CACHE_GENERATION_ENABLED or conversation_id:
        return None   # 多轮对话绕过缓存
    ...

def set_generation(self, query, chunk_contents, result, conversation_id=None):
    if not settings.CACHE_GENERATION_ENABLED or conversation_id:
        return False
    ...
```

> 注：使用 `conversation_id` 字符串本身作为缓存键哈希的一部分是错误的——同一会话第 2 轮和第 5 轮的 `conversation_id` 相同但历史不同，会互相污染缓存。直接跳过比引入错误 key 更安全。
