## 一、整体一致性评估

1. **核心架构理念**
   - 三份文档都采用**快慢双通道**设计

## 二、需要修正的不一致问题

### 🔴 问题1：预处理顺序的差异

**design.md（3.3.1节）的顺序**：
```
查询预处理（共用） → 路由决策 → 快车道专属预处理
  ├─ 术语标准化
  ├─ 提问优化（笼统度判断）
  ├─ 结构化识别
  └─ 复杂度路由判断
       ↓
  [快车道] → 查询扩展 + 元数据提取
  [慢车道] → 直接进入工具调用
```

**16-业务流程图.md（第8-20行）的顺序**：
```
用户输入查询 → 术语标准化 → 提问优化判断 → 复杂度路由
  ↓
快车道 → 元数据提取 + 查询扩展 → 三路召回
慢车道 → 工具调用循环
```

**08-RAG功能层次与状态机.md（第143-155行）的描述**：
```
原始查询 → 术语标准化 → 笼统度评估 → 清晰查询 → 查询改写 → 元数据提取 → 传递给路由层
```

**问题所在**：
- design.md 明确说明：**查询改写和元数据提取是快车道专属**，在路由决策后执行
- 08文档错误地将"查询改写 → 元数据提取"放在了路由层**之前**
- 16-业务流程图正确地将它们放在快车道分支内

**修正方案**：
需要更新 `08-RAG功能层次与状态机.md` 第143-155行的状态转换图，明确：
1. 预处理层只负责：术语标准化 → 笼统度评估
2. 查询改写和元数据提取是**快车道的一部分**，在路由后执行
