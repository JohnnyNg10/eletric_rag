# 召回层设计

## 1. 概述

### 1.1 定位

召回层（Recall Layer）是 RAG 系统检索引擎的第一级，负责从海量知识库中快速筛选出可能相关的文档块。召回层追求"宁可错召不可漏召"的原则，通过多路并行召回策略提升召回覆盖率，为后续重排层提供充足候选集。

### 1.2 在 RAG 流水线中的位置

```
预处理层 → 路由层 → [召回层] → 重排层 → 生成层
                      ↑
            快车道/慢车道都会使用
```

**处理顺序**：
1. **预处理层**：术语标准化 + 笼统度评估（可能返回澄清选项）
2. **路由层**：决策快车道或慢车道
3. **快车道专属前置**：查询改写（生成 2-3 个扩展查询）+ 元数据提取（生成过滤条件）
4. **召回层**：三路并行召回 → 合并去重 → Top50
5. **重排层**：两阶段重排 → 充分性判断 → Top5
6. **生成层**：LLM 生成答案 + 引用溯源

### 1.3 核心职责

1. **多路并行召回**：向量召回、关键词召回、结构化召回同时执行
2. **初步筛选**：从数万/数十万文档块中快速召回可能相关的候选集
3. **结果合并去重**：将三路召回结果按 chunk_id 去重，取 Top50
4. **快速响应**：召回阶段延迟目标 < 200ms

## 2. 三路召回策略

### 2.1 向量召回 (Vector Recall)

**技术方案**：Qdrant 稠密向量 + 稀疏向量混合检索

**模型**：
- **稠密向量**：`bge-large-zh-v1.5` (1024 维)
  - 擅长语义相似度匹配
  - 适合模糊查询、同义词查询
- **稀疏向量**：`efficient-splade` (关键词增强)
  - 弥补稠密向量对专业术语的不敏感
  - 适合包含专业术语的查询

**召回量**：Top 20

**Qdrant 混合检索策略**：
```python
# 稠密向量检索
dense_results = qdrant_client.search(
    collection_name="power_standards",
    query_vector=("dense", dense_embedding),
    limit=20,
    query_filter=filters  # 元数据过滤（电压等级、标准类型等）
)

# 稀疏向量检索
sparse_results = qdrant_client.search(
    collection_name="power_standards",
    query_vector=("sparse", sparse_embedding),
    limit=20,
    query_filter=filters
)

# 混合检索（RRF 融合）
hybrid_results = qdrant_client.search(
    collection_name="power_standards",
    query_vector=[
        ("dense", dense_embedding, 0.6),   # 权重 0.6
        ("sparse", sparse_embedding, 0.4)  # 权重 0.4
    ],
    limit=20,
    query_filter=filters
)
```

**优势**：
- 语义相似度高，适合"换个说法问同一件事"
- 稀疏向量增强专业术语匹配
- 支持元数据过滤（电压等级、标准类型、发布时间等）

**适用场景**：
- "隔离开关的安装要求" → 召回包含"隔离开关"、"安装"、"技术条件"的块
- "10kV 配电装置与建筑物的距离" → 召回包含"配电装置"、"安全距离"、"建筑物间距"的块

### 2.2 关键词召回 (Keyword Recall)

**技术方案**：Elasticsearch BM25 算法

**召回量**：Top 20

**查询策略**：
```json
{
  "query": {
    "bool": {
      "must": [
        {
          "multi_match": {
            "query": "10kV配电装置与建筑物距离",
            "fields": ["content^2", "title^3", "clause^1.5"],
            "type": "best_fields",
            "operator": "or"
          }
        }
      ],
      "filter": [
        {"term": {"voltage_level": "10kV"}},
        {"term": {"doc_type": "standard"}},
        {"term": {"status": "valid"}}
      ]
    }
  },
  "size": 20
}
```

**优势**：
- 精确匹配专业术语（"10kV"、"隔离开关"、"GB 50057-2010"）
- BM25 算法对词频和文档长度的平衡处理
- 支持布尔查询和过滤条件

**适用场景**：
- 包含明确标准号的查询："GB 50057-2010 对接地电阻的要求"
- 包含具体参数的查询："10kV 配电装置的安全距离"
- 包含专业术语的查询："刀闸"（已被术语标准化为"隔离开关"）

### 2.3 结构化召回 (Structured Recall)

**技术方案**：MySQL 精确查询（基于 `documents` 和 `chunks` 表）

**召回量**：Top 10

**查询策略**：
```sql
-- 场景1: 精确标准号查询
SELECT c.* FROM chunks c
JOIN documents d ON c.document_id = d.id
WHERE d.standard_no = 'GB 50057-2010'
  AND d.status = 'valid'
ORDER BY c.position_in_doc
LIMIT 10;

-- 场景2: 精确条款号查询
SELECT * FROM chunks
WHERE clause = '3.2.1'
  AND document_id IN (
    SELECT id FROM documents 
    WHERE standard_no = 'GB 50057-2010'
  )
LIMIT 10;

-- 场景3: 电压等级 + 分类组合查询
SELECT c.* FROM chunks c
JOIN documents d ON c.document_id = d.id
WHERE d.voltage_level = '10kV'
  AND d.category = '配电'
  AND d.status = 'valid'
ORDER BY d.reference_count DESC, c.position_in_doc
LIMIT 10;
```

**优势**：
- 零误差精确定位（标准号、条款号、设备型号）
- 支持复杂的组合查询（电压等级 + 专业分类 + 有效性状态）
- 可追踪替代关系（`replaced_by`、`replaces` 字段）

**适用场景**：
- 明确标准号："GB 50057-2010 的接地电阻要求"
- 明确条款号："DL/T 621-1997 第 3.2.1 条"
- 结构化查询："10kV 配电装置相关的所有有效标准"

### 2.4 三路召回流程

```python
class MultiPathRecall:
    """三路并行召回"""
    
    def __init__(self):
        self.vector_recall = VectorRecall()      # Qdrant 向量召回
        self.keyword_recall = KeywordRecall()    # Elasticsearch BM25
        self.structured_recall = StructuredRecall()  # MySQL 精确查询
    
    async def recall(
        self, 
        query: str, 
        filters: Dict[str, Any],
        expanded_queries: List[str] = None
    ) -> List[Chunk]:
        """
        三路并行召回
        
        Args:
            query: 标准化后的查询
            filters: 元数据过滤条件（电压等级、标准类型等）
            expanded_queries: 扩展查询列表（快车道生成）
        
        Returns:
            List[Chunk]: 去重后的 Top50 文档块
        """
        # 步骤1: 三路并行召回
        vector_task = self.vector_recall.search(query, filters, top_k=20)
        keyword_task = self.keyword_recall.search(query, filters, top_k=20)
        structured_task = self.structured_recall.search(query, filters, top_k=10)
        
        # 等待所有任务完成
        vector_chunks, keyword_chunks, structured_chunks = await asyncio.gather(
            vector_task, keyword_task, structured_task
        )
        
        # 步骤2: 合并去重（按 chunk_id）
        all_chunks = self._merge_deduplicate([
            vector_chunks,
            keyword_chunks,
            structured_chunks
        ])
        
        # 步骤3: 保留召回来源信息（用于后续分析）
        for chunk in all_chunks:
            chunk.recall_sources = []
            if chunk.id in [c.id for c in vector_chunks]:
                chunk.recall_sources.append("vector")
            if chunk.id in [c.id for c in keyword_chunks]:
                chunk.recall_sources.append("keyword")
            if chunk.id in [c.id for c in structured_chunks]:
                chunk.recall_sources.append("structured")
        
        # 步骤4: 返回 Top50
        return all_chunks[:50]
    
    def _merge_deduplicate(self, chunk_lists: List[List[Chunk]]) -> List[Chunk]:
        """
        合并去重
        
        策略：
        - 按 chunk_id 去重
        - 保留分数最高的副本
        - 按综合分数排序
        """
        chunk_map = {}
        
        for chunks in chunk_lists:
            for chunk in chunks:
                if chunk.id not in chunk_map:
                    chunk_map[chunk.id] = chunk
                else:
                    # 保留分数更高的副本
                    if chunk.score > chunk_map[chunk.id].score:
                        chunk_map[chunk.id] = chunk
        
        # 按分数排序
        merged_chunks = sorted(
            chunk_map.values(), 
            key=lambda c: c.score, 
            reverse=True
        )
        
        return merged_chunks
```

## 3. 数据库设计集成

### 3.1 documents 表（文档元数据）

召回层依赖 `documents` 表的以下字段进行过滤和排序：

| 字段 | 召回层用途 |
|------|-----------|
| `standard_no` | 结构化召回精确匹配 |
| `doc_type` | 过滤文档类型（standard/textbook/manual/regulation） |
| `category` | 过滤专业分类（配电/变电/继保/高压/输电） |
| `voltage_level` | 过滤电压等级（10kV/35kV/110kV/220kV/500kV） |
| `status` | 过滤有效性（valid/expired/draft） |
| `reference_count` | 结构化召回排序依据（被引用次数越多优先级越高） |
| `replaced_by` / `replaces` | 追踪标准替代关系 |

### 3.2 chunks 表（文档块）

召回层从 `chunks` 表检索文档块，依赖以下字段：

| 字段 | 召回层用途 |
|------|-----------|
| `document_id` | 关联到 `documents` 表获取元数据 |
| `content` | 关键词召回的主要匹配字段 |
| `vector_id` | 向量召回时关联 Qdrant 向量 |
| `has_dense_vector` / `has_sparse_vector` | 判断是否可用于向量召回 |
| `clause` | 结构化召回精确匹配条款号 |
| `chapter` / `section` | 结构化召回辅助定位 |
| `position_in_doc` | 结构化召回排序依据 |
| `metadata` | 存储扩展元数据（JSON），用于高级过滤 |
| `related_chunk_ids` | 关联块 IDs，用于上下文扩展 |

### 3.3 召回层数据流

```
[查询] 
  ↓
[元数据提取] → filters = {voltage_level: "10kV", category: "配电"}
  ↓
[三路并行召回]
  ├─ [Qdrant] → query documents.chunks WHERE vector_id IN (...)
  ├─ [Elasticsearch] → query chunks.content MATCH "..."
  └─ [MySQL] → query documents JOIN chunks WHERE standard_no/clause/...
  ↓
[合并去重] → chunk_id 去重，保留分数最高的副本
  ↓
[Top50] → 传递给重排层
```

## 4. 召回策略选择

### 4.1 快车道召回

**特点**：查询改写 + 元数据提取 + 三路召回

```python
# 快车道召回流程
expanded_queries = ["原查询", "同义变体1", "同义变体2"]
filters = {
    "voltage_level": "10kV",
    "category": "配电",
    "doc_type": "standard",
    "status": "valid"
}

# 对每个扩展查询分别召回，取并集
all_chunks = []
for query in expanded_queries:
    chunks = await multi_path_recall.recall(query, filters)
    all_chunks.extend(chunks)

# 去重并返回 Top50
final_chunks = merge_deduplicate(all_chunks)[:50]
```

**召回量**：
- 每个扩展查询召回 Top50
- 3 个扩展查询 → 最多 150 个候选块
- 去重后返回 Top50

### 4.2 慢车道召回

**特点**：多步推理，每步调用召回层

```python
# 慢车道多步推理示例
step1_query = "GB 50057-2010 对接地装置的要求"
step1_chunks = await multi_path_recall.recall(step1_query, filters)

# 从召回结果中提取关联标准
related_standards = extract_related_standards(step1_chunks)

# 第二步：召回关联标准的内容
step2_query = f"DL/T 621-1997 对接地电阻的规定"
step2_chunks = await multi_path_recall.recall(step2_query, filters)

# 合并两步召回结果
final_chunks = merge_deduplicate([step1_chunks, step2_chunks])[:50]
```

**召回量**：每步召回 Top50，最多 3 步

## 5. 性能优化

### 5.1 并行召回

三路召回采用 `asyncio.gather()` 并行执行，理论延迟为最慢通道的延迟：

| 通道 | 平均延迟 |
|------|---------|
| 向量召回（Qdrant） | ~80ms |
| 关键词召回（ES） | ~50ms |
| 结构化召回（MySQL） | ~20ms |
| **并行总延迟** | **~80ms** |

### 5.2 向量索引优化

**Qdrant HNSW 索引参数**：
```python
qdrant_client.create_collection(
    collection_name="power_standards",
    vectors_config={
        "dense": VectorParams(
            size=1024,
            distance=Distance.COSINE,
            hnsw_config=HnswConfigDiff(
                m=16,              # 每个节点的邻居数（默认 16）
                ef_construct=200,  # 构建时的探索深度（默认 100）
            )
        ),
        "sparse": VectorParams(
            size=30522,  # SPLADE 词表大小
            distance=Distance.DOT,
            on_disk=True  # 稀疏向量存储在磁盘
        )
    }
)
```

**搜索时参数**：
```python
qdrant_client.search(
    collection_name="power_standards",
    query_vector=query_embedding,
    limit=20,
    search_params=SearchParams(
        hnsw_ef=128,  # 搜索时的探索深度（默认 128）
        exact=False   # 近似搜索（ANN）
    )
)
```

### 5.3 Elasticsearch 优化

**索引设置**：
```json
{
  "settings": {
    "number_of_shards": 3,
    "number_of_replicas": 1,
    "refresh_interval": "30s",
    "analysis": {
      "analyzer": {
        "power_standard_analyzer": {
          "type": "custom",
          "tokenizer": "ik_max_word",
          "filter": ["lowercase", "synonym_filter"]
        }
      }
    }
  }
}
```

**查询优化**：
- 使用 `multi_match` 查询，对 `title`、`clause`、`content` 字段赋予不同权重
- 使用 `filter` 而非 `must` 进行元数据过滤（不计入评分，可缓存）

### 5.4 MySQL 查询优化

**索引策略**（已在 `documents` 和 `chunks` 表创建）：
- `idx_standard_no` (documents.standard_no)
- `idx_clause` (chunks.clause)
- `idx_document_id` (chunks.document_id)
- `idx_vector_id` (chunks.vector_id)
- `idx_voltage_level` (documents.voltage_level)

**查询优化**：
- 使用 `EXPLAIN` 验证索引使用
- 避免 `SELECT *`，只查询必要字段
- 使用 `LIMIT` 限制返回结果

## 6. 召回质量评估

### 6.1 召回率 (Recall@K)

**定义**：在 Top K 召回结果中，包含正确答案的比例

**目标**：
- Recall@50 ≥ 95%（召回层目标：尽可能不漏召）
- Recall@20 ≥ 90%

**测试方法**：
```python
def evaluate_recall(test_cases: List[TestCase], k: int = 50) -> float:
    """
    评估召回率
    
    Args:
        test_cases: 测试用例（包含查询和标注的正确块ID）
        k: Top K
    
    Returns:
        Recall@K
    """
    hit_count = 0
    for case in test_cases:
        recalled_chunks = await multi_path_recall.recall(case.query, case.filters)
        recalled_ids = [c.id for c in recalled_chunks[:k]]
        
        if case.ground_truth_chunk_id in recalled_ids:
            hit_count += 1
    
    return hit_count / len(test_cases)
```
