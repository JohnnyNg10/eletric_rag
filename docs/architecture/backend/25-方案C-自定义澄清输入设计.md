# 方案C：自定义澄清输入设计与实施

> **定位**：为澄清功能增加自定义输入兜底，覆盖系统生成选项无法满足的长尾需求  
> **前置阅读**：[01-澄清功能设计分析.md](../clarification/01-澄清功能设计分析.md)、[15-阶段B-预处理路由一体化设计.md](./15-阶段B-预处理路由一体化设计.md)  
> **撰写日期**：2026-07-16

---

## 一、问题背景

### 当前澄清功能的局限

**阶段B现状**（系统完全生成澄清选项）：
1. LLM 一体化调用：识别 `missing_dimensions` + 生成 3 个澄清选项
2. KB 填充（有限）：仅 `standard_series` 可 ES 聚合，其余维度为 LLM 幻觉
3. 用户交互：单选（选一个选项）或跳过

**核心问题**：
- ❌ 用户意图不在预设选项中（如想查 220kV 但只有 10kV/35kV 选项）
- ❌ 无法处理长尾需求（6kV、特殊设备类型、小众应用场景）
- ❌ 数据飞轮无法学习"用户想要但系统未提供"的需求

**影响**：
- 预期 10-15% 用户找不到合适选项，只能"跳过"，澄清功能对这部分用户完全失效
- 跳过率高 → 用户在笼统查询下得到低质量答案 → 满意度下降

---

## 二、方案设计

### 2.1 方案选择

经对比三个备选方案（详见分析文档），选择**方案C（混合方案）**：

**设计**：
1. **主流程保持不变**：系统生成 3 个选项 + "跳过"（当前设计）
2. **兜底机制**：在"跳过"选项下方增加"自定义补充"折叠区域
   - 默认折叠，点击展开后显示文本框
   - 文本框 placeholder："例如：220kV 变电站室外"
   - 输入后自动选中"自定义补充"选项，取消其他选项

**优势**：
- ✅ 不破坏主流程（大部分用户不展开，体验不变）
- ✅ 为长尾需求提供兜底（折叠降低心理门槛）
- ✅ 数据飞轮可区分"系统选项接受率" vs "自定义输入率"
- ✅ 前端实现简单（折叠组件 + 文本框互斥逻辑）

## 三、技术实施

### 3.1 后端变更

#### Schema 变更（`backend/app/schemas/query.py`）

```python
class QueryRequest(BaseModel):
    query: str
    refined_query: Optional[str] = None
    custom_refinement: Optional[str] = Field(
        default=None, 
        max_length=200, 
        description="用户自定义补充内容（方案C）"
    )
    selected_option_id: Optional[int] = None
    user_lane: Optional[str] = None
    clarification_context: Optional[Dict[str, Any]] = None

    @field_validator('custom_refinement')
    @classmethod
    def validate_custom_refinement(cls, v: Optional[str]) -> Optional[str]:
        if v is not None:
            v = v.strip()
            if not v:
                return None
            if len(v) > 200:
                raise ValueError("自定义补充内容不能超过200字符")
        return v
```

**优先级规则**：
```
custom_refinement（不为空） > refined_query（不为空） > query（原始）
```

#### 服务层变更（`backend/app/services/query_service.py`）

```python
async def execute_query(
    self,
    query: str,
    user_id: int,
    custom_refinement: Optional[str] = None,  # [方案C]
    refined_query: Optional[str] = None,
    selected_option_id: Optional[int] = None,
    # ... 其他参数
) -> Dict[str, Any]:
    # 优先级：custom_refinement > refined_query > resolved_query
    final_query = custom_refinement if custom_refinement else (
        refined_query if refined_query else resolved_query
    )
    is_custom_input = custom_refinement is not None
    
    logger.info(f"[User {user_id}] Processing query: {final_query} (custom={is_custom_input})")
    
    # ... 其余流程不变

def _record_clarification_log(
    self,
    query_log_id: int,
    original_query: str,
    refined_query: str,
    selected_option_id: Optional[int],
    custom_input: bool,  # [方案C]
    clarification_context: Dict[str, Any]
) -> int:
    if custom_input:
        user_choice = "custom"
        user_input = refined_query
    elif selected_option_id:
        user_choice = f"option_{selected_option_id}"
        user_input = None
    else:
        user_choice = "skip"
        user_input = None
    
    clarification_log = ClarificationLog(
        query_log_id=query_log_id,
        original_query=original_query,
        user_choice=user_choice,
        user_input=user_input,
        custom_input=custom_input,  # [方案C]
        refined_query=refined_query,
        # ... 其余字段
    )
```

// composables/useQuery.ts
export function useQuery() {
  const customRefinement = ref<string>('');  // [方案C]
  
  function handleCustomInput(input: string) {
    customRefinement.value = input;
    if (input.trim()) {
      // 有自定义输入时，清空系统选项
      selectedOptionId.value = null;
      refinedQuery.value = null;
    }
  }
  
  function handleOptionSelect(optionId: number | null, refined: string | null) {
    selectedOptionId.value = optionId;
    refinedQuery.value = refined;
    if (optionId !== null) {
      // 选择系统选项时，清空自定义输入
      customRefinement.value = '';
    }
  }

        selected_option_id: selectedOptionId.value,

    });

}

## 四、数据飞轮增强

### 4.1 统计指标

| 指标 | 计算方式 | 目标 |
|------|---------|------|
| **自定义输入率** | `COUNT(custom_input=True) / COUNT(*)` | < 15% |
| **系统选项接受率** | `COUNT(user_choice LIKE 'option_%') / COUNT(*)` | > 60% |
| **跳过率** | `COUNT(user_choice='skip') / COUNT(*)` | < 25% |

**解读**：
- 自定义输入率 > 15%：系统选项覆盖不足，需扩充 LLM prompt 的 Few-shot 示例
- 系统选项接受率 < 60%：选项质量差，需优化 LLM 生成逻辑或修复 KB 字段（如 `voltage_level`）
- 跳过率 > 25%：笼统度评估误判，需调整阈值或优化 prompt

---

### 4.2 高频自定义输入分析

**每周任务**：
1. 提取 `user_input` 字段的高频模式（聚类或人工标注）
2. 识别未覆盖的维度值（如"220kV"、"6kV"、"SF6断路器"）
3. 更新 LLM prompt 的 Few-shot 示例：
   ```python
   CLARIFICATION_EXAMPLES = [
       {
           "query": "隔离开关安全距离",
           "missing_dimensions": ["voltage_level"],
           "options": [
               {"label": "10kV户内", "refined_query": "..."},
               {"label": "35kV户外", "refined_query": "..."},
               {"label": "220kV变电站", "refined_query": "..."}  # ← 新增高频
           ]
       }
   ]
   ```

---

### 4.3 KB 字段修复优先级

当自定义输入率 > 15% 时，按以下优先级修复 KB 字段：

| 维度 | 当前状态 | 修复优先级 | 收益 |
|------|---------|----------|------|
| `voltage_level` | 恒为 NULL | **P0** | 电压等级是最高频缺失维度，修复后可 ES 聚合 |
| `equipment_type` | 无独立字段 | P1 | 需 NER 提取或重新入库时标注 |
| `application_scene` | 无独立字段 | P2 | 自由文本，难聚合 |

## 七、成功指标

| 指标 | 当前（无自定义输入） | 目标（方案C上线 4 周后） |
|------|---------------------|----------------------|
| 澄清选项接受率 | 30-40% | 60%+ |
| 跳过率 | 40-50% | < 25% |
| 自定义输入率 | 0% | 10-15% |
| 用户满意度（澄清环节） | 中 | 高 |

**验收标准**：
- ✅ 自定义输入率在 10-15% 区间（过低说明未被发现，过高说明系统选项覆盖不足）
