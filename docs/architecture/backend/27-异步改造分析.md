# 27 - 同步阻塞改造分析

**文档版本**: v1.0  
**最后更新**: 2026-07-16

---

## 一、问题背景

FastAPI 是基于 asyncio 的异步框架，所有请求处理器均运行在单一事件循环中。当异步函数（`async def`）内部调用同步阻塞 I/O 时，事件循环被占用，其他并发请求无法推进，直到该阻塞调用返回。

当前项目的 Redis、MySQL、Elasticsearch、Qdrant 客户端均使用**同步**实现，在 `async def` 路径中直接调用，构成系统级并发瓶颈。

**实测影响**：单请求延迟约 78-86 秒（含 LLM），其中约 35 秒为 CPU 重排（非 I/O 阻塞）。在多并发场景下，由于事件循环阻塞，第 2 个请求的延迟将在第 1 个请求结束后才开始计时，QPS 接近于 1/86s ≈ 0.012。异步改造后理论并发 QPS 可提升至 2-3×。

---

## 二、受影响模块总览

| 优先级 | 存储层 | 客户端类型 | 主要调用文件 | 改造难度 |
|--------|--------|-----------|-------------|---------|
| P0 | Redis | `redis.Redis`（同步） | `cache.py`（17 处调用方） | 中 |
| P0 | MySQL | SQLAlchemy 同步 ORM | `query_repo.py`, `query_service.py` | 高 |
| P1 | Elasticsearch | `elasticsearch.Elasticsearch`（同步） | `search_engine.py`（8 处） | 低 |
| P1 | Qdrant | `QdrantClient`（同步） | `vector_store.py`（3+ 处） | 低 |
| P2 | MinIO | `minio.Minio`（同步，无官方 async） | `object_store.py` | 中（需线程池） |

## 三、各模块详细分析

### 3.1 Redis — P0

**当前实现**：`backend/app/storage/cache.py`

```python
import redis

class CacheManager:
    @property
    def client(self) -> redis.Redis:
        self._client = redis.Redis(host=..., max_connections=50)
        return self._client

    def _get_raw(self, key: str) -> Optional[bytes]:
        return self.client.get(key)   # 同步阻塞

    def _set_raw(self, key: str, value: bytes, ttl: int) -> bool:
        self.client.setex(key, ttl, value)  # 同步阻塞

    def mget(self, keys) -> List:
        return self.client.mget(keys)  # 同步阻塞

    def mset(self, key_value_ttl) -> bool:
        pipeline = self.client.pipeline()  # 同步阻塞
        ...
```

**调用链**（共 17 处同步调用，分布在 5 个模块）：

| 调用文件 | 调用方法 | 所在函数 |
|---------|---------|---------|
| `core/embedding/embedder.py` | `cache.get_dense/set_dense` | `encode()` |
| `core/embedding/embedder.py` | `cache.get_sparse/set_sparse` | `encode_sparse()` |
| `core/embedding/embedder.py` | `cache.get_dense_by_id/set_dense_by_id` | `encode_by_id()` |
| `core/retrieval/fast_lane.py` | `cache.get_recall/set_recall` | `_multi_path_recall()` |
| `core/retrieval/fast_lane.py` | `cache.get_rerank/set_rerank` | `execute()` |
| `core/retrieval/rerank.py` | `cache.mget/mset` | `_compute_scores()` |
| `core/retrieval/child_expander.py` | `cache.get/set` | `expand()` |
| `services/query_service.py` | `cache.get_generation/set_generation` | `execute_query()` |

**改造方案**：将 `redis.Redis` 替换为 `redis.asyncio.Redis`，所有 `_get_raw`、`_set_raw`、`mget`、`mset` 改为 `async def`，上游 17 处调用点加 `await`。

```python
# 改造后
import redis.asyncio as aioredis

class CacheManager:
    @property
    def client(self) -> aioredis.Redis:
        self._client = aioredis.Redis(host=..., max_connections=50)
        return self._client

    async def _get_raw(self, key: str) -> Optional[bytes]:
        return await self.client.get(key)

    async def _set_raw(self, key: str, value: bytes, ttl: int) -> bool:
        await self.client.setex(key, ttl, value)
        return True

    async def mget(self, keys) -> List:
        return await self.client.mget(keys)

    async def mset(self, key_value_ttl) -> bool:
        async with self.client.pipeline() as pipe:
            for key, value, ttl in key_value_ttl:
                pipe.setex(key, ttl, value)
            await pipe.execute()
        return True
```

**注意**：`invalidate_recall_and_generation()` 中的 `client.scan` 循环也需改为 `async for` 或 `await client.scan()`。

### 3.2 MySQL（SQLAlchemy）— P0

**当前实现**：`backend/app/db/session.py` + `db/repositories/`

```python
# session.py
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker

engine = create_engine(settings.DATABASE_URL, pool_size=10, ...)
SessionLocal = sessionmaker(bind=engine)

# 依赖注入（同步）
def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

**主要同步调用点**：

| 文件 | 同步操作 |
|------|---------|
| `db/repositories/query_repo.py` | `db.query(QueryLog).filter(...).all()` |
| `db/repositories/query_repo.py` | `db.add(log); db.commit()` |
| `services/query_service.py` | 通过 `get_db()` 注入同步 session |
| `core/retrieval/recall.py` | 结构化召回走 MySQL（通过 ORM） |

**改造方案**：引入 SQLAlchemy 异步引擎。

```python
# session.py 改造后
from sqlalchemy.ext.asyncio import create_async_engine, AsyncSession, async_sessionmaker

engine = create_async_engine(
    settings.DATABASE_URL.replace("mysql+pymysql://", "mysql+aiomysql://"),
    pool_size=10,
)
AsyncSessionLocal = async_sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)

async def get_db():
    async with AsyncSessionLocal() as session:
        yield session
```

所有 `db.query(...)` 改为 `await session.execute(select(Model).where(...))`，依赖包新增 `aiomysql`。

### 3.3 Elasticsearch — P1

**当前实现**：`backend/app/storage/search_engine.py`

```python
from elasticsearch import Elasticsearch

class SearchEngine:
    def __init__(self):
        self.client = Elasticsearch(
            hosts=[f"http://{settings.ELASTICSEARCH_HOST}:{settings.ELASTICSEARCH_PORT}"],
            request_timeout=30
        )
```

所有搜索、索引操作（`client.search`、`client.index`、`client.indices.exists`、`client.indices.create`）均为同步调用，共约 8 处。

**改造方案**：替换为 `elasticsearch.AsyncElasticsearch`，该类与同步版本 API 完全一致，仅需：

1. 将 `Elasticsearch` 替换为 `AsyncElasticsearch`
2. 所有调用加 `await`
3. 在应用关闭时调用 `await self.client.close()`

```python
from elasticsearch import AsyncElasticsearch

class SearchEngine:
    def __init__(self):
        self.client = AsyncElasticsearch(hosts=[...])

    async def search(self, query: str, ...) -> List[Dict]:
        resp = await self.client.search(index=self.index_name, body=body)
        return resp["hits"]["hits"]
```

改造范围仅限 `search_engine.py` 一个文件，上游 `recall.py` 的 `keyword_recall.search()` 已是 `async def`，调用处加 `await` 即可。

### 3.4 Qdrant — P1

**当前实现**：`backend/app/storage/vector_store.py`

```python
from qdrant_client import QdrantClient

class VectorStore:
    def __init__(self):
        self.client = QdrantClient(host=settings.QDRANT_HOST, port=settings.QDRANT_PORT, timeout=30)
```

同步调用点：`client.search`、`client.query_points`、`client.upsert`、`client.get_collections`、`client.create_collection`。

**改造方案**：`qdrant-client` 原生支持异步，替换为 `AsyncQdrantClient`：

```python
from qdrant_client import AsyncQdrantClient

class VectorStore:
    def __init__(self):
        self.client = AsyncQdrantClient(host=settings.QDRANT_HOST, port=settings.QDRANT_PORT)

    async def hybrid_search(self, ...) -> List[ScoredPoint]:
        return await self.client.query_points(...)
```

API 与同步版本几乎完全对称，改造成本低。

### 3.5 MinIO — P2

**当前实现**：`backend/app/storage/object_store.py`

```python
from minio import Minio

class ObjectStore:
    def __init__(self):
        self.client = Minio(endpoint=settings.MINIO_ENDPOINT, ...)
```

MinIO 官方不提供 async Python 客户端。MinIO 操作（PDF 上传/下载）不在查询关键路径上，仅在文档导入时使用。

**改造方案**：使用 `asyncio.to_thread()` 将同步调用包装为非阻塞：

```python
import asyncio

class ObjectStore:
    async def upload_file(self, bucket: str, path: str, data: bytes) -> str:
        def _upload():
            self.client.put_object(bucket, path, ...)
        await asyncio.to_thread(_upload)
```

由于 MinIO 不在请求热路径上，此方案优先级低，暂可接受现状。

## 四、改造优先级与实施顺序

```
P0（并发瓶颈，影响所有请求）
  └─ Redis（cache.py）：所有缓存读写在热路径上，17 处调用
  └─ MySQL（session.py + query_repo.py）：查询日志写入、结构化召回均在热路径

P1（影响热路径，但单次延迟低于 Redis/MySQL）
  └─ Elasticsearch（search_engine.py）：BM25 召回约 50-100ms，3 路并行中的一路
  └─ Qdrant（vector_store.py）：向量召回约 30-60ms，3 路并行中的一路

P2（非热路径）
  └─ MinIO（object_store.py）：仅文档导入时调用，不影响查询延迟
```

**建议实施顺序**：

1. **先改 Elasticsearch + Qdrant（P1）**：改动范围小，各自局限在单一文件，API 对称，风险低，可快速验证异步改造流程。
2. **再改 Redis（P0）**：调用分散在 5 个文件 17 处，改动量最大，但 `redis.asyncio` API 与同步版本一致，逐文件迁移。
3. **最后改 MySQL（P0）**：涉及 ORM 层架构变更（`AsyncSession` + `aiomysql`），需要验证 `init_db()` 启动逻辑是否兼容，风险最高，应在前两步验证后再实施。
4. **MinIO（P2）**：用 `asyncio.to_thread` 包装，任意时间改造均可。

## 五、预期收益

| 场景 | 改造前 | 改造后 |
|------|--------|--------|
| 单请求延迟 | 约 78-86s（含 LLM） | 基本不变（I/O 改造不降低单次延迟） |
| 2 并发请求总时间 | ~160s（串行） | ~86s（真正并发） |
| 10 并发 QPS | ~0.12（1/86s × 10 被事件循环串行） | ~0.5-1.0（取决于 LLM 并发限制） |
| Redis 每次缓存读写阻塞时长 | 1-5ms × 完全阻塞事件循环 | 释放事件循环，其他协程可推进 |

**核心结论**：异步改造不降低单请求延迟，但可将系统有效 QPS 提升 2-5 倍，是支撑多用户并发的必要基础。

## 六、改造注意事项

### 6.1 全局单例的线程安全

当前 `cache.py` 使用模块级全局单例 `cache = get_cache_manager()`。改造为异步后，`AsyncRedis` 的连接池是协程安全（coroutine-safe）而非线程安全（thread-safe）的，单例模式本身可以保留，但需确保不在同步上下文中调用异步方法。

### 6.2 `init_db()` 启动函数

`app/db/session.py` 的 `init_db()` 在 FastAPI 的 `startup` 事件中调用，本身已在 async 上下文中。改为 `AsyncSession` 后，`init_db()` 需相应改为 `async def init_db()`，在 `await engine.begin()` 上下文中执行 DDL。

### 6.3 rerank.py 中的 mget/mset

`rerank.py::_compute_scores()` 目前调用同步 `cache.mget/mset`。改造后需将 `_compute_scores()` 声明为 `async def`，并在调用处 `await`。由于该函数内部有 `torch.no_grad()` 的 CPU 推理块，推理部分需通过 `asyncio.to_thread()` 包装，防止阻塞事件循环（重排是当前最大瓶颈，约 35s，该优化与缓存改造可一并进行）。

### 6.4 依赖变更

| 新增依赖 | 用途 |
|---------|------|
| `aiomysql` | SQLAlchemy async 引擎驱动 |
| `redis.asyncio`（已在 `redis-py` 包内） | 无需新增，`redis>=4.2` 已内置 |
| `elasticsearch` async（已内置） | `elasticsearch>=7.x` 已包含 `AsyncElasticsearch` |
| `qdrant-client` async（已内置） | `qdrant-client>=1.1` 已包含 `AsyncQdrantClient` |
