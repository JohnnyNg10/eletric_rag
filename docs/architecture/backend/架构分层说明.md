# 后端架构分层说明文档

## 文档目的

本文档旨在说明清楚两个架构文档的关系和命名规范，避免混淆。

## 两个架构视角

### 1. 技术分层视角（04-后端架构设计.md）

**4层技术架构**：
```
┌─────────────────────────────────────┐
│         API层 (endpoints)            │  HTTP请求入口
├─────────────────────────────────────┤
│         服务层 (services)            │  业务逻辑编排
├─────────────────────────────────────┤
│         核心层 (core)                │  算法实现
├─────────────────────────────────────┤
│         存储层 (storage)             │  数据存储
└─────────────────────────────────────┘
```

**目录结构**：
- `app/api/v1/endpoints/` - API路由层
- `app/services/` - 业务服务层
- `app/core/` - 核心算法层
  - `preprocessing/` - 预处理模块
  - `retrieval/` - 检索模块
  - `generation/` - 生成模块
- `app/storage/` - 存储层

### 2. RAG功能流程视角（08-RAG功能层次与状态机.md）

**7层功能流水线**：
```
接入层 → 预处理层 → 路由层 → 召回层 → 重排层 → 生成层 → 存储层
```

这是按**数据流动**划分的功能层次。

## 命名规范

### Service vs Coordinator

| 类型 | 命名 | 位置 | 职责 |
|-----|------|------|------|
| **业务服务** | `XXXService` | `app/services/` | 编排多个核心层模块 |
| **层内协调器** | `XXXCoordinator` 或直接用功能名 | `app/core/xxx/` | 协调本层内的多个组件 |

**示例**：

1. **`QueryService`** (业务服务层)
   - 位置：`app/services/query_service.py`
   - 职责：编排预处理→路由→召回→重排→生成的完整流程
   - 调用：多个核心层模块

2. **`Preprocessor`** (预处理层协调器)
   - 位置：`app/core/preprocessing/preprocessor.py`
   - 职责：协调 TermNormalizer、QueryOptimizer、QueryRewriter、MetadataExtractor
   - 调用：预处理层内的4个组件

3. **`RetrievalEngine`** (检索引擎协调器)
   - 位置：`app/core/retrieval/engine.py`
   - 职责：协调快车道、慢车道、路由器
   - 调用：检索层内的多个组件

## 实际调用链

```
HTTP请求
  ↓
API层 (query.py)
  ↓
服务层 (QueryService)
  ↓
核心层：
  ├─ Preprocessor (预处理协调器)
  │   ├─ TermNormalizer
  │   ├─ QueryOptimizer
  │   ├─ QueryRewriter
  │   └─ MetadataExtractor
  ├─ Router (路由器)
  ├─ RetrievalEngine (检索协调器)
  │   ├─ FastLane
  │   └─ SlowLane
  ├─ Reranker (重排器)
  └─ Generator (生成器)
  ↓
存储层 (Qdrant/ES/MySQL)
```

## 两个文档的对应关系

| 04技术分层 | 08功能流程 | 实现类 |
|-----------|-----------|--------|
| 服务层 | - | QueryService |
| 核心层.预处理模块 | 接入层 + 预处理层 | Preprocessor |
| 核心层.检索模块 | 路由层 + 召回层 + 重排层 | RetrievalEngine |
| 核心层.生成模块 | 生成层 | Generator |
| 存储层 | 存储层 | VectorStore/SearchEngine |

## 总结

- **两个文档不冲突**：一个是技术分层，一个是功能流程
- **命名规范**：业务层用`Service`，核心层协调器根据具体功能命名
- **当前实现**：API层 + 服务层 + 预处理层（核心层第一个模块）
