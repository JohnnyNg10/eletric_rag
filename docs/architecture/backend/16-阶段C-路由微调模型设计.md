# 阶段C：路由微调模型设计方案

> **前置条件**：完成阶段B（一体化LLM输出 + 数据飞轮），积累1000-2000条标注数据  
> **目标**：用轻量微调模型替换大模型LLM调用，延迟从4000ms降至**<100ms**  
> **撰写日期**：2026-07-10

---

## 一、任务拆解

### 1.1 阶段B的完整输出

阶段B的一体化LLM调用负责以下全部输出（与[15-阶段B-预处理路由一体化设计.md](./15-阶段B-预处理路由一体化设计.md)保持一致）：

```json
{
  "vagueness_score": 0.65,
  "strategy": "clarify_optional",
  "missing_dimensions": ["voltage_level", "application_scene"],
  "options": [
    {
      "label": "10kV配电装置安全距离",
      "refined_query": "10kV配电装置与建筑物及各类设备的安全净距要求",
      "kb_verified": false
    }
  ],
  "lane": "fast",
  "lane_confidence": 0.82,
  "lane_reason": "单一维度查询，包含具体设备类型，无对比或多跳需求"
}
```

按任务类型拆分：

| 输出字段 | 任务类型 | 说明 |
|---------|---------|------|
| `vagueness_score` | 回归（0-1） | 笼统度评分 |
| `missing_dimensions` | 多标签分类（8维枚举key） | 缺失维度识别 |
| `lane` | 二分类（fast/slow） | 路由判断 |
| `lane_confidence` | 回归（0-1） | 路由置信度 |
| `lane_reason` | **文本生成** | 面向用户的路由解释 |
| `options[].label` | **文本生成** | 澄清选项标题 |
| `options[].refined_query` | **文本生成** | 改写后的完整查询 |

### 1.2 分类任务 vs 生成任务的处理策略

阶段C不用单一模型承担所有任务，而是**按任务类型分离处理**：

```
原始查询（术语标准化后）
  ├── 分类/回归任务（4个字段）→ 微调编码器（主体）
  │     vagueness_score / missing_dimensions / lane / lane_confidence
  │
  └── 文本生成任务（3个字段）→ KB模板引擎 + 规则
        lane_reason → 置信度分段模板生成
        options → KB聚合 + 模板拼装（与阶段B相同策略，见§1.3）
```

### 1.3 文本生成部分的处理

**options生成**：与阶段B完全相同，由KB聚合 + 模板拼装完成，不依赖大模型：

- 可聚合维度（`standard_series` 等）：ES聚合真实值 → 按模板拼装 `label` 和 `refined_query`
- 不可聚合维度：退化为基于 `missing_dimensions` 枚举key的模板生成，例如：
  - `voltage_level` → `label: "请指定电压等级"`, `refined_query: f"{query}（电压等级：__）"`
- `kb_verified` 标记保持与阶段B一致

**lane_reason生成**：用置信度分段的固定模板，无需LLM：

```python
LANE_REASON_TEMPLATES = {
    ("fast", "high"):   "单维度查询，可直接召回，无需多跳推理",
    ("fast", "medium"): "查询较明确，初步判断单路检索可覆盖",
    ("slow", "high"):   "查询涉及{keywords}，需要多路检索或跨标准推理",
    ("slow", "medium"): "查询可能涉及多个标准或对比分析，建议慢车道处理",
}
```

其中 `keywords` 从查询中提取对比词/多跳词（正则匹配），`high/medium` 按 `lane_confidence` 阈值（>0.85 为 high）判断。

**结论**：阶段C只需要为分类/回归任务设计微调模型，文本生成部分通过规则+KB解决。

## 二、微调模型架构

### 2.1 基座模型选择

分类/回归任务最适合的模型是**编码器（Encoder-only）**，而非生成式大模型：

| 模型 | 参数量 | 推理延迟 | 显存 | 优势 |
|------|--------|---------|------|------|
| **chinese-roberta-wwm-ext**（推荐） | 110M | ~8ms | ~0.5GB | 哈工大中文全词掩码，分类能力强 |
| chinese-macbert-base | 110M | ~8ms | ~0.5GB | 同规模，语义相似任务更优 |
| Qwen2.5-1.5B-Instruct | 1.5B | ~80ms | ~3GB | 更强，但比编码器慢10倍且无必要 |
| Qwen2.5-7B-Instruct | 7B | ~300ms | ~8GB | 过杀：分类任务不需要生成能力 |

**推荐**：`chinese-roberta-wwm-ext`（`hfl/chinese-roberta-wwm-ext`，HuggingFace）

理由：
- 110M参数，全量微调快（单卡RTX 3060，30分钟内收敛）
- 推理延迟~8ms，加上KB聚合~50ms，总计<100ms，远优于阶段B的4000ms
- 中文预训练充分，无需LoRA等PEFT技术，直接全量微调

### 2.2 模型架构

```
原始查询（分词后）
  ↓
[CLS] + 查询tokens + [SEP]
  ↓
chinese-roberta-wwm-ext（110M）
Transformer × 12层
hidden_size = 768
  ↓
[CLS] token 隐藏状态（768维）
  ↓
┌─────────────────┬─────────────────┬─────────────────┐
↓                 ↓                 ↓                 ↓
回归头           多标签分类头      分类头            置信度头
FC(768→1)       FC(768→8)        FC(768→2)         FC(768→1)
Sigmoid         Sigmoid          Softmax           Sigmoid
↓                 ↓                 ↓                 ↓
vagueness_score  missing_dims(8)   lane(fast/slow)   lane_confidence
```

**设计要点**：
- 四个任务头共享RoBERTa主干的[CLS]表示，多任务联合训练
- 主干全量微调（不冻结），110M参数规模下全量微调比LoRA效果更稳定
- 无需LoRA、量化等优化手段，原生transformers即可满足延迟要求

## 三、训练方案

### 3.1 数据准备

#### 数据来源

阶段B数据飞轮（`query_logs`表）：

```sql
SELECT
    q.normalized_query              AS query,
    q.vagueness_score               AS vagueness_score,
    c.missing_dimensions            AS missing_dimensions,
    COALESCE(q.user_lane, q.predicted_lane) AS ground_truth_lane,
    q.lane_confidence               AS lane_confidence,
    q.created_at
FROM query_logs q
LEFT JOIN clarification_logs c ON q.id = c.query_log_id
WHERE q.predicted_lane IS NOT NULL
  AND q.vagueness_score IS NOT NULL
ORDER BY q.created_at DESC;
```

**标注优先级**：
1. `user_lane IS NOT NULL`：用户主动修改路由，信号最强
2. `lane_confidence >= 0.8`：LLM高置信度判断，可信
3. 排除矛盾样本：同一 `normalized_query` 出现不同 `user_lane` 的记录

#### 数据划分

```
总数据：1500条（预期阶段B积累量）
├── 训练集：1200条 (80%)
├── 验证集：150条 (10%)
└── 测试集：150条 (10%)
```

分层采样：确保 fast/slow 比例在各集合一致（约9:1）。

#### 标注格式

```python
{
    "input": "隔离开关的技术参数要求",
    "target": {
        "vagueness_score": 0.70,                 # float 0-1
        "missing_dimensions": [1, 1, 1, 0, 0, 0, 0, 0],  # 8维one-hot
        "lane": 0,                               # 0=fast, 1=slow
        "lane_confidence": 0.85                  # float 0-1
    }
}
```

维度索引映射（与阶段B `POWER_CLARIFICATION_DIMS` 保持一致）：

```python
DIM_INDEX_MAP = {
    "voltage_level": 0,      "equipment_type": 1,
    "application_scene": 2,  "neutral_grounding": 3,
    "capacity_range": 4,     "install_env": 5,
    "standard_series": 6,    "protection_type": 7,
}
```

### 3.2 微调算法

**全量微调**（full fine-tuning）：

直接对所有参数执行梯度更新，不使用LoRA等PEFT方法。理由：
- 110M参数规模，全量微调内存占用~2GB，单卡8GB完全可承受
- 分类任务全量微调收敛更快、效果更稳定
- LoRA适合冻结大模型主干只训练少量适配参数，对110M编码器无必要

### 3.3 损失函数

**多任务联合损失**：

```python
L_total = λ1 * L_vagueness + λ2 * L_dimensions + λ3 * L_lane + λ4 * L_confidence

L_vagueness   = MSE(pred, true)           # 回归
L_dimensions  = BCE(pred, true)           # 多标签二分类
L_lane        = CrossEntropy(pred, true)  # 二分类（带类别权重）
L_confidence  = MSE(pred, true)           # 回归

权重：λ1=0.25, λ2=0.25, λ3=0.40, λ4=0.10
（路由判断 λ3 最高，置信度 λ4 最低）
```

**slow类别权重**（fast:slow ≈ 9:1，类别不均衡）：

```python
class_weights = {"fast": 1.0, "slow": 9.0}
```

### 3.4 训练配置

```python
training_args = {
    "learning_rate": 2e-5,         # 编码器微调常用学习率（比LoRA低一个数量级）
    "num_epochs": 5,               # 小数据集，epoch数稍多
    "batch_size": 32,              # 110M模型单卡32可承受
    "warmup_ratio": 0.1,
    "weight_decay": 0.01,
    "lr_scheduler": "linear",
    "fp16": True,
    "max_grad_norm": 1.0
}
```

硬件要求：
- 最低：GTX 1080Ti (11GB)，训练时间~30分钟
- 推荐：RTX 3060 (12GB) 或更高，无需A100级别硬件

## 四、评估指标

### 4.1 子任务指标

#### 笼统度评估
- **MAE**：平均绝对误差，目标 < 0.12
- **相关系数**（Pearson r）：目标 > 0.85

#### 缺失维度识别
- **Macro F1**：各维度F1均值，目标 > 0.75
- **Hamming Loss**：多标签错误率，目标 < 0.10

#### 路由判断（核心指标）
- **整体准确率**：目标 > 90%
- **slow Recall**：目标 > 85%（漏判慢车道代价高）
- **slow Precision**：目标 > 70%（误判快车道为慢车道导致过度解析）

#### 置信度
- **校准误差**（ECE）：预测置信度与实际准确率的偏差，目标 < 0.05

### 4.2 业务指标对比

| 指标 | 阶段A（规则） | 阶段B（LLM） | 阶段C目标（微调模型） |
|------|-------------|-------------|---------------------|
| **延迟 P99** | ~5ms | ~4200ms | **<100ms** |
| **路由准确率** | ~50%（测试显示） | ~85% | **>90%** |
| **slow Recall** | 低（规则漏判多） | ~70% | **>85%** |
| **成本/千次** | ~0元 | ~1元（LLM API） | **~0元**（本地推理） |

## 五、部署方案

### 5.1 推理服务化

```python
# app/core/preprocessing/route_model.py

from transformers import AutoTokenizer, AutoModel
import torch

class RouteModel:
    def __init__(self, model_path: str = "models/roberta-wwm-route"):
        self.tokenizer = AutoTokenizer.from_pretrained(model_path)
        self.model = MultiTaskRouteModel.from_pretrained(model_path)
        self.model.eval()

    def predict(self, query: str) -> RouteDecision:
        inputs = self.tokenizer(
            query, return_tensors="pt",
            max_length=128, truncation=True, padding=True
        )
        with torch.no_grad():
            outputs = self.model(**inputs)

        lane_idx = outputs.lane.argmax(dim=-1).item()
        return RouteDecision(
            vagueness_score=float(outputs.vagueness.sigmoid()),
            missing_dimension_keys=self._decode_dims(outputs.dimensions),
            lane="slow" if lane_idx == 1 else "fast",
            lane_confidence=float(outputs.confidence.sigmoid()),
        )

    def _decode_dims(self, logits, threshold=0.5):
        probs = logits.sigmoid().squeeze()
        return [k for k, v in DIM_INDEX_MAP.items() if probs[v] > threshold]
```

**部署特点**：
- 嵌入FastAPI进程，启动时加载，常驻内存（~500MB）
- 无需额外推理框架（llama.cpp、vLLM等均不适用于编码器）
- 单进程即可支撑 >100 QPS（~8ms/query）

### 5.2 与阶段B的切换策略

```python
class HybridPreprocessor:
    def __init__(self):
        self.use_model = os.getenv("USE_ROUTE_MODEL", "false") == "true"
        self.route_model = RouteModel() if self.use_model else None
        self.llm_fallback = QueryOptimizer()   # 阶段B的LLM方案

    async def optimize(self, query: str) -> OptimizationResult:
        if self.use_model:
            try:
                decision = self.route_model.predict(query)
                options = await self._build_options(decision.missing_dimension_keys)
                lane_reason = self._generate_reason(decision)
                return OptimizationResult.from_decision(decision, options, lane_reason)
            except Exception as e:
                logger.error(f"RouteModel失败，回退LLM: {e}")
                return await self.llm_fallback.optimize(query)
        else:
            return await self.llm_fallback.optimize(query)
```

**A/B测试**：10%流量走微调模型，90%走LLM，对比准确率和延迟，显著优于基线后全量切换。

## 七、风险与缓解

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|---------|
| 训练数据不足1000条 | 泛化差 | 中 | 延长阶段B积累期 / 用现有阶段B LLM批量标注补充数据 |
| slow Recall不达85% | 慢车道漏判 | 中 | 调高slow类别权重 / 增加slow样本数量 / 降低slow判断阈值 |
| 编码器对长查询截断 | 复杂查询理解差 | 低 | max_length=128足够（电力查询通常<60字符） |
| 阶段B选项文本质量下降 | 用户体验变差 | 低 | 模板引擎生成的选项比LLM幻觉更稳定，风险实际为负 |

## 八、成本估算

### 训练成本

- 硬件：GTX 1080Ti (11GB) 即可
- 训练时间：~30分钟（5 epochs，1200样本，批次32）
- 云服务（可选）：~0.5元/卡时 × 0.5h = **0.25元**

### 推理成本

- 推理延迟：~8ms/query（RoBERTa编码器）
- 加KB聚合后：~50-80ms/query（P99 < 100ms）
- 显存：~500MB（可与embedding模型共享GPU）
- QPS：单卡可支撑 >100 QPS

**对比阶段B（LLM API）**：
- 阶段B：~0.001元/次 × 1000次/天 = 1元/天
- 阶段C：0元（训练一次性成本0.25元）
- **ROI**：6小时即可回本

## 九、后续优化方向

### 短期
1. **在线学习**：每月用新增数据重训练一次（阶段B飞轮持续产出数据）
2. **主动学习**：挑选低置信度样本（`lane_confidence < 0.6`）交给LLM重新标注

### 长期
1. **蒸馏更小模型**：RoBERTa-wwm-ext(110M) → BERT-tiny(14M)，延迟降至<2ms
2. **KB聚合维度扩展**：随着`voltage_level`字段被填充，更多维度可从模板生成转为KB验证，提升选项质量
