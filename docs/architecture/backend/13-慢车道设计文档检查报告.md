# 慢车道设计文档一致性检查报告

> 被检查文档：13-慢车道设计.md

## 一、整体评估

**结论**：文档基本符合架构设计，但存在 **4 处需要修正** 的问题和 **2 处可优化** 的细节。

## 二、发现的问题

### 问题 1：`query_logs` 表字段不匹配 ❌

**位置**：第十一节 "可审计性要求"

**当前描述**：
```
| 字段 | 内容 |
| `strategy` | 实际执行的工具调用序列，如 `list_related_standards→retrieve_standard→retrieve_clause` |
```

**问题**：根据 `06-数据模型设计.md` 第 2.2.4 节，`query_logs.strategy` 字段定义为：
```sql
strategy VARCHAR(30),  -- none/suggest/clarify_optional/clarify_required
```

该字段用于存储**提问优化策略**，不是慢车道的工具调用序列。

**正确做法**：
- 慢车道的工具调用序列应存入 `expanded_queries` 字段（JSON 类型）
- 或者新增字段 `reasoning_steps` JSON（如果需要更结构化的存储）

**修正建议**：
```markdown
| 字段 | 内容 |
|-----|------|
| `lane` | `slow` |
| `expanded_queries` | 各步骤传给工具的查询文本列表（JSON 数组） |
| `retrieval_time` | 整个推理循环耗时（ms） |
| `recall_count` | 最终聚合的 chunk 数量 |
| `retrieved_chunk_ids` | 召回的 chunk IDs（JSON 数组） |

**可选扩展字段**（当前数据库未定义，如需要需先加表字段）：
| `reasoning_steps` | 工具调用序列详情，如 `[{"step":1,"tool":"list_related_standards","params":{...},"result_count":5}]` |
```

---

### 问题 2：数据库缺少 `conversation_id` 字段说明 ⚠️

**位置**：第十一节（隐含问题）

**问题**：根据 `06-数据模型设计.md`，`query_logs` 表没有 `conversation_id` 字段。但根据实际代码（见之前报错），该字段已被使用且刚刚手动加入数据库。

**影响**：文档未说明慢车道是否需要记录 `conversation_id`（多轮对话场景）。

**建议**：
- 如果慢车道支持多轮对话（如"继续追问上一个问题"），需在日志记录中包含 `conversation_id`
- 更新 `06-数据模型设计.md`，将 `conversation_id` 正式加入 `query_logs` 表定义

---

### 问题 3：工具返回格式未明确 ⚠️

**位置**：第五节 "工具集设计"

**当前描述**：
- `retrieve_standard` 输出："Top-N 相关文档块（同快车道召回格式）"
- `retrieve_clause` 输出："该条款的完整文本 + 元数据"
- `list_related_standards` 输出："匹配的标准号 + 标题列表"

**问题**：三个工具的输出格式不一致，但在"信息聚合策略"（第七节）中说"聚合后的结果格式与快车道输出的 `rerank_results` 格式相同"。

**冲突点**：
- `list_related_standards` 只返回标准号+标题，没有 chunk 内容，无法直接转换为 `rerank_results` 格式
- `retrieve_clause` 的"完整文本+元数据"格式未明确是否为 `ChunkResult` 对象

**修正建议**：
明确三个工具的输出统一为 `List[ChunkResult]`，即使 `list_related_standards` 返回的是文档级信息，也应包装成 chunk 格式（可以是文档摘要块）：

```markdown
### 5.1 retrieve_standard
**输出**：`List[ChunkResult]` — Top-N 相关文档块

### 5.2 retrieve_clause
**输出**：`List[ChunkResult]` — 包含该条款的单个 ChunkResult（长度为1的列表）

### 5.3 list_related_standards
**输出**：`List[Dict]` — 标准元信息列表，格式：`[{"standard_no": "GB 50057", "title": "...", "doc_count": 23}]`
**注意**：此工具返回的不是 chunk，需在聚合时跳过或转换为提示信息传给 LLM
```

---

### 问题 4：`04-后端架构设计.md` 中慢车道伪代码有误 ⚠️

**位置**：参考文档 `04-后端架构设计.md` 第 2.1 节

**问题**：后端架构文档中的慢车道示例代码将工具定义为：
```python
async def _retrieve_standard(self, query: str, standard_ids: List[str] = None, **kwargs):
```

但在慢车道设计文档（13）中，参数名为 `standard_ids`（复数），而描述中又说"可选"。

**一致性建议**：
- 统一参数名：`standard_ids`（List[str]，可选）
- 或改为 `standard_no`（str，可选，单个标准号）+ `category`（str，可选，分类过滤）

当前 13 号文档的描述 `standard_ids`（可选）是合理的，04 号文档应保持一致。

## 三、可优化的细节

### 优化点 1：LLM 决策超时与快车道不一致

**位置**：第四节 "LLM 决策机制" 4.3

**当前描述**：LLM 决策超时 1.5s

**参考**：04 号文档未明确提及慢车道的 LLM 决策超时，但快车道充分性判断是 1.5s。

**建议**：明确说明"与快车道充分性判断的超时策略保持一致（1.5s）"——**当前文档已正确说明** ✅

---

### 优化点 2：资源隔离的技术实现方式未说明

**位置**：第十节 "资源隔离与限流"

**当前描述**：独立限流 QPS=10，超出返回 429

**缺失**：未说明技术实现方式（令牌桶？滑动窗口？Redis 计数器？）

**建议**：补充技术实现参考：
```markdown
**隔离策略**：
- 独立限流：慢车道 QPS 上限 10，快车道不受影响
  - 实现方式：Redis 滑动窗口计数器，key 格式 `ratelimit:slow_lane:{timestamp_second}`
  - 限流粒度：全局限流（所有用户共享 10 QPS）
- 超出配额时返回 `429 Too Many Requests`，提示用户稍后重试或简化问题
```

## 四、与数据库设计的对照检查

### ✅ 已正确使用的字段

| 字段 | 慢车道用途 | 数据库定义 |
|------|-----------|-----------|
| `lane` | 存储 `"slow"` | `ENUM('fast', 'slow')` ✅ |
| `retrieval_time` | 整个推理循环耗时（ms） | `INT` ✅ |
| `recall_count` | 最终聚合的 chunk 数量 | `INT` ✅ |
| `retrieved_chunk_ids` | 召回的 chunk IDs | `JSON` ✅ |
| `expanded_queries` | 各步骤查询文本 | `JSON` ✅ |

### ⚠️ 字段用途不匹配

| 字段 | 慢车道文档描述 | 数据库实际定义 | 冲突 |
|------|--------------|--------------|-----|
| `strategy` | 工具调用序列 | 提问优化策略（none/suggest/...） | ❌ 冲突 |

### 💡 建议新增字段

如果希望慢车道的推理链路更易追溯，建议在 `query_logs` 表新增：

```sql
ALTER TABLE query_logs ADD COLUMN reasoning_steps JSON COMMENT '慢车道推理步骤详情';
```

结构示例：
```json
[
  {
    "step": 1,
    "tool": "list_related_standards",
    "params": {"keyword": "功率因数"},
    "elapsed_ms": 150,
    "result_count": 3
  },
  {
    "step": 2,
    "tool": "retrieve_standard",
    "params": {"query": "功率因数要求", "standard_ids": ["GB/T 33593-2017"]},
    "elapsed_ms": 800,
    "result_count": 15
  }
]
```
