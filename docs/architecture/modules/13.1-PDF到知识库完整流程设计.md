## 一、问题诊断

### 1.1 当前问题

通过存储层测试发现，现有的PDF解析和入库流程存在以下问题：

#### 问题1：表格被切碎
```
原始PDF表格：
| 序号 | 检验项目 | 技术要求 | 试验方法 |
|-----|---------|---------|---------|
| 1   | 充电时间 | 5.4     | 6.4     |

存入Qdrant后：
chunk_1: "5.4 | 6.4"  (9字符，无上下文)
chunk_2: "1 | 充电时间 |" (语义破碎)
```

**根本原因**：`pdf_to_md.py` 按行解析表格，每行被当成独立文本块，丢失了表头和上下文。

#### 问题2：元数据缺失
```python
# 实际存储的payload
{
  "standard_no": None,  # 应该是 "GB 7958-2014"
  "doc_title": "ICS29.",  # 误判为封面页的ICS分类号
  "clause": None,        # 条款号未提取
  "category": None       # 分类未识别
}
```

**根本原因**：没有实现元数据提取逻辑，存储时payload字段全是默认值。

#### 问题3：图片未处理
PDF中的图片（电路图、接线图、示意图）被跳过，导致用户问"XX图所示的连接方式"时无法召回。

#### 问题4：分块策略简陋
当前是固定500字符切分，导致：
- 条款被截断（"5.2.1 插头额定电流" 被切成 "5.2.1" 和 "插头额定电流"）
- 公式与说明文字分离
- 章节标题与正文混在一起

### 4.1 Step 1: 文档解析层

#### 4.1.1 PDF解析策略

根据PDF类型采用不同解析方案：

| PDF类型 | 判断依据 | 解析方案 | 工具 |
|---------|---------|---------|------|
| 文字版 | PyMuPDF提取文本量 > 页数×100字符 | 直接提取原生文本+表格 | PyMuPDF + pdfplumber |
| 扫描版 | 提取文本量少 | OCR识别 | PaddleOCR |
| 混合版 | 部分页有文本，部分页无 | 逐页判断，分别处理 | 组合 |

#### 4.1.2 表格处理（核心改进点）

**问题诊断**：当前`pdf_to_md.py`的表格处理逻辑按行解析，导致表格被切碎。

**改进方案**：使用`pdfplumber`的表格提取API，保留完整表格结构。

##### 4.1.2.1 简单表格处理

```python
import pdfplumber
from typing import List, Dict

def extract_tables_from_pdf(pdf_path: str) -> List[Dict]:
    """
    提取PDF中的所有表格，保留完整结构
    
    Returns:
        List[{
            "page": 页码,
            "table_index": 页内表格索引,
            "title": 表格标题（上方最近的文本）,
            "bbox": 表格边界框,
            "data": [[row1_col1, row1_col2, ...], [row2_col1, ...]]  # 二维数组
        }]
    """
    tables_info = []
    
    with pdfplumber.open(pdf_path) as pdf:
        for page_num, page in enumerate(pdf.pages, 1):
            # 提取页面中的所有表格
            tables = page.extract_tables()
            
            for table_idx, table in enumerate(tables):
                # 查找表格标题（上方最近的文本，通常是"表X"）
                table_bbox = page.find_tables()[table_idx].bbox
                title = find_table_title(page, table_bbox)
                
                tables_info.append({
                    "page": page_num,
                    "table_index": table_idx,
                    "title": title,
                    "bbox": table_bbox,
                    "data": table  # 完整的二维数组
                })
    
    return tables_info

def table_to_markdown(table_data: List[List[str]], title: str = "") -> str:
    """
    将表格转换为Markdown格式，保留完整结构
    
    Input:
        table_data = [
            ["序号", "检验项目", "技术要求", "试验方法"],
            ["1", "充电时间", "5.4", "6.4"],
            ["2", "操作性能", "5.5", "6.2"]
        ]
    
    Output:
        > **表1 检验项目表**
        
        | 序号 | 检验项目 | 技术要求 | 试验方法 |
        |-----|---------|---------|---------|
        | 1   | 充电时间 | 5.4     | 6.4     |
        | 2   | 操作性能 | 5.5     | 6.2     |
    """
    if not table_data:
        return ""
    
    # Markdown表格标题
    md_lines = []
    if title:
        md_lines.append(f"> **{title}**")
        md_lines.append("")
    
    # 表头
    header = table_data[0]
    md_lines.append("| " + " | ".join(str(cell or "") for cell in header) + " |")
    
    # 分隔行
    md_lines.append("|" + "|".join(["-----"] * len(header)) + "|")
    
    # 数据行
    for row in table_data[1:]:
        md_lines.append("| " + " | ".join(str(cell or "") for cell in row) + " |")
    
    return "\n".join(md_lines)
```

##### 4.1.2.2 复杂表格处理（跨行/跨列合并）

**挑战**：电力标准中常见复杂表格：

```
示例：GB 7958-2014 检验规则表
┌─────┬───────────┬──────────┬──────────┬──────────┐
│ 序号 │ 检验项目   │ 技术要求  │ 试验方法  │ 出厂检验 │
│     │           │          │          ├──────────┤
│     │           │          │          │ 型式检验  │
├─────┼───────────┼──────────┼──────────┼──────────┤
│  1  │ 充电时间   │  5.4     │  6.4     │    √     │
│     │           │          │          │    √     │
├─────┼───────────┼──────────┼──────────┼──────────┤
│  2  │ 操作性能   │          │          │          │
│     ├───────────┤  5.5     │  6.2     │    √     │
│     │ 电压指示   │          │          │    √     │
└─────┴───────────┴──────────┴──────────┴──────────┘

问题：
- "序号1"跨2行（行合并）
- "5.4"跨2行
- "检验项目"包含子项（"操作性能"和"电压指示"）
```

**pdfplumber的局限性**：

`pdfplumber.extract_tables()` 对合并单元格的处理：
- Word转换的PDF：合并单元格后续位置填`""`（空字符串）
- 原生PDF：后续位置填`None`
- 两种情况都需要后处理来恢复合并语义

**解决方案：JSON结构化存储（单一数据源）**

存储策略选择：

| 方案 | 优势 | 劣势 |
|-----|------|------|
| HTML+Markdown双存储 | Markdown可直接检索 | 两份数据可能不一致，HTML无法向量化 |
| **JSON单一数据源**（采用） | 结构完整，按需生成Markdown，数据一致 | 需要渲染时做一次转换 |

决策：采用JSON存储，`text`字段在入库时由JSON动态生成Markdown（用于向量检索），JSON结构本身记录在`metadata.table_data`中作为精确渲染依据。

```python
def extract_complex_table(page, table_bbox) -> Dict:
    """
    提取复杂表格，返回JSON结构化数据
    
    pdfplumber行为说明：
    - Word转PDF：合并单元格的后续格为 ""（空字符串）
    - 原生扫描PDF：后续格为 None
    - 两者都视为"被合并"标志
    """
    raw = page.extract_table(table_bbox, {
        "vertical_strategy": "lines",
        "horizontal_strategy": "lines",
        "intersection_tolerance": 3
    })
    
    title = ""         # 由调用方从页面文本识别并传入
    headers = raw[0] if raw else []
    rows = raw[1:] if len(raw) > 1 else []
    merges = detect_merged_cells(raw)
    
    return {
        "title": title,
        "headers": [str(h or "") for h in headers],
        "rows": [[str(c or "") for c in row] for row in rows],
        "merges": merges   # List[{"row":r,"col":c,"rowspan":rs,"colspan":cs}]
    }


def detect_merged_cells(table_data: List[List]) -> List[Dict]:
    """
    检测合并单元格，返回合并块列表
    
    算法：
    1. 遍历所有非空单元格（空=None或""）
    2. 从该单元格向右/向下扩展，统计连续空单元格数
    3. rowspan/colspan > 1 时记录为合并块
    
    注意：pdfplumber已在合并区域的起始格保留内容，
    后续格为空——无需区分"真空格"和"被合并格"，
    直接按连续空格计算跨度即可。
    """
    merges = []
    rows = len(table_data)
    cols = len(table_data[0]) if rows > 0 else 0
    claimed = set()   # 已归属于某合并块的格

    for r in range(rows):
        for c in range(cols):
            if (r, c) in claimed:
                continue
            cell = table_data[r][c]
            if cell is None or cell == "":
                continue

            # 向下统计 rowspan
            rowspan = 1
            while r + rowspan < rows and (
                table_data[r + rowspan][c] is None or
                table_data[r + rowspan][c] == ""
            ):
                rowspan += 1

            # 向右统计 colspan
            colspan = 1
            while c + colspan < cols and (
                table_data[r][c + colspan] is None or
                table_data[r][c + colspan] == ""
            ):
                colspan += 1

            if rowspan > 1 or colspan > 1:
                merges.append({
                    "row": r, "col": c,
                    "rowspan": rowspan, "colspan": colspan
                })
                # 标记被合并的格（排除起始格本身）
                for dr in range(rowspan):
                    for dc in range(colspan):
                        if dr > 0 or dc > 0:
                            claimed.add((r + dr, c + dc))

    return merges


def table_json_to_markdown(table_json: Dict) -> str:
    """
    从JSON结构生成Markdown表格（用于向量检索的text字段）
    
    合并单元格处理：将合并内容填充至所有覆盖的格，
    使Markdown保持矩形结构，语义上下文不丢失。
    """
    headers = table_json["headers"]
    rows = table_json["rows"]
    merges = table_json.get("merges", [])
    title = table_json.get("title", "")

    # 构建填充后的二维表（合并内容向下/向右复制）
    all_rows = [headers] + rows
    filled = [[cell for cell in row] for row in all_rows]
    for m in merges:
        r0, c0, rs, cs = m["row"], m["col"], m["rowspan"], m["colspan"]
        val = filled[r0][c0]
        for dr in range(rs):
            for dc in range(cs):
                if dr > 0 or dc > 0:
                    if r0 + dr < len(filled) and c0 + dc < len(filled[r0 + dr]):
                        filled[r0 + dr][c0 + dc] = val

    md_lines = []
    if title:
        md_lines.append(f"> **{title}**")
        md_lines.append("")
    header_row = filled[0]
    md_lines.append("| " + " | ".join(str(h) for h in header_row) + " |")
    md_lines.append("|" + "|".join(["-----"] * len(header_row)) + "|")
    for row in filled[1:]:
        md_lines.append("| " + " | ".join(str(c) for c in row) + " |")
    return "\n".join(md_lines)
```

##### 4.1.2.3 表格质量验证

```python
def validate_table_extraction(table_data: List[List]) -> bool:
    """
    验证表格提取质量
    
    检查项：
    1. 行数/列数合理（>0）
    2. 表头非空
    3. 没有全空行
    4. 列数一致
    """
    if not table_data or len(table_data) == 0:
        return False
    
    # 检查表头
    if not any(table_data[0]):
        logger.warning("Table header is empty")
        return False
    
    # 检查列数一致性
    col_count = len(table_data[0])
    for row in table_data:
        if len(row) != col_count:
            logger.warning(f"Inconsistent column count: {len(row)} vs {col_count}")
            return False
    
    # 检查全空行
    empty_rows = sum(1 for row in table_data if not any(row))
    if empty_rows > len(table_data) * 0.5:
        logger.warning(f"Too many empty rows: {empty_rows}/{len(table_data)}")
        return False
    
    return True
```

#### 4.1.3 图片处理（图文混合chunk方案）

**核心思路**：VLM描述 + OCR标注 + 上下文文字 → 文本chunk + 图片引用

```python
import fitz  # PyMuPDF
from pathlib import Path

def extract_images_from_pdf(pdf_path: str, output_dir: Path) -> List[Dict]:
    """
    提取PDF中的图片，保存到本地，并OCR识别图中文字
    
    Returns:
        List[{
            "page": 页码,
            "image_index": 页内图片索引,
            "bbox": 图片边界框,
            "image_path": 保存的图片文件路径,
            "caption": 图片标题（下方最近的文本，如"图2.3"）,
            "ocr_text": OCR识别的图中文字
        }]
    """
    images_info = []
    doc = fitz.open(pdf_path)
    
    for page_num, page in enumerate(doc, 1):
        # 获取页面中的所有图片
        image_list = page.get_images()
        
        for img_idx, img in enumerate(image_list):
            xref = img[0]
            base_image = doc.extract_image(xref)
            
            # 保存图片
            image_bytes = base_image["image"]
            image_ext = base_image["ext"]
            image_filename = f"page_{page_num:03d}_img_{img_idx:02d}.{image_ext}"
            image_path = output_dir / image_filename
            
            with open(image_path, "wb") as img_file:
                img_file.write(image_bytes)
            
            # OCR识别图中文字（电路图、接线图的标注）
```

```python
def latex_to_text(latex: str) -> str:
    """
    将LaTeX转换为纯文本表达式
    
    示例：
    \\frac{a}{b} → a / b
    \\sqrt{x} → sqrt(x)
    """
    text = latex
    text = re.sub(r'\\frac\{(.+?)\}\{(.+?)\}', r'(\1) / (\2)', text)
    text = re.sub(r'\\sqrt\{(.+?)\}', r'sqrt(\1)', text)
    text = text.replace('\\times', '×')
    text = text.replace('\\cdot', '·')
    return text
```

### 4.2 Step 2: 智能分块层

#### 4.2.1 国家标准分块策略（条款粒度）

国家标准具有严格的层级结构：**章 → 节 → 条 → 款 → 项**

**分块原则**：
1. **父块**：完整的章节（如"第5章 技术要求"），包含该章下的所有条款
2. **子块**：单个条款（如"5.2.1 插头额定电流"），包含条款号、标题、正文

**Token限制（硬约束）**：

bge-large-zh-v1.5的有效上下文窗口为512 token，超出后向量质量显著下降。父块作为召回单元，必须控制大小：

```
MAX_PARENT_TOKENS = 800   # 父块token上限（留20%余量给特殊字符）
MAX_CHILD_TOKENS  = 256   # 子块token上限
```

当某章节超过800 token时，按条款边界切分为多个父块，确保每个父块对应连续的若干条款。

**父子关系存储说明**：
- `parent_chunk_id`：存于子块payload（Qdrant）及MySQL `chunks`表中
- 父块包含哪些子块：**仅存于MySQL**（通过 `parent_chunk_id` 反查），不写入Qdrant payload，避免payload膨胀

```python
import re
from typing import List, Dict

MAX_PARENT_TOKENS = 800
MAX_CHILD_TOKENS  = 256


def estimate_tokens(text: str) -> int:
    """粗估token数：中文约1字=1token，英文约4字符=1token"""
    chinese = sum(1 for c in text if '一' <= c <= '鿿')
    others = len(text) - chinese
    return chinese + others // 4


class StandardChunker:
    """国家标准分块器，按条款粒度切分"""
    
    def chunk(self, markdown: str, doc_info: Dict) -> List[Dict]:
        """
        分块策略：
        1. 识别章节标题（## / ### 开头）
        2. 识别条款编号（正则匹配 5.2.1、5.2.1.1 等）
        3. 生成父块（章/章片段，≤800 token）+ 子块（条款，≤256 token）
        
        Returns:
            List[{
                "chunk_id": "唯一ID",
                "chunk_type": "parent" | "child",
                "text": "chunk文本内容",
                "parent_chunk_id": "父块ID（仅子块有）",
                "metadata": {条款号、章节、页码等}
            }]
        
        注意：child_chunk_ids 不写入chunk结构，通过MySQL parent_chunk_id FK反查。
        """
        chunks = []
        
        # 1. 按章节拆分
        sections = self.split_by_sections(markdown)
        
        for section in sections:
            # 2. 提取章节下的所有条款（子块）
            clauses = self.extract_clauses(section["content"])
            
            # 3. 将条款分组，确保每组父块不超过 MAX_PARENT_TOKENS
            clause_groups = self._group_clauses_by_token_limit(clauses)
            
            for group_idx, clause_group in enumerate(clause_groups):
                parent_text = "\n\n".join(c["text"] for c in clause_group)
                parent_chunk = {
                    "chunk_id": generate_uuid(),
                    "chunk_type": "parent",
                    "text": parent_text,
                    "metadata": {
                        "chapter": section["chapter_no"],
                        "chapter_title": section["title"],
                        "parent_part": group_idx + 1,  # 同章分多父块时的序号
                        "doc_id": doc_info["doc_id"],
                        "standard_no": doc_info["standard_no"]
                    }
                }
                
                for clause in clause_group:
                    child_chunk = {
                        "chunk_id": generate_uuid(),
                        "chunk_type": "child",
                        "text": clause["text"],
                        "parent_chunk_id": parent_chunk["chunk_id"],
                        "metadata": {
                            "clause": clause["clause_no"],
                            "clause_title": clause["title"],
                            "chapter": section["chapter_no"],
                            **parent_chunk["metadata"]
                        }
                    }
                    chunks.append(child_chunk)
                
                chunks.append(parent_chunk)
        
        return chunks
    
    def _group_clauses_by_token_limit(
        self, clauses: List[Dict]
    ) -> List[List[Dict]]:
        """将条款列表按 MAX_PARENT_TOKENS 分组"""
        groups = []
        current_group = []
        current_tokens = 0
        
        for clause in clauses:
            t = estimate_tokens(clause["text"])
            if current_group and current_tokens + t > MAX_PARENT_TOKENS:
                groups.append(current_group)
                current_group = []
                current_tokens = 0
            current_group.append(clause)
            current_tokens += t
        
        if current_group:
            groups.append(current_group)
        
        return groups if groups else [[]]
    
    def extract_clauses(self, section_text: str) -> List[Dict]:
        """
        提取条款
        
        正则匹配：
        - 5.2.1 条款标题
        - 5.2.1.1 子条款
        - (1) 项
        """
        clause_pattern = r'^(\d+\.\d+(?:\.\d+)*)\s+(.+?)$'
        clauses = []
        
        lines = section_text.split('\n')
        current_clause = None
        
        for line in lines:
            match = re.match(clause_pattern, line.strip())
            if match:
                # 新条款开始
                if current_clause:
                    clauses.append(current_clause)
                
                current_clause = {
                    "clause_no": match.group(1),
                    "title": match.group(2),
                    "text": line
                }
            elif current_clause:
                # 条款正文内容
                current_clause["text"] += "\n" + line
        
        if current_clause:
            clauses.append(current_clause)
        
        return clauses
```

```python
    if is_simple_formula(latex_formula):
        # 简单公式：保留LaTeX即可
        text = f"{formula_block['context']}\n\n{latex_formula}"
    else:
        # 复杂公式：生成自然语言描述
        nl_description = generate_formula_description(latex_formula)
        text_expr = latex_to_text(latex_formula)
        
        text = f"""{formula_block['title']}

【公式】{nl_description}

数学表达式：{text_expr}

LaTeX：{latex_formula}

变量说明：
{extract_variable_explanations(formula_block['context'])}
"""
    
    return {
        "chunk_id": generate_uuid(),
        "chunk_type": "formula",
        "text": text,
        "latex_formula": latex_formula,
        "metadata": {
            "has_formula": True,
            "formula_type": classify_formula_type(latex_formula)
        }
    }
```

## 八、设计决策记录

### 决策1：图片处理方案 - 图文混合chunk vs ColPali

**背景**：电力标准包含大量技术图纸（电路图、接线图），需要支持图片检索。

**备选方案**：
1. **ColPali**：Vision-Language模型，直接处理PDF页面图像，multi-vector检索
2. **图文混合chunk**：VLM生成描述 + OCR标注 + 文本向量检索

**决策**：采用图文混合chunk方案

**理由**：
- 系统核心需求是"可溯源、可校验"，需要句子级引用，ColPali只能返回页面级结果
- 图文混合chunk保留了现有架构（Qdrant单向量 + ES fallback）
- 查询时无需GPU，降低在线成本
- VLM描述生成仅在入库时执行一次，总成本可控

**Trade-off**：
- 放弃了ColPali的原生视觉理解能力
- 但获得了更好的引用精度和更低的查询延迟

### 决策2：公式处理方案 - LaTeX + 自然语言描述

**背景**：电力标准包含大量数学公式，纯LaTeX向量化效果差。

**决策**：保留LaTeX原文 + LLM生成自然语言描述

**理由**：
- LaTeX符号（`\frac`、`\sqrt`）缺乏语义，向量检索效果差
- 自然语言描述（"短路电流等于电压除以阻抗"）可被语义检索
- 保留LaTeX原文，前端可渲染数学公式
- 同时支持变量名的BM25精确匹配

### 决策3：表格分块策略 - 独立成块 vs 拆分行

**背景**：当前`pdf_to_md.py`按行解析表格，导致表格被切碎。

**决策**：表格作为独立chunk存储

**理由**：
- 表格是整体语义单元，拆开会丢失表头和列关系
- 用户查询"检验项目有哪些"应召回整个表格
- 前端可直接渲染完整表格，无需拼接

**实现**：使用pdfplumber的`extract_tables()`提取完整二维数组

### 决策4：复杂表格存储格式 - JSON vs HTML+Markdown

**背景**：复杂表格包含合并单元格（rowspan/colspan），需要同时支持向量检索和精确渲染。

**备选方案**：
1. **HTML+Markdown双存储**：HTML保留完整结构，Markdown用于检索
2. **JSON单一数据源**：JSON记录headers/rows/merges，按需生成Markdown

**决策**：采用JSON单一数据源

**理由**：
- 数据一致性：单一数据源避免HTML与Markdown不一致
- 灵活性：JSON可生成多种格式（Markdown用于检索，HTML用于前端，CSV用于导出）
- 结构化：合并信息显式记录为`{"row":r,"col":c,"rowspan":rs,"colspan":cs}`，便于程序处理
- 存储效率：JSON比HTML+Markdown冗余度低

**Trade-off**：
- 前端渲染需要一次JSON→HTML转换（开销可忽略）
- 但换来了数据完整性和扩展性

### 决策5：VLM模型选择 - Qwen2.5-VL-7B

**备选方案**：
- Qwen2.5-VL-7B（7B参数）
- Qwen2.5-VL-3B（3B参数）
- PaliGemma-3B（通用VLM）

**决策**：Qwen2.5-VL-7B

**理由**：
- 中文技术图纸理解效果好
- 电力专业术语识别准确
- 入库时已用GPU，无额外硬件成本
- 7B vs 3B的精度提升值得多20%的推理时间
