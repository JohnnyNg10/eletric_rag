# 索引存储层 (Index Storage Layer)

本文档详细描述索引存储层的架构设计，涵盖向量库、全文检索库、结构化元数据库的三库协同机制。

**核心理念**：三库协同、多路召回，覆盖不同检索场景，提供多维度过滤能力。

**说明**：示例基于实际标准库（`电力国标PDF/` 目录，当前26个标准），可扩展至数千标准。

---

## 一、架构概览

### 1.1 三库协同架构

采用「向量库 + 全文检索库 + 结构化元数据库」三库并存架构，各司其职、优势互补。

```
┌─────────────────────────────────────────────────────┐
│                 索引存储层架构                       │
├─────────────────────────────────────────────────────┤
│                                                      │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────┐  │
│  │  Qdrant      │  │ Elasticsearch│  │  MySQL   │  │
│  │  向量数据库   │  │  全文检索引擎 │  │ 元数据库  │  │
│  └──────────────┘  └──────────────┘  └──────────┘  │
│        ▲                  ▲                 ▲        │
│        │                  │                 │        │
│  ┌─────┴──────────────────┴─────────────────┴─────┐ │
│  │          三路召回 (Recall Layer)               │ │
│  │  - 语义召回 (向量库)                            │ │
│  │  - 关键词召回 (全文检索)                        │ │
│  │  - 精确召回 (结构化查询)                        │ │
│  └─────────────────────────────────────────────────┘ │
│                                                      │
└─────────────────────────────────────────────────────┘
```

### 1.2 存储内容划分

| 存储系统 | 存储对象 | 主要用途 | 检索场景 |
|---------|---------|---------|---------|
| Qdrant | 父块向量（稠密+稀疏）+ Payload元数据 | 语义相似度检索 + 混合检索 | 概念查询、模糊查询 |
| Elasticsearch | 子块原始文本 + 分词索引 | 关键词精确匹配、短语检索 | 术语查询、标准号查询 |
| MySQL | 文档台账、元数据、引用关系、用户日志 | 精确定位、结构化查询、统计分析 | 标准号直查、条款号定位 |
| MinIO | 原始PDF文件 | 原文下载、离线归档 | 溯源验证 |

## 二、Qdrant 向量数据库

### 2.1 技术选型理由

- **原生混合检索**：支持稠密向量 + 稀疏向量融合，单次查询完成语义召回与关键词匹配
- **灵活的 Payload 过滤**：支持嵌套条件、范围查询、数组匹配，可按专业分类、电压等级等维度缩小检索空间
- **高性能索引**：HNSW图索引，百万级向量检索延迟 <100ms
- **轻量化部署**：Rust实现，单二进制文件，资源占用低
- **Scalar Quantization**：量化压缩，内存占用降低50%+

### 2.3 混合检索实现

#### 稠密 + 稀疏向量融合

```python
from qdrant_client.models import SearchRequest, QueryRequest, FusionQuery

# 混合检索：稠密向量(语义) + 稀疏向量(关键词)
results = client.query_points(
    collection_name="documents",
    query=FusionQuery(
        fusion="rrf",  # Reciprocal Rank Fusion
        queries=[
            # 稠密向量查询（语义召回）
            {
                "using": "dense",
                "vector": dense_embedding,  # 1024维
                "limit": 50
            },
            # 稀疏向量查询（关键词召回）
            {
                "using": "sparse",
                "vector": sparse_embedding,  # {token_id: weight}
                "limit": 50
            }
        ]
    ),
    # Payload 过滤
    filter={
        "must": [
            {"key": "status", "match": {"value": "valid"}},
            {"key": "voltage_level", "match": {"value": "250V"}},
            {"key": "category", "match": {"any": ["电气安全", "插头插座"]}}
        ]
    },
    limit=20,
    with_payload=True
)
```

#### RRF 融合算法

Qdrant 内置 Reciprocal Rank Fusion 算法，自动融合多路召回结果：

```
RRF_score(doc) = Σ 1 / (k + rank_i(doc))

其中：
- rank_i(doc) 是文档在第 i 路召回中的排名
- k 是常数（默认60）
```

### 2.5 HNSW 索引参数调优

```python
# Collection 创建时指定 HNSW 参数
client.create_collection(
    collection_name="documents",
    vectors_config={
        "dense": VectorParams(
            size=1024,
            distance=Distance.COSINE,
            hnsw_config={
                "m": 16,  # 每个节点的连接数（默认16）
                "ef_construct": 100,  # 构建时的搜索深度（默认100）
            }
        )
    }
)

# 查询时指定 ef 参数（搜索深度）
results = client.search(
    collection_name="documents",
    query_vector=dense_embedding,
    limit=20,
    search_params={"hnsw_ef": 128}  # 查询时搜索深度（越大越准确但越慢）
)
```

**参数说明**：
- `m`：每个节点连接数，↑提升召回率，↓降低内存占用
- `ef_construct`：构建时搜索深度，↑提升索引质量，↓延长构建时间
- `hnsw_ef`：查询时搜索深度，↑提升召回率，↓增加延迟

**推荐配置**：
- 开发环境：`m=16, ef_construct=100, hnsw_ef=64`
- 生产环境：`m=32, ef_construct=200, hnsw_ef=128`

## 六、三库协同检索策略

### 6.1 检索决策树

```python
def route_retrieval(query: str, metadata: dict) -> str:
    """根据查询类型决定检索策略"""
    
    # 规则1: 明确标准号 → MySQL直查
    if has_standard_no(query):
        return "structured_query"
    
    # 规则2: 明确条款号 → MySQL精确定位
    if has_clause_number(query):
        return "structured_query"
    
    # 规则3: 精确术语（设备型号、参数） → ES关键词检索
    if has_exact_terms(query):
        return "keyword_search"
    
    # 规则4: 概念性查询 → Qdrant语义检索
    if is_conceptual(query):
        return "semantic_search"
    
    # 默认: 混合检索（Qdrant稠密+稀疏向量融合）
    return "hybrid_search"
```

### 6.2 三路召回融合

```python
async def three_way_recall(query: str, filters: dict, top_k: int = 20):
    """
    三路并行召回
    
    1. 向量库语义召回（Qdrant）
    2. 关键词召回（Elasticsearch BM25）
    3. 结构化召回（MySQL精确匹配）
    """
    # 并行执行三路召回
    vector_results, es_results, db_results = await asyncio.gather(
        qdrant_search(query, filters, top_k),
        elasticsearch_search(query, filters, top_k),
        mysql_search(query, filters)
    )
    
    # RRF融合
    merged_results = reciprocal_rank_fusion([
        vector_results,
        es_results,
        db_results
    ], k=60)
    
    return merged_results[:top_k]
```

### 6.3 RRF 融合算法实现

```python
def reciprocal_rank_fusion(results_list: List[List[dict]], k: int = 60) -> List[dict]:
    """
    Reciprocal Rank Fusion 算法
    
    RRF_score(doc) = Σ 1 / (k + rank_i(doc))
    """
    doc_scores = {}
    
    for results in results_list:
        for rank, doc in enumerate(results, start=1):
            doc_id = doc["chunk_id"]
            score = 1.0 / (k + rank)
            
            if doc_id not in doc_scores:
                doc_scores[doc_id] = {"doc": doc, "score": 0}
            
            doc_scores[doc_id]["score"] += score
    
    # 按分数排序
    sorted_docs = sorted(
        doc_scores.values(),
        key=lambda x: x["score"],
        reverse=True
    )
    
    return [item["doc"] for item in sorted_docs]
```

## 九、容量规划

### 9.1 数据量估算

**当前状态（初期数据）**：
- 标准文档：26个（`电力国标PDF/` 目录）
- 平均页数：约30页/文档（实际文件大小 380KB~1.7MB）
- 分块粒度：父块512 token，子块256 token
- 父子块比例：1:4

**初期计算**：
- 总父块数：26 × 30 / 2 = 390个
- 总子块数：390 × 4 = 1,560个

**扩展规划（目标规模）**：
- 标准文档：2000~5000个（覆盖GB/DL/NB全系列电力标准）
- 总父块数：50,000~125,000个
- 总子块数：200,000~500,000个

### 9.2 存储空间估算

**初期（26个标准）**：

| 存储系统 | 存储对象 | 单条大小 | 总量 | 总空间 |
|---------|---------|---------|------|--------|
| Qdrant | 父块向量 | 4KB (1024维float32) | 390 | 1.6MB |
| Qdrant | 稀疏向量 | 1KB | 390 | 390KB |
| Qdrant | Payload | 2KB | 390 | 780KB |
| ES | 子块文本 | 1KB | 1.5K | 1.5MB |
| MySQL | 元数据 | 2KB | 26 | 52KB |
| MinIO | 原始PDF | 1MB平均 | 26 | 26MB |

**总计（初期）**：Qdrant ~3MB, ES ~2MB, MySQL ~100KB, MinIO ~26MB

**扩展后（5000个标准）**：

| 存储系统 | 总空间 |
|---------|--------|
| Qdrant | ~1GB |
| ES | ~500MB |
| MySQL | ~10MB |
| MinIO | ~5GB |
