# 扫描件 PDF 存储方案设计

## 一、问题背景

### 1.1 当前情况

**数据源**：`实际数据/DL/` 目录下的扫描件 PDF 文档
- 文件类型：水电水利工程相关的 DL 系列标准
- 文件特点：**扫描件**，非原生 PDF
- 内容组成：
  - 条文文字（需 OCR 识别）
  - 工程图纸（需图像识别）
  - 数据表格（需表格解析）

### 1.2 核心挑战

| 挑战 | 说明 | 影响 |
|------|------|------|
| OCR 质量不稳定 | 扫描质量参差不齐，部分文字模糊 | 检索召回率下降 |
| 图表分离困难 | 图片、表格与正文混排 | 无法单独索引图表 |
| 版面复杂 | 双栏排版、页眉页脚、批注 | 内容提取顺序错乱 |
| 文件体积大 | 高分辨率扫描件，单文件 10MB+ | 存储和传输成本高 |

### 1.3 设计目标

1. **文字可检索**：OCR 识别文字并建立全文索引
2. **图表可定位**：提取图片和表格，支持图文混合检索
3. **溯源可追溯**：保留原始 PDF 和页面坐标，支持精确定位
4. **性能可接受**：处理速度满足批量导入需求

### 2.1 多层存储架构

```
┌─────────────────────────────────────────────────────────┐

├─────────────────────────────────────────────────────────┤

│  │  层级 1: 原始文件层 (MinIO)                       │  │

│                         ↓                                │

│  │  层级 2: 解析结果层 (MinIO + MySQL)               │  │
│  │  - OCR 识别文本（Markdown）                       │  │

│  │  - 提取的表格（JSON/CSV）                         │  │
│  │  - 页面坐标映射（JSON）                           │  │
│  └──────────────────────────────────────────────────┘  │
│                         ↓                                │
│  ┌──────────────────────────────────────────────────┐  │
│  │  层级 3: 结构化索引层 (MySQL)                     │  │

│  │  - 章节条款结构                                   │  │
│  │  - 图表元数据（类型、位置、标题）                │  │
│  └──────────────────────────────────────────────────┘  │
│                         ↓                                │
│  ┌──────────────────────────────────────────────────┐  │
│  │  层级 4: 检索索引层 (Qdrant + ES)                 │  │
│  │  - 文本向量（语义检索）                           │  │
│  │  - 图像向量（CLIP/多模态）                        │  │
│  │  - 全文索引（关键词检索）                         │  │
│  └──────────────────────────────────────────────────┘  │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### 2.2 存储分工

| 存储层 | 存储内容 | 用途 | 特点 |
|--------|---------|------|------|
| **MinIO - PDF Bucket** | 原始扫描 PDF | 溯源验证、离线归档 | 只写不改，永久保存 |
| **MinIO - Markdown Bucket** | OCR 文本（Markdown） | 人工审核、内容校验 | 结构化文本 |
| **MinIO - Image Bucket** | 提取的图片 | 图文混合检索、展示 | 按页面组织 |
| **MinIO - Table Bucket** | 提取的表格（JSON） | 结构化数据检索 | 可转 CSV/Excel |
| **MySQL - documents** | 文档元数据 | 精确查询、版本管理 | 标准号、状态 |
| **MySQL - chunks** | 文本块元数据 | 位置追溯、关联关系 | 条款号、坐标 |
| **MySQL - images** | 图片元数据 | 图片定位、分类 | 类型、标题、坐标 |
| **MySQL - tables** | 表格元数据 | 表格定位、检索 | 列信息、数据类型 |
| **Qdrant** | 文本向量 + 图像向量 | 语义检索、多模态检索 | 混合检索 |
| **Elasticsearch** | OCR 文本 + 表格内容 | 关键词精确匹配 | BM25 排序 |

#### 3.1.1.1 Chunk表（扩展内容类型）

**关键改进**：增加 `content_type` 字段，统一管理文本、图片描述、表格摘要

```python
class Chunk(Base):
    """文档块表（扩展支持图片描述、表格摘要）"""
    __tablename__ = "chunks"
    
    # ... 原有字段 ...
    
    # 内容
    content = Column(Text, nullable=False, comment="文本内容")
    
    # 新增：内容类型（关键）
    content_type = Column(
        Enum('text', 'image_description', 'table_summary', name='content_type_enum'),
        nullable=False,
        default='text',
        comment="内容类型"
    )
    
    # 关联ID（根据content_type决定）
    # - content_type='text': 无关联
    # - content_type='image_description': 关联image_id
    # - content_type='table_summary': 关联table_id
    related_resource_id = Column(BigInteger, comment="关联的资源ID（图片/表格）")
    related_resource_type = Column(String(20), comment="资源类型（image/table）")
    
    # 向量信息（统一向量化）
    vector_id = Column(String(100), comment="Qdrant向量ID")
    has_dense_vector = Column(Boolean, default=False)
    has_sparse_vector = Column(Boolean, default=False)
```

**内容类型说明**：

| content_type | content字段内容 | related_resource_id | 用途 |
|-------------|----------------|---------------------|------|
| `text` | 原文文本 | NULL | 普通文本块 |
| `image_description` | VLM生成的图片描述 | image_id | 图片检索入口 |
| `table_summary` | 表格内容摘要 | table_id | 表格检索入口 |

#### 3.1.2 新增：图片表

class Image(Base):
    """图片表"""
    __tablename__ = "images"
    
    id = Column(BigInteger, primary_key=True, autoincrement=True)
    document_id = Column(BigInteger, ForeignKey('documents.id'), nullable=False)

                     comment="关联的文本块ID（VLM描述块）")
    
    # 图片信息
    image_type = Column(
        Enum('figure', 'diagram', 'photo', 'chart', name='image_type_enum'),
        nullable=False,
        comment="图片类型"
    )
    file_path = Column(String(500), nullable=False, comment="MinIO文件路径")
    file_size = Column(Integer, comment="文件大小（字节）")
    width = Column(Integer, comment="宽度（像素）")
    height = Column(Integer, comment="高度（像素）")
    
    # 位置信息
    page_number = Column(Integer, nullable=False, comment="所在页码")
    bbox = Column(JSON, comment="边界框坐标 {x, y, width, height}")
    
    # 内容信息
    caption = Column(Text, comment="图注/标题")
    figure_number = Column(String(50), comment="图号（如 图5-2）")
    ocr_text = Column(Text, comment="图内文字（OCR识别）")
    
    # VLM生成的描述（不单独索引，通过chunk_id关联）
    vlm_description = Column(Text, comment="VLM生成的图片语义描述")
    vlm_model = Column(String(50), comment="使用的VLM模型（如豆包vision-pro）")
    vlm_confidence = Column(Float, comment="VLM描述置信度")
    
    # 元数据
    metadata = Column(JSON, comment="扩展元数据")
    
    created_at = Column(TIMESTAMP, server_default=func.now())
    
    # 索引
    __table_args__ = (
        Index('idx_document_id', 'document_id'),
        Index('idx_chunk_id', 'chunk_id'),
        Index('idx_page_number', 'page_number'),
        Index('idx_figure_number', 'figure_number'),
        {'comment': '图片表'}
    )
```

**关键改进**：
- `chunk_id`：指向包含VLM描述的文本块
- 不再需要`vector_id`，因为图片不单独建向量索引
- VLM描述存储在Image表，但通过Chunk表统一检索
```

### 4.2 核心技术选型

#### 4.2.1 OCR 引擎

**主选：PaddleOCR**
- **优势**：中文识别准确率高（~95%），支持倾斜/模糊文字
- **速度**：CPU 模式 ~0.5秒/页，GPU 模式 ~0.1秒/页
- **输出**：文字 + 坐标 + 置信度

```python
from paddleocr import PaddleOCR

ocr = PaddleOCR(
    use_angle_cls=True,  # 支持旋转识别
    lang='ch',           # 中文
    use_gpu=True,
    show_log=False
)

result = ocr.ocr(img_path, cls=True)
# 返回: [[[bbox], (text, confidence)], ...]
```

**备选：Tesseract 5.x**
- **优势**：开源免费，支持100+语言
- **劣势**：中文识别率较低（~85%），对扫描质量要求高

#### 4.2.2 表格识别

**主选：PaddleOCR-Table / TableMaster**
- **能力**：识别复杂表格（合并单元格、无边框表格）
- **输出**：HTML/JSON 结构 + 单元格内容

```python
from paddleocr import PPStructure

table_engine = PPStructure(
    table=True,
    ocr=True,
    show_log=False
)

result = table_engine(img)
# 返回: [{'type': 'table', 'bbox': [...], 'res': {...}}]
```

#### 4.2.3 VLM 图片描述生成（使用 API）

**主选：豆包多模态 API / 通义千问VL API**
- **优势**：无需本地部署大模型，节省显存
- **成本**：~0.01元/图片
- **速度**：API调用 ~1-2秒/图片

**环境变量配置（.env）**：
```bash
# VLM API 配置
ENABLE_VLM_DESCRIPTION=true
VLM_PROVIDER=doubao  # doubao / qwen / local
DOUBAO_API_KEY=your_api_key_here
DOUBAO_API_ENDPOINT=https://ark.cn-beijing.volces.com/api/v3/chat/completions
QWEN_API_KEY=your_qwen_api_key
```

**豆包多模态 API 实现**：
```python
# backend/app/core/vlm/vlm_client.py

import requests
import base64
from app.config import settings

class VLMAPIClient:
    """VLM API 客户端（豆包多模态）"""
    
    def __init__(self):
        self.provider = settings.VLM_PROVIDER
        
        if self.provider == "doubao":
            self.api_key = settings.DOUBAO_API_KEY
            self.endpoint = settings.DOUBAO_API_ENDPOINT
            self.model = "doubao-vision-pro"
        elif self.provider == "qwen":
            self.api_key = settings.QWEN_API_KEY
            self.model = "qwen-vl-plus"
    
    async def generate_description(self, image_path: str) -> dict:
        """
        生成图片描述
        
        Returns:
            {
                'description': '图片描述文本',
                'confidence': 0.95,
                'model': 'doubao-vision-pro'
            }
        """
        if not settings.ENABLE_VLM_DESCRIPTION:
            return {'description': None, 'confidence': 0.0}
        
        if self.provider == "doubao":
            return await self._call_doubao_api(image_path)
        elif self.provider == "qwen":
            return await self._call_qwen_api(image_path)
        else:
            return {'description': None, 'confidence': 0.0}
    
    async def _call_doubao_api(self, image_path: str) -> dict:
        """调用豆包API"""
        
        # 1. 读取图片并转为 base64
        with open(image_path, 'rb') as f:
            image_base64 = base64.b64encode(f.read()).decode('utf-8')
        
        # 2. 构造请求
        payload = {
            "model": self.model,
            "messages": [
                {
                    "role": "user",
                    "content": [
                        {
                            "type": "image_url",
                            "image_url": {
                                "url": f"data:image/png;base64,{image_base64}"
                            }
                        },
                        {
                            "type": "text",
                            "text": """请详细描述这张工程图纸，包括：
1. 图纸类型（剖面图/平面图/示意图/流程图）
2. 主要组成部分和关键设备
3. 结构布局和空间关系
4. 图中的重要标注和尺寸

要求：用一段话概括，不超过100字，专注于技术细节。"""
                        }
                    ]
                }
            ],
            "temperature": 0.3,
            "max_tokens": 200
        }
        
        headers = {
            "Authorization": f"Bearer {self.api_key}",
            "Content-Type": "application/json"
        }
        
        # 3. 发送请求
        try:
            response = requests.post(
                self.endpoint,
                json=payload,
                headers=headers,
                timeout=10
            )
            
            if response.status_code != 200:
                return {
                    'description': None,
                    'confidence': 0.0,
                    'error': f"API调用失败: {response.text}"
                }
            
            # 4. 解析响应
            result = response.json()
            description = result['choices'][0]['message']['content']
            
            return {
                'description': description,
                'confidence': 0.9,
                'model': self.model
            }
        
        except Exception as e:
            return {
                'description': None,
                'confidence': 0.0,
                'error': str(e)
            }

# 全局实例
vlm_client = VLMAPIClient()
```

| 方案 | 优势 | 劣势 | 适用场景 |
|------|------|------|---------|
| **API（推荐）** | 无需显存、快速部署、模型自动更新 | 依赖网络、按量付费 | 初期开发、批量导入 |
| **本地模型** | 离线运行、无API费用 | 需14GB显存、维护成本高 | 大规模生产环境 |

**成本估算**：
- 图片数量：~300张（20个DL标准）
- API成本：300 × 0.01元 = 3元
- 结论：初期使用API完全可行

```python
# backend/app/tasks/scan_processor.py

from celery import shared_task
from paddleocr import PaddleOCR, PPStructure
import asyncio

@shared_task(bind=True)
def process_scanned_pdf_task(self, pdf_path: str, doc_id: int):
    """
    异步处理扫描件 PDF
    
    Args:
        pdf_path: PDF 文件路径
        doc_id: 文档 ID
    """
    try:
        processor = ScannedPDFProcessor()
        
        # 更新处理状态
        self.update_state(state='PROCESSING', meta={'progress': 0})
        
        # 处理文档
        result = asyncio.run(processor.process_document(pdf_path, doc_id))
        
        return {
            'status': 'success',
            'doc_id': doc_id,
            'pages_processed': result['page_count'],
            'images_extracted': result['image_count'],
            'tables_extracted': result['table_count']
        }
        
    except Exception as e:
        self.update_state(state='FAILURE', meta={'error': str(e)})
        raise


class ScannedPDFProcessor:
    """扫描件 PDF 处理器"""
    
    def __init__(self):
        self.ocr = PaddleOCR(use_angle_cls=True, lang='ch', use_gpu=True)
        self.table_engine = PPStructure(table=True, ocr=True)
        
        # 加载 VLM API 客户端（从环境变量读取配置）
        if settings.ENABLE_VLM_DESCRIPTION:
            from app.core.vlm.vlm_client import vlm_client
            self.vlm_client = vlm_client
        else:
            self.vlm_client = None
    
    async def process_document(self, pdf_path: str, doc_id: int):
        """处理单个扫描件 PDF"""
        
        # 1. 上传原始 PDF 到 MinIO
        await self._upload_original_pdf(pdf_path, doc_id)
        
        # 2. 转换为图片
        page_images = self._pdf_to_images(pdf_path)
        
        # 3. 并行处理每一页
        tasks = [
            self._process_page(img, page_num, doc_id)
            for page_num, img in enumerate(page_images, start=1)
        ]
        page_results = await asyncio.gather(*tasks)
        
        # 4. 合并结果并生成 Markdown
        full_markdown = self._merge_pages_to_markdown(page_results)
        await self._save_markdown(full_markdown, doc_id)
        
        # 5. 保存图片和表格到 MinIO
        await self._save_images_and_tables(page_results, doc_id)
        
        # 6. 更新数据库元数据
        await self._update_database(doc_id, page_results)
        
        # 7. 向量化并存入 Qdrant + ES
        await self._vectorize_and_index(doc_id, page_results)
        
        return {
            'page_count': len(page_results),
            'image_count': sum(len(p['images']) for p in page_results),
            'table_count': sum(len(p['tables']) for p in page_results)
        }
    
    async def _process_page(self, image, page_num: int, doc_id: int):
        """处理单页"""
        result = {
            'page_num': page_num,
            'text_blocks': [],
            'images': [],
            'tables': []
        }
        
        # 1. 版面分析（识别文字/图片/表格区域）
        layout = self.table_engine(image)
        
        for region in layout:
            if region['type'] == 'text':
                # OCR 文字识别
                ocr_result = self.ocr.ocr(region['bbox'], cls=True)
                text_block = {
                    'text': self._extract_text_from_ocr(ocr_result),
                    'bbox': region['bbox'],
                    'confidence': self._get_avg_confidence(ocr_result)
                }
                result['text_blocks'].append(text_block)
            
            elif region['type'] == 'figure':
                # 提取图片 + 生成 VLM 描述
                img_info = await self._extract_and_describe_image(
                    image, region['bbox'], page_num, doc_id
                )
                result['images'].append(img_info)
            
            elif region['type'] == 'table':
                # 表格识别
                table_info = await self._recognize_table(
                    image, region['bbox'], page_num, doc_id
                )
                result['tables'].append(table_info)
        
        return result
    
    async def _extract_and_describe_image(
        self, 
        page_image, 
        bbox, 
        page_num: int, 
        doc_id: int
    ):
        """提取图片并生成 VLM 描述"""
        
        # 1. 裁剪图片区域
        cropped = page_image.crop(bbox)
        
        # 2. 保存到本地临时文件
        temp_path = f"/tmp/doc_{doc_id}_page_{page_num}_fig.png"
        cropped.save(temp_path)
        
        # 3. OCR 识别图内文字
        ocr_result = self.ocr.ocr(temp_path, cls=True)
        ocr_text = self._extract_text_from_ocr(ocr_result)
        
        # 4. 使用 VLM API 生成语义描述
        vlm_result = await self._generate_vlm_description(temp_path)
        vlm_description = vlm_result.get('description', '')
        
        # 5. 上传到 MinIO
        object_name = f"doc_{doc_id}/page_{page_num:03d}_fig.png"
        await object_store.upload_image(temp_path, object_name)
        
        # 6. 创建图片记录（稍后关联到chunk）
        return {
            'file_path': object_name,
            'bbox': bbox,
            'page_number': page_num,
            'ocr_text': ocr_text,
            'vlm_description': vlm_description,
            'vlm_model': vlm_result.get('model', ''),
            'vlm_confidence': vlm_result.get('confidence', 0.0)
        }
    
    async def _save_images_and_create_chunks(self, page_results: List, doc_id: int):
        """
        保存图片到数据库，并为每张图片创建描述Chunk
        
        关键：VLM描述作为Chunk存入，参与统一检索
        """
        for page_result in page_results:
            for img_info in page_result['images']:
                # 1. 保存图片到 images 表（先不关联chunk_id）
                image = Image(
                    document_id=doc_id,
                    image_type='diagram',
                    file_path=img_info['file_path'],
                    page_number=img_info['page_number'],
                    bbox=img_info['bbox'],
                    ocr_text=img_info['ocr_text'],
                    vlm_description=img_info['vlm_description'],
                    vlm_model=img_info['vlm_model'],
                    vlm_confidence=img_info['vlm_confidence']
                )
                db.add(image)
                await db.flush()  # 获取image.id
                
                # 2. 为图片描述创建 Chunk（关键）
                if img_info['vlm_description']:
                    chunk = Chunk(
                        document_id=doc_id,
                        content=img_info['vlm_description'],  # VLM描述作为内容
                        content_type='image_description',     # 标记类型
                        related_resource_id=image.id,         # 关联图片ID
                        related_resource_type='image',
                        page_start=img_info['page_number'],
                        page_end=img_info['page_number'],
                        chunk_type='parent'
                    )
                    db.add(chunk)
                    await db.flush()
                    
                    # 3. 反向关联：图片记录chunk_id
                    image.chunk_id = chunk.id
                    
                    # 4. 向量化图片描述Chunk（统一向量化）
                    await self._vectorize_chunk(chunk)
        
        await db.commit()
    
    async def _generate_vlm_description(self, image_path: str) -> str:
        """使用 VLM API 生成图片描述"""
        
        if not self.vlm_client:
            return ""  # VLM 功能未启用
        
        result = await self.vlm_client.generate_description(image_path)
        
        return result.get('description', '')
```

```python
async def unified_search(query: str, top_k: int = 20):
    """
    统一文本检索（不区分内容类型）
    
    关键：所有Chunk统一检索，通过content_type区分处理
    """
    
    # 1. 向量召回（Qdrant）
    text_embedding = await embedder.embed(query)
    vector_results = await qdrant_client.search(
        collection_name="documents",
        query_vector=text_embedding,
        limit=top_k
    )
    
    # 2. 关键词召回（ES）
    es_results = await es_client.search(
        index="documents",
        body={
            "query": {
                "match": {
                    "content": query
                }
            },
            "size": top_k
        }
    )
    
    # 3. RRF融合
    merged_chunks = reciprocal_rank_fusion([vector_results, es_results])
    
    # 4. 加载关联资源（图片/表格）
    enriched_chunks = await enrich_with_resources(merged_chunks)
    
    return enriched_chunks


async def enrich_with_resources(chunks: List[dict]) -> List[dict]:
    """
    为检索结果加载关联的图片/表格
    """
    enriched = []
    
    for chunk in chunks:
        enriched_chunk = chunk.copy()
        
        # 如果是图片描述块，加载图片信息
        if chunk['content_type'] == 'image_description':
            image_id = chunk['related_resource_id']
            image = await db.query(Image).filter(Image.id == image_id).first()
            
            enriched_chunk['image'] = {
                'id': image.id,
                'file_path': image.file_path,
                'caption': image.caption,
                'figure_number': image.figure_number,
                'page_number': image.page_number
            }
        
        # 如果是表格摘要块，加载表格信息
        elif chunk['content_type'] == 'table_summary':
            table_id = chunk['related_resource_id']
            table = await db.query(Table).filter(Table.id == table_id).first()
            
            enriched_chunk['table'] = {
                'id': table.id,
                'json_path': table.json_path,
                'title': table.title,
                'page_number': table.page_number
            }
        
        enriched.append(enriched_chunk)
    
    return enriched
```

async def generate_answer(chunks: List[dict], query: str) -> str:
    """
    生成答案，自动插入图片和表格
    """
    
    # 1. 构造上下文
    context_parts = []
    
    for chunk in chunks:
        if chunk['content_type'] == 'text':
            context_parts.append(chunk['content'])
        
        elif chunk['content_type'] == 'image_description':
            # VLM描述作为上下文
            context_parts.append(chunk['content'])
            # 标记：生成时需要插入图片
            context_parts.append(f"[IMAGE:{chunk['image']['id']}]")
        
        elif chunk['content_type'] == 'table_summary':
            context_parts.append(chunk['content'])
            context_parts.append(f"[TABLE:{chunk['table']['id']}]")
    
    context = "\n\n".join(context_parts)
    
    # 2. 调用LLM生成答案
    prompt = f"""
    基于以下内容回答用户问题：
    
    {context}
    
    用户问题：{query}
    
    要求：
    1. 当看到[IMAGE:xxx]标记时，在答案中插入"如图X所示"
    2. 当看到[TABLE:xxx]标记时，在答案中插入"如表X所示"
    """
    
    answer = await llm_client.generate(prompt)
    
    # 3. 返回答案 + 关联资源列表
    return {
        'answer': answer,
        'images': [c['image'] for c in chunks if c['content_type'] == 'image_description'],
        'tables': [c['table'] for c in chunks if c['content_type'] == 'table_summary']
    }
```

   ```python
   async def multimodal_search(query: str, top_k: int = 10):
       """图文混合检索"""

       # 1. 判断查询意图
       intent = detect_intent(query)  # "text" / "image" / "table" / "mixed"

       # 2. 生成文本向量
       text_embedding = await embedder.embed(query)

       results = []

       if intent in ["text", "mixed"]:
           # 3a. 文本向量召回
           text_results = await qdrant_client.search(
               collection_name="documents",
               query_vector=text_embedding,
               limit=top_k
           )
           results.extend(text_results)

       if intent in ["image", "mixed"]:
           # 3b. 图像向量召回（使用 CLIP 编码文本）
           clip_embedding = await clip_model.encode_text(query)

           image_results = await qdrant_client.search(
               collection_name="images",
               query_vector=clip_embedding,
               limit=top_k,
               query_filter={
                   "must": [
                       {"key": "doc_type", "match": {"value": "standard"}}
                   ]
               }
           )
           results.extend(image_results)

       if intent in ["table", "mixed"]:
           # 3c. 表格内容检索（ES全文匹配）
           table_results = await es_client.search(
               index="tables",
               query={"match": {"content_summary": query}},
               size=top_k
           )
           results.extend(table_results)

       # 4. RRF 融合
       merged = reciprocal_rank_fusion(results)

       return merged[:top_k]
   ```

   ## 七、性能优化

   ### 7.1 批量处理策略

   ```python
   # 使用 Celery 分布式任务队列
   @shared_task
   def batch_process_pdfs(pdf_list: List[str]):
       """批量处理 PDF"""

       # 将任务分发到多个 worker
       tasks = [
           process_scanned_pdf_task.apply_async(args=[pdf_path, doc_id])
           for pdf_path, doc_id in pdf_list
       ]

       # 等待所有任务完成
       results = [task.get() for task in tasks]

       return results
   ```

   ### 7.2 GPU 加速

   ```python
   # PaddleOCR GPU 配置
   ocr = PaddleOCR(
       use_gpu=True,
       gpu_mem=8000,  # 8GB 显存
       use_mp=True,   # 多进程
       total_process_num=4  # 4个进程并行
   )

   # 批量处理（提升吞吐量）
   images = [page1, page2, page3, page4]
   results = ocr.ocr(images, cls=True)
   ```

   ### 7.3 增量处理

   只处理新增或更新的文档：

   ```python
   def should_process(pdf_path: str, doc_id: int) -> bool:
       """判断是否需要重新处理"""

       # 检查文件哈希
       current_hash = calculate_file_hash(pdf_path)

       doc = db.query(Document).filter(Document.id == doc_id).first()

       if not doc or doc.file_hash != current_hash:
           return True  # 新文件或文件已更新

       if doc.process_status == 'failed':
           return True  # 上次处理失败

       return False  # 已处理且未更新
   ```

   ## 十、与现有系统并行运行

   ### 10.1 架构隔离设计

   扫描件PDF处理作为**可选扩展功能**，与现有文本RAG系统完全隔离：

   ```
   ┌─────────────────────────────────────────────────────────┐
   │              现有系统 + 扫描件扩展（并行）               │
   └─────────────────────────────────────────────────────────┘

   用户查询
      ↓
   ┌─────────────────────────────────────────────────────────┐
   │ 预处理 + 路由（不变）                                    │
   └─────────────────────────────────────────────────────────┘
      ↓
   ┌──────────────────┬──────────────────────────────────────┐
   │  原有文本检索    │  新增图片检索（可选）                 │
   │  (始终启用)      │  (通过开关控制)                       │
   ├──────────────────┼──────────────────────────────────────┤
   │ Qdrant:          │ ES: images 索引                       │
   │  documents       │ Qdrant: images collection (可选)     │
   │ ES:              │ MySQL: images/tables 表               │
   │  documents 索引  │                                       │
   │ MySQL:           │                                       │
   │  documents 表    │                                       │
   └──────────────────┴──────────────────────────────────────┘
   ```
