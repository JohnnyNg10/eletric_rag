# 知识加工层 (Knowledge Processing Layer)

本文档详细描述知识加工层的设计与实现，涵盖文档解析、智能分块、元数据处理、术语增强等核心环节。

**核心理念**：70%的RAG效果来自数据质量，知识加工层是命中率的基础。

**说明**：文档示例基于实际标准库（`电力国标PDF/` 目录，当前26个标准文件），可扩展至数千标准。

---

## 一、架构概览

### 1.1 定位与职责

知识加工层位于数据流水线的**前端处理阶段**，负责将原始PDF文档转换为结构化、可检索的知识单元。

```
原始PDF文档
    ↓
文档解析（PDF → Markdown）
    ↓
智能分块（父子块混合）
    ↓
术语增强（标准化 + 扩展）
    ↓
元数据挂载（分类 + 权重）
    ↓
向量化（稠密 + 稀疏）
    ↓
索引存储（三库协同）
```

### 1.2 两类数据源的差异化处理

#### 国家标准类文档（GB/GB/T/DL/NB）

**结构特点**：
- 层级严谨：章-节-条-款-项
- 条款独立性强
- 引用关系多
- 版本更替频繁
- 附表附录多

**处理策略**：
1. 结构化提取：标准号、版本号、发布日期、实施日期、替代关系
2. 按**条款粒度**拆分：单条独立成块，保留完整条款编号
3. 引用关联：自动关联引用的其他条款，形成关联块组
4. 附录处理：表格、参数表单独成块，保留表格结构与表头

#### 电力专业书籍类文档

**结构特点**：
- 章节体系清晰
- 原理推导多
- 公式密集
- 图表配套
- 知识点连贯性强

**处理策略**：
1. 按目录层级提取章节结构
2. 按**语义知识点**分块：公式+推导+适用条件整体成块
3. 图表绑定：图表与对应文字说明绑定成块
4. 核心标记：定义、定理、结论做标记加权

## 二、文档解析流水线

### 2.1 解析流程

```
原始PDF → 版面分析 → 文本提取 → 公式识别 → 表格还原 → 结构重建 → 清洗归一
```

### 2.2 文字版PDF处理

**优先策略**：提取原生文本与排版结构

**保留信息**：
- 标题层级（H1~H6）
- 列表结构（有序/无序）
- 表格边框与单元格对齐
- 字体加粗、斜体等样式标记

**工具选择**：
- PyMuPDF (fitz)：提取文本、表格、图片
- pdfplumber：表格结构精确提取
- camelot：复杂表格解析

### 2.3 扫描版PDF处理

**识别流程**：OCR识别 + 版面还原

**关键技术**：
- OCR引擎：PaddleOCR（中文优化）
- 版面分析：基于深度学习的版面检测模型
- 公式识别：LaTeX格式输出（MathPix / LaTeX-OCR）
- 表格重建：单元格合并检测 + 行列对齐

**输出格式**：统一为结构化Markdown

```markdown
# 5.2.1 插头额定值

根据 GB 1002-2024 第 5.2.1 条规定：

插头的额定电流应符合以下要求：
- 16A 及以下插头：温升不超过50K
- 20A 及以上插头：温升不超过60K

$$
I_{max} = K \times \frac{S}{\rho \times L}
$$

其中：$I_{max}$ 为最大电流（A），$S$ 为导体截面积（mm²），$\rho$ 为电阻率。
```

## 三、智能分块策略

### 3.1 父子块混合机制

采用**父子块混合分块**，兼顾召回的广度与上下文的完整度。

| 块类型 | Token粒度 | 作用 | 适用场景 |
|-------|----------|------|---------|
| 父块 | 512~1024 | 向量召回，保证语义完整性 | 章节、知识点组、关联条款组 |
| 子块 | 128~256 | 精确定位，送入LLM生成 | 单条标准条款、单个公式、单个定义 |

**检索流程**：
1. 召回时先命中父块（语义召回）
2. 再定位到对应子块（精确定位）
3. 既避免语义碎片化，又保证答案精准度

### 3.2 国家标准分块规则

#### 规则1：按条款粒度拆分

```python
# 示例：GB 1002-2024
父块：第 5 章「插头和插座的额定值和结构要求」（包含 5.1~5.6 所有条款）
  └─ 子块1：5.1 条「一般要求」
  └─ 子块2：5.2 条「额定电流」
  └─ 子块3：5.3 条「额定电压」
  └─ 子块4：5.4 条「接地触头」
  └─ 子块5：5.5 条「防护等级」
```

#### 规则2：保留完整条款编号

每个子块必须包含：
- 标准号：`GB 1002-2024`
- 条款号：`第 5.2.1 条`
- 条款标题：`插头额定电流要求`
- 条款内容：完整正文 + 表格 + 公式

#### 规则3：引用关联处理

```python
# 当条款引用其他条款时
原文："...应符合本标准第 5.1 条的规定"
处理：
  1. 识别引用：正则匹配条款号
  2. 关联查询：查找 5.1 条的内容
  3. 补充上下文：将引用条款的核心内容追加到父块
  4. 建立链接：元数据中记录引用关系
```

### 3.3 专业书籍分块规则

#### 规则1：按语义知识点分块（模型辅助）

书籍的知识点边界常与标题层级不对齐——一个知识点可能跨多个小节，或一节包含多个独立知识点。纯规则（按标题切分）无法准确定位语义边界，因此采用**「标题初筛 + 嵌入模型语义边界检测 + LLM 边界确认」**：

```python
# 示例：《电力系统分析》
父块：第 2.3 节「潮流计算的牛顿-拉夫逊法」
  └─ 子块1：基本原理（数学推导）
  └─ 子块2：迭代公式（包含雅可比矩阵）
  └─ 子块3：适用条件与收敛性分析
  └─ 子块4：算例演示
```

**处理流程**：
```python
def semantic_chunk(section_text: str) -> List[Chunk]:
    # 1. 标题初筛：按目录层级做粗切分（章 → 节）
    coarse_blocks = split_by_heading(section_text)

    # 2. 语义边界检测：用嵌入模型计算相邻段落的语义相似度，
    #    在相似度显著下降处（语义突变点）设为候选分块边界
    paragraphs = split_paragraphs(coarse_blocks)
    embeddings = embedder.encode_dense(paragraphs)  # bge-large-zh-v1.5
    boundaries = detect_similarity_drops(embeddings, threshold=0.6)

    # 3. LLM 边界确认：仅对相似度处于阈值附近的"不确定边界"
    #    调用 LLM 判断应合并还是切分（大部分边界由第2步确定，LLM调用量小）
    boundaries = llm_confirm_ambiguous_boundaries(paragraphs, boundaries)

    # 4. 公式/图表保护：结合规则2、3，确保语义单元完整不被截断
    return build_chunks(paragraphs, boundaries)
```

#### 规则2：公式完整性保护

**禁止截断公式**：
- 检测公式边界：`$$...$$` 或 `\begin{equation}...\end{equation}`
- 强制整体成块：公式 + 前后解释文字
- 保留公式编号：`(2.3-1)`

#### 规则3：图表绑定

```python
# 图表处理
原文：
  "图 2.5 展示了不同负荷下的电压分布曲线。
   从图中可以看出..."

处理：
  1. 提取图片：保存为独立文件
  2. OCR图片中的文字标注
  3. 绑定说明：图片 + 前后文字说明成块
  4. 图文索引：建立图片内容的文本索引
```

### 3.4 语义分块模型选型

语义分块的核心是判断"相邻文本是否属于同一知识点"，本质是语义相似度问题，**优先复用已有嵌入模型，避免引入新依赖**：

| 环节 | 模型 | 说明 |
|------|------|------|
| 语义边界检测（主） | **bge-large-zh-v1.5**（已有） | 计算相邻段落余弦相似度，相似度骤降点即语义边界（Semantic Chunking / Text Tiling 思路），无额外模型 |
| 边界确认（辅） | 豆包Pro / 通义千问（API） | 仅对相似度接近阈值的少量"不确定边界"调用，判断合并/切分，调用量可控 |
| 公式/图表完整性 | 规则（正则） | 见规则2、3，公式边界确定性强，规则即可 |

**推荐**：主用 bge-large-zh-v1.5 做语义边界检测（离线批处理，复用入库时已加载的嵌入模型），LLM 仅兜底不确定边界。国家标准因结构严谨（章-节-条-款），仍以条款规则切分为主，无需语义检测；语义分块主要用于结构松散的专业书籍。

### 4.2 元数据提取流程

**设计原则**：结构化字段用规则（格式固定、准确率高、零成本），语义字段用模型（规则易漏判/误判）。

```python
def extract_metadata(doc_content: str, doc_info: dict) -> dict:
    """
    元数据提取流程

    1. 正则匹配（确定性字段）：标准号、条款号、日期、电压等级
    2. LLM 多标签分类（语义字段）：专业分类、知识类型
    3. LLM 增强：关键词、摘要、重要性评分
    4. 数据库查询：引用关系、替代关系
    """
    metadata = {}

    # 1. 正则匹配（结构化字段，格式固定，准确率接近100%）
    metadata["standard_no"] = extract_standard_no(doc_content)   # GB 1002-2024
    metadata["clause"] = extract_clause(doc_content)             # 5.2.1
    metadata["publish_date"] = extract_date(doc_content)
    metadata["voltage_level"] = extract_voltage_level(doc_content)  # 枚举有限，正则可穷举

    # 2. LLM 多标签分类（语义字段，一个文档可能跨多个专业领域）
    #    规则按关键词匹配会漏判（跨分类）和误判，改用 LLM few-shot 多标签分类
    classification = llm_classify_multilabel(
        doc_content,
        labels=["配电", "变电", "继保", "高压", "输电", "防雷", "接地"]
    )
    metadata["category"] = classification["primary"]       # 主分类
    metadata["sub_categories"] = classification["all"]     # 全部相关分类（多标签）
    metadata["knowledge_type"] = classification["type"]    # 规范/原理/参数/流程

    # 3. LLM 增强（纯语义任务）
    metadata["keywords"] = llm_extract_keywords(doc_content)
    metadata["importance_score"] = llm_score_importance(doc_content)

    # 4. 数据库关联
    metadata["citation_count"] = db.get_citation_count(metadata["standard_no"])

    return metadata
```

### 4.3 分类模型选型

专业分类是**多标签语义任务**（一个条款可能同时属于"配电"和"防雷"），不适合用关键词规则。知识加工是**离线批处理**，延迟不敏感、成本敏感、准确率优先，据此选型：

| 阶段 | 方案 | 模型 | 理由 |
|------|------|------|------|
| MVP（首选） | LLM few-shot 多标签分类 | 豆包Pro / 通义千问Turbo（API） | 无需标注数据即可上线；离线批量调用（50条/批）摊薄成本 |
| 进阶（降本） | 嵌入 + 轻量分类头 | **bge-large-zh-v1.5**（已有）+ MLP/逻辑回归多标签头 | 复用现有嵌入模型，零新增依赖；用 LLM 阶段积累的标注做训练数据 |
| 可选（更高精度） | 微调预训练分类器 | chinese-roberta-wwm-ext / ERNIE 3.0 | 数据量充足时，多标签分类准确率更高，但引入新模型依赖 |

**推荐路径**：MVP 用豆包Pro 批量分类并落库标注 → 积累 2000+ 样本后训练"bge 编码 + 分类头"的轻量方案，把这一环节的 LLM 调用成本降到接近零。规则仅用于分类结果的快速校验（如"标准号含 GB 1002 → 必含电气安全标签"）。

## 五、术语增强

### 5.1 术语标准化

**目标**：消除行业黑话和口语化表达，统一为标准术语。

**映射规则**：

| 原始术语 | 标准术语 | 别名 |
|---------|---------|------|
| 刀闸 | 隔离开关 | 刀闸、隔离刀闸 |
| PT | 电压互感器 | PT、电压互感器、VT |
| CT | 电流互感器 | CT、电流互感器、TA |
| 避雷针 | 接闪杆 | 避雷针、避雷器 |
| 10千伏 | 10kV | 10千伏、10KV、10kv |

**实现方式**：
```python
# 术语词典（存储在 MySQL term_dictionary 表）
class TermNormalizer:
    def normalize(self, text: str) -> str:
        """术语标准化"""
        for term in self.term_dict:
            for alias in term.aliases:
                text = text.replace(alias, term.standard_term)
        return text
```

### 5.2 术语扩展（Loop Engineering闭环2）

**场景**：用户使用非标准术语提问，导致召回失败。

**优化方案**：
1. 记录用户自定义输入的新术语
2. 专家审核后加入术语词典
3. 下次查询自动映射

**数据来源**：
- 澄清对话日志（`clarification_logs` 表）
- 用户反馈（召回失败的badcase）

## 六、向量化与索引

### 6.1 双向量机制

每个父块生成两个向量：

#### 稠密向量（Semantic Embedding）

- **模型**：bge-large-zh-v1.5
- **维度**：1024维
- **用途**：语义相似度检索
- **归一化**：L2归一化，便于余弦相似度计算

```python
from sentence_transformers import SentenceTransformer

model = SentenceTransformer('BAAI/bge-large-zh-v1.5')
dense_vector = model.encode(chunk_text, normalize_embeddings=True)
```

#### 稀疏向量（Keyword-based Sparse Embedding）

- **模型**：BM42 / SPLADE
- **格式**：`{token_id: weight}` 稀疏字典
- **用途**：精确关键词匹配
- **优势**：对术语、标准号、参数等精确匹配效果好

```python
from transformers import AutoModelForMaskedLM, AutoTokenizer

model = AutoModelForMaskedLM.from_pretrained('naver/efficient-splade-VI-BT-large-query')
tokenizer = AutoTokenizer.from_pretrained('naver/efficient-splade-VI-BT-large-query')

# 生成稀疏向量
inputs = tokenizer(chunk_text, return_tensors='pt')
outputs = model(**inputs)
sparse_vector = get_sparse_representation(outputs)  # {token_id: weight}
```

### 6.2 向量化参数配置

```python
# 配置
EMBEDDING_CONFIG = {
    "dense": {
        "model": "BAAI/bge-large-zh-v1.5",
        "dim": 1024,
        "batch_size": 32,
        "normalize": True
    },
    "sparse": {
        "model": "naver/efficient-splade-VI-BT-large-query",
        "top_k": 128,  # 只保留top-K个最高权重的token
        "normalize": False
    }
}
```

### 7.1 Airflow DAG 设计

```python

from airflow.operators.python import PythonOperator
from datetime import datetime, timedelta

dag = DAG(

# 依赖关系
t1 >> t2 >> t3 >> t4 >> t5
```

### 7.3 版本管理

**场景**：标准更新替代旧版本

**处理策略**：
1. 检查 `replaced_by` 字段
2. 将旧版本 `status` 改为 `expired`
3. 新版本 `status` 设为 `valid`
4. 保留旧版本向量，但降低权重
5. 在检索结果中标注版本状态

## 九、性能优化

- PDF解析：多进程并行
- 向量化：GPU批处理（batch_size=32）
- 索引写入：批量写入（batch_size=100）

### 9.2 缓存策略

- 模型加载缓存（单例模式）
- 术语词典缓存（Redis）
- 向量化结果缓存（相同文本不重复计算）
