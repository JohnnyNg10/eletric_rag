# 知识加工层 (Knowledge Processing Layer)

本文档详细描述知识加工层的设计与实现，涵盖文档解析、智能分块、元数据处理、术语增强等核心环节。

**核心理念**：70%的RAG效果来自数据质量，知识加工层是命中率的基础。

---

## 一、架构概览

### 1.1 定位与职责

知识加工层位于数据流水线的**前端处理阶段**，负责将原始PDF文档转换为结构化、可检索的知识单元。

```
原始PDF文档
    ↓
文档解析（PDF → Markdown）
    ↓
智能分块（父子块混合）
    ↓
术语增强（标准化 + 扩展）
    ↓
元数据挂载（分类 + 权重）
    ↓
向量化（稠密 + 稀疏）
    ↓
索引存储（三库协同）
```

### 1.2 两类数据源的差异化处理

#### 国家标准类文档（GB/GB/T/DL/NB）

**结构特点**：
- 层级严谨：章-节-条-款-项
- 条款独立性强
- 引用关系多
- 版本更替频繁
- 附表附录多

**处理策略**：
1. 结构化提取：标准号、版本号、发布日期、实施日期、替代关系
2. 按**条款粒度**拆分：单条独立成块，保留完整条款编号
3. 引用关联：自动关联引用的其他条款，形成关联块组
4. 附录处理：表格、参数表单独成块，保留表格结构与表头

#### 电力专业书籍类文档

**结构特点**：
- 章节体系清晰
- 原理推导多
- 公式密集
- 图表配套
- 知识点连贯性强

**处理策略**：
1. 按目录层级提取章节结构
2. 按**语义知识点**分块：公式+推导+适用条件整体成块
3. 图表绑定：图表与对应文字说明绑定成块
4. 核心标记：定义、定理、结论做标记加权

## 二、文档解析流水线

### 2.1 解析流程

```
原始PDF → 版面分析 → 文本提取 → 公式识别 → 表格还原 → 结构重建 → 清洗归一
```

### 2.2 文字版PDF处理

**优先策略**：提取原生文本与排版结构

**保留信息**：
- 标题层级（H1~H6）
- 列表结构（有序/无序）
- 表格边框与单元格对齐
- 字体加粗、斜体等样式标记

**工具选择**：
- PyMuPDF (fitz)：提取文本、表格、图片
- pdfplumber：表格结构精确提取
- camelot：复杂表格解析

### 2.3 扫描版PDF处理

**识别流程**：OCR识别 + 版面还原

**关键技术**：
- OCR引擎：PaddleOCR（中文优化）
- 版面分析：基于深度学习的版面检测模型
- 公式识别：LaTeX格式输出（MathPix / LaTeX-OCR）
- 表格重建：单元格合并检测 + 行列对齐

**输出格式**：统一为结构化Markdown

```markdown
# 3.2.1 配电室安全距离要求

根据 GB 50057-2010 第 4.3.2 条规定：

10kV 配电室的最小安全距离应符合以下要求：
- 带电部分至接地部分：≥125mm
- 带电部分至其他带电部分：≥125mm

$$
D_{min} = K \times \frac{U_m}{\sqrt{3}}
$$

其中：$D_{min}$ 为最小电气间隙（mm），$U_m$ 为设备最高电压（kV）。
```

## 三、智能分块策略

### 3.1 父子块混合机制

采用**父子块混合分块**，兼顾召回的广度与上下文的完整度。

| 块类型 | Token粒度 | 作用 | 适用场景 |
|-------|----------|------|---------|
| 父块 | 512~1024 | 向量召回，保证语义完整性 | 章节、知识点组、关联条款组 |
| 子块 | 128~256 | 精确定位，送入LLM生成 | 单条标准条款、单个公式、单个定义 |

**检索流程**：
1. 召回时先命中父块（语义召回）
2. 再定位到对应子块（精确定位）
3. 既避免语义碎片化，又保证答案精准度

### 3.2 国家标准分块规则

#### 规则1：按条款粒度拆分

```python
# 示例：GB 50057-2010
父块：第 4.3 节「配电室安全距离」（包含 4.3.1~4.3.5 所有条款）
  └─ 子块1：4.3.1 条「一般规定」
  └─ 子块2：4.3.2 条「10kV 配电室」
  └─ 子块3：4.3.3 条「35kV 配电室」
  └─ 子块4：4.3.4 条「特殊场所」
  └─ 子块5：4.3.5 条「防护措施」
```

#### 规则2：保留完整条款编号

每个子块必须包含：
- 标准号：`GB 50057-2010`
- 条款号：`第 4.3.2 条`
- 条款标题：`10kV 配电室安全距离要求`
- 条款内容：完整正文 + 表格 + 公式

#### 规则3：引用关联处理

```python
# 当条款引用其他条款时
原文："...应符合本标准第 3.2.1 条的规定"
处理：
  1. 识别引用：正则匹配条款号
  2. 关联查询：查找 3.2.1 条的内容
  3. 补充上下文：将引用条款的核心内容追加到父块
  4. 建立链接：元数据中记录引用关系
```

### 3.3 专业书籍分块规则

#### 规则1：按语义知识点分块

```python
# 示例：《电力系统分析》
父块：第 2.3 节「潮流计算的牛顿-拉夫逊法」
  └─ 子块1：基本原理（数学推导）
  └─ 子块2：迭代公式（包含雅可比矩阵）
  └─ 子块3：适用条件与收敛性分析
  └─ 子块4：算例演示
```

#### 规则2：公式完整性保护

**禁止截断公式**：
- 检测公式边界：`$$...$$` 或 `\begin{equation}...\end{equation}`
- 强制整体成块：公式 + 前后解释文字
- 保留公式编号：`(2.3-1)`

#### 规则3：图表绑定

```python
# 图表处理
原文：
  "图 2.5 展示了不同负荷下的电压分布曲线。
   从图中可以看出..."

处理：
  1. 提取图片：保存为独立文件
  2. OCR图片中的文字标注
  3. 绑定说明：图片 + 前后文字说明成块
  4. 图文索引：建立图片内容的文本索引
```

## 四、元数据体系设计

### 4.1 元数据字段定义

每个文档块挂载以下元数据，支持检索时的前置过滤。

#### 基础属性

```json
{
  "doc_id": "doc_12345",
  "doc_title": "建筑物防雷设计规范",
  "standard_no": "GB 50057-2010",
  "isbn": null,
  "publish_org": "中华人民共和国住房和城乡建设部",
  "version": "2010版",
  "publish_date": "2010-04-01",
  "implement_date": "2010-10-01",
  "status": "valid",
  "replaced_by": null,
  "replaces": "GB 50057-1994"
}
```

#### 分类属性

```json
{
  "doc_type": "standard",
  "category": "防雷",
  "sub_category": "建筑防雷",
  "voltage_level": "10kV",
  "knowledge_type": "规范",
  "keywords": ["防雷", "接地", "避雷针", "配电室"]
}
```

#### 位置属性

```json
{
  "page_number": 23,
  "chapter": "第 4 章",
  "section": "4.3 节",
  "clause_number": "4.3.2",
  "clause_title": "配电室安全距离要求"
}
```

#### 权重属性

```json
{
  "authority_level": "national_standard",
  "citation_count": 156,
  "importance_score": 0.92
}
```

### 4.2 元数据提取流程

```python
def extract_metadata(doc_content: str, doc_info: dict) -> dict:
    """
    元数据提取流程
    
    1. 正则匹配：标准号、条款号、日期
    2. 规则引擎：分类、电压等级、设备类型
    3. LLM增强：关键词、摘要、重要性评分
    4. 数据库查询：引用关系、替代关系
    """
    metadata = {}
    
    # 1. 正则匹配（高准确率）
    metadata["standard_no"] = extract_standard_no(doc_content)
    metadata["clause_number"] = extract_clause_number(doc_content)
    metadata["publish_date"] = extract_date(doc_content)
    
    # 2. 规则引擎（基于专家知识）
    metadata["voltage_level"] = classify_voltage_level(doc_content)
    metadata["category"] = classify_by_rules(doc_content)
    
    # 3. LLM增强（处理边界情况）
    if not metadata["category"]:
        metadata["category"] = llm_classify(doc_content)
    
    metadata["keywords"] = llm_extract_keywords(doc_content)
    metadata["importance_score"] = llm_score_importance(doc_content)
    
    # 4. 数据库关联
    metadata["citation_count"] = db.get_citation_count(metadata["standard_no"])
    
    return metadata
```

## 五、术语增强

### 5.1 术语标准化

**目标**：消除行业黑话和口语化表达，统一为标准术语。

**映射规则**：

| 原始术语 | 标准术语 | 别名 |
|---------|---------|------|
| 刀闸 | 隔离开关 | 刀闸、隔离刀闸 |
| PT | 电压互感器 | PT、电压互感器、VT |
| CT | 电流互感器 | CT、电流互感器、TA |
| 避雷针 | 接闪杆 | 避雷针、避雷器 |
| 10千伏 | 10kV | 10千伏、10KV、10kv |

**实现方式**：
```python
# 术语词典（存储在 MySQL term_dictionary 表）
class TermNormalizer:
    def normalize(self, text: str) -> str:
        """术语标准化"""
        for term in self.term_dict:
            for alias in term.aliases:
                text = text.replace(alias, term.standard_term)
        return text
```

### 5.2 术语扩展（Loop Engineering闭环2）

**场景**：用户使用非标准术语提问，导致召回失败。

**优化方案**：
1. 记录用户自定义输入的新术语
2. 专家审核后加入术语词典
3. 下次查询自动映射

**数据来源**：
- 澄清对话日志（`clarification_logs` 表）
- 用户反馈（召回失败的badcase）

## 六、向量化与索引

### 6.1 双向量机制

每个父块生成两个向量：

#### 稠密向量（Semantic Embedding）

- **模型**：bge-large-zh-v1.5
- **维度**：1024维
- **用途**：语义相似度检索
- **归一化**：L2归一化，便于余弦相似度计算

```python
from sentence_transformers import SentenceTransformer

model = SentenceTransformer('BAAI/bge-large-zh-v1.5')
dense_vector = model.encode(chunk_text, normalize_embeddings=True)
```

#### 稀疏向量（Keyword-based Sparse Embedding）

- **模型**：BM42 / SPLADE
- **格式**：`{token_id: weight}` 稀疏字典
- **用途**：精确关键词匹配
- **优势**：对术语、标准号、参数等精确匹配效果好

```python
from transformers import AutoModelForMaskedLM, AutoTokenizer

model = AutoModelForMaskedLM.from_pretrained('naver/efficient-splade-VI-BT-large-query')
tokenizer = AutoTokenizer.from_pretrained('naver/efficient-splade-VI-BT-large-query')

# 生成稀疏向量
inputs = tokenizer(chunk_text, return_tensors='pt')
outputs = model(**inputs)
sparse_vector = get_sparse_representation(outputs)  # {token_id: weight}
```

### 6.2 向量化参数配置

```python
# 配置
EMBEDDING_CONFIG = {
    "dense": {
        "model": "BAAI/bge-large-zh-v1.5",
        "dim": 1024,
        "batch_size": 32,
        "normalize": True
    },
    "sparse": {
        "model": "naver/efficient-splade-VI-BT-large-query",
        "top_k": 128,  # 只保留top-K个最高权重的token
        "normalize": False
    }
}
```

## 七、数据处理流水线实现

### 7.1 Airflow DAG 设计

```python
from airflow import DAG
from airflow.operators.python import PythonOperator
from datetime import datetime, timedelta

dag = DAG(
    'document_ingestion_pipeline',
    default_args={
        'owner': 'data_team',
        'retries': 2,
        'retry_delay': timedelta(minutes=5),
    },
    description='文档入库处理流水线',
    schedule_interval='@daily',
    start_date=datetime(2026, 1, 1),
    catchup=False,
)

# 任务定义
t1 = PythonOperator(task_id='parse_pdf', python_callable=parse_pdf_task, dag=dag)
t2 = PythonOperator(task_id='chunk_documents', python_callable=chunk_task, dag=dag)
t3 = PythonOperator(task_id='extract_metadata', python_callable=metadata_task, dag=dag)
t4 = PythonOperator(task_id='generate_embeddings', python_callable=embedding_task, dag=dag)
t5 = PythonOperator(task_id='index_to_stores', python_callable=index_task, dag=dag)

# 依赖关系
t1 >> t2 >> t3 >> t4 >> t5
```

### 7.2 批处理与增量更新

**批量入库**（初次导入）：
```bash
# 全量处理所有PDF
airflow dags trigger document_ingestion_pipeline \
  --conf '{"mode": "batch", "input_dir": "/data/pdfs/"}'
```

**增量更新**（新标准发布）：
```bash
# 单个文档处理
airflow dags trigger document_ingestion_pipeline \
  --conf '{"mode": "incremental", "file": "GB_50057-2024.pdf"}'
```

### 7.3 版本管理

**场景**：标准更新替代旧版本

**处理策略**：
1. 检查 `replaced_by` 字段
2. 将旧版本 `status` 改为 `expired`
3. 新版本 `status` 设为 `valid`
4. 保留旧版本向量，但降低权重
5. 在检索结果中标注版本状态

## 八、质量保障

### 8.1 数据质量检查

**自动化检查项**：
- PDF解析完整性（页数一致性）
- 表格结构完整性（行列对齐）
- 公式识别准确性（LaTeX语法检查）
- 元数据完整性（必填字段非空）
- 分块长度合规（128~1024 token）

### 8.2 人工抽检

**抽检比例**：10%
**抽检内容**：
- 条款拆分准确性
- 引用关联正确性
- 元数据标注准确性
- 术语标准化效果
