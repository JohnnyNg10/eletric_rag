# 业务流程图

## 一、核心业务流程

### 1.1 用户查询流程（主流程）

```mermaid
graph TD
    A[用户输入查询] --> B[术语标准化]
    B --> C[提问优化判断]
    C --> D{是否需要澄清?}
    D -->|否| E[复杂度路由]
    D -->|是-suggest| F[显示智能补全]
    D -->|是-clarify| G[显示澄清对话]
    F --> H[用户选择/跳过]
    G --> H
    H --> E
    E --> I{路由到哪个车道?}
    I -->|快车道 90%| PRE[元数据提取 + 查询扩展]
    I -->|慢车道 10%| K[工具调用循环]
    PRE --> J[三路召回]
    J --> L[两阶段重排]
    L --> M{召回充分?}
    M -->|是| N[LLM生成答案]
    M -->|否| O[查询改写 + 二次检索]
    O --> N
    K --> P[多步检索聚合]
    P --> N
    N --> Q[引用溯源]
    Q --> R[事实一致性校验]
    R --> S[返回结果给用户]
```

### 1.2 快车道详细流程

```mermaid
sequenceDiagram
    participant User as 用户
    participant API as API服务
    participant Router as 路由器
    participant FastLane as 快车道
    participant VectorDB as Qdrant
    participant ES as Elasticsearch
    participant MySQL as MySQL
    participant Reranker as 重排器
    participant LLM as 生成模型

    User->>API: 发起查询
    API->>Router: 查询预处理
    Router->>FastLane: 路由到快车道
    
    FastLane->>FastLane: 元数据提取（电压/标准号/分类）
    FastLane->>FastLane: 查询扩展（多Query/HyDE，最多3个）
    
    par 三路并行召回
        FastLane->>VectorDB: 向量召回 Top20（含元数据过滤）
        FastLane->>ES: 关键词召回 Top20
        FastLane->>MySQL: 结构化召回 Top10
    end
    
    VectorDB-->>FastLane: 返回结果
    ES-->>FastLane: 返回结果
    MySQL-->>FastLane: 返回结果
    
    FastLane->>FastLane: 合并去重
    FastLane->>Reranker: 粗排 Top50→Top20
    FastLane->>Reranker: 精排 Top20→Top5
    
    FastLane->>FastLane: 召回充分性判断
    
    alt 召回充分
        FastLane->>LLM: 生成答案
    else 召回不充分
        FastLane->>FastLane: 改写查询
        FastLane->>VectorDB: 二次召回
        FastLane->>LLM: 生成答案
    end
    
    LLM-->>FastLane: 返回答案
    FastLane->>FastLane: 提取引用
    FastLane-->>API: 返回结果
    API-->>User: 展示答案
```

### 1.3 慢车道流程（多跳推理）

```mermaid
graph TD
    A[慢车道入口] --> B[步骤1: 模型决策]
    B --> C{需要继续检索?}
    C -->|是| D[选择检索工具]
    D --> D1[retrieve_standard<br/>标准检索]
    D --> D2[retrieve_clause<br/>条款精确定位]
    D --> D3[list_related_standards<br/>相关标准清单]
    D1 --> E[获取结果]
    D2 --> E
    D3 --> E
    E --> F{达到步数上限3步?}
    F -->|否| B
    F -->|是| G[聚合所有结果]
    C -->|否-信息充分| G
    G --> H[LLM生成答案<br/>附推理链路]
    H --> I[返回结果]
```

**工具说明**：
- `retrieve_standard`：调用快车道三路召回（可指定标准号过滤）
- `retrieve_clause`：精确定位某标准某条款（查MySQL元数据库）
- `list_related_standards`：返回含某关键词的相关标准清单

**控制约束**：步数≤3，单步超时2s，总延迟预算8s，独立限流QPS=10

```mermaid
graph TD
```

## 四、Loop Engineering闭环流程

### 4.1 周优化循环（5大闭环）

```mermaid
graph LR
    A[每周定时触发<br/>Airflow DAG] --> B[数据采集<br/>日志/反馈]
    B --> C[问题诊断]
    C --> D[闭环1: Prompt优化]
    C --> E[闭环2: 术语库扩展]
    C --> F[闭环3: 难例分析]
    C --> T[闭环4: 测试集扩充]
    D --> G[闭环5: A/B测试]
    E --> G
    F --> G
    T --> G
    G --> H{效果验证}
    H -->|显著提升 >5%| I[自动全量上线]
    H -->|无显著差异 2-5%| J[人工决策]
    H -->|效果变差| K[自动回滚]
    I --> L[更新监控指标]
    J --> L
    K --> L
    L --> M[生成周报]
```

**5大闭环说明**：
| 闭环 | 目标 | 自动化策略 |
|------|------|-----------|
| 闭环1 Prompt优化 | 降低笼统度误判率 | 置信度>0.7自动注入Few-shot |
| 闭环2 术语库扩展 | 挖掘新术语/俗称 | 频次≥5自动加入，≤2自动丢弃 |
| 闭环3 难例分析 | 定位召回失败根因 | 分块/嵌入/重排/缺失分类 |
| 闭环4 测试集扩充 | 防止效果退化 | 用户好评样本自动加入 |
| 闭环5 A/B决策 | 加速迭代 | 显著差异自动全量/下线 |

**数据依赖**：`query_logs`（笼统度、策略、二次检索）、`clarification_logs`（用户选择、自定义输入）、`badcase_tracking`（难例根因）

## 五、关键时序图

### 5.1 流式输出时序

```mermaid
sequenceDiagram
    participant Client as 前端
    participant WS as WebSocket
    participant API as 后端API
    participant LLM as 生成模型

    Client->>WS: 建立连接
    Client->>WS: 发送查询
    WS->>API: 转发查询
    API->>API: 检索相关文档
    API->>LLM: 流式生成请求
    
    loop 流式返回
        LLM-->>API: 返回token片段
        API-->>WS: 推送chunk
        WS-->>Client: 实时显示
    end
    
    LLM-->>API: 生成完成
    API->>API: 提取引用
    API-->>WS: 推送citations
    WS-->>Client: 显示引用来源
    API-->>WS: 推送done
    WS-->>Client: 结束标记
```

### 5.2 文档上传与处理

```mermaid
sequenceDiagram
    participant User as 用户
    participant Frontend as 前端
    participant API as 后端API
    participant MinIO as 对象存储
    participant Celery as 任务队列
    participant Worker as 异步Worker
    participant Airflow as 流水线

    User->>Frontend: 上传PDF
    Frontend->>API: POST /documents/upload
    API->>MinIO: 存储原始文件
    MinIO-->>API: 返回文件路径
    API->>Celery: 创建处理任务
    Celery-->>API: 返回task_id
    API-->>Frontend: 返回task_id
    Frontend->>Frontend: 轮询任务状态

    Worker->>Airflow: 触发DAG
    Airflow->>Airflow: PDF解析
    Airflow->>Airflow: 智能分块
    Airflow->>Airflow: 向量化
    Airflow->>Airflow: 入库索引
    Airflow-->>Worker: 执行完成
    Worker-->>Celery: 更新任务状态
    
    Frontend->>API: GET /tasks/{task_id}
    API->>Celery: 查询任务状态
    Celery-->>API: 返回SUCCESS
    API-->>Frontend: 返回结果
```

```
       ↓
┌──────────────────────────────┐

       ↓
```
