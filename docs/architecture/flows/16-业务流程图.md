# 业务流程图

## 零、系统全貌（简练版）

```mermaid
graph LR
    A[用户输入] --> B[术语标准化<br/>笼统度评估]
    B --> C{澄清?}
    C -->|是| D[展示澄清选项]
    C -->|否| E[路由决策]
    D -->|确认| E

    E -->|快车道| G[查询扩展<br/>+ HyDE]
    E -->|慢车道| L[LLM工具调用<br/>最多3步]

    G --> H[三路并行召回<br/>向量·关键词·结构化]
    H --> I[两阶段重排<br/>粗排→精排]
    I --> J{召回充分?}
    J -->|否| K[二次检索<br/>跨标准引用]
    K --> I
    J -->|是| M

    L --> M[LLM生成答案]
    M --> N[引用溯源]
    N --> O[返回用户]


```

**系统特点**：
- 预处理：术语标准化 → 笼统度评估（0-1分）→ 可选澄清
- 快车道（90%）：适用于单一/明确查询，三路召回 + 重排 + 可选二次检索
- 慢车道（10%）：适用于对比/多跳查询，LLM 决策工具调用（retrieve_standard/clause/list）
- 缓存加速：L1 Embedding(24h) / L2 召回(6h) / L3 重排(4h) / L4 生成(2h)

## 一、核心业务流程

### 1.1 用户查询流程（主流程 - 阶段B）

```mermaid
graph TD
    A[用户输入查询] --> HIST[加载对话历史<br/>query_log_repo.get_conversation_history]
    HIST --> COREF{有历史 &<br/>非澄清查询?}
    COREF -->|是| CR[指代消解<br/>CoreferenceResolver.resolve]
    COREF -->|否| B
    CR --> B[术语标准化]
    B --> C[笼统度评估 + 路由判断<br/>一体化LLM调用]
    C --> D[返回预处理结果<br/>含澄清选项 + 路由建议]
    D --> E[前端展示确认面板]
    E --> F{用户操作}
    F -->|选择澄清选项| G[refined_query]
    F -->|修改路由| H[user_lane覆盖]
    F -->|直接提交| I[使用原查询 + 系统路由]
    G --> J[第二次请求：执行查询]
    H --> J
    I --> J
    J --> K{实际路由决策}
    K -->|快车道| DECOMP[查询拆解<br/>is_multi_aspect → sub_queries]
    K -->|慢车道| L[工具调用循环]
    DECOMP --> PRE[元数据提取 + 查询扩展<br/>HyDE 并行生成]
    PRE --> M[三路并行召回<br/>低召回时自动放宽过滤条件]
    M --> MD[内容去重<br/>短块/目录页过滤 + 精确去重]
    MD --> N[两阶段重排 Top8<br/>L3缓存 get/set]
    N --> O{充分性判断?}
    O -->|充分| EXP[子块扩展<br/>ChildChunkExpander]
    O -->|不充分| Q[缺口分析<br/>提取被引用标准号]
    Q --> Q1[缺口查询改写 LLM + 三路二次召回]
    Q --> Q2[被引用标准精确召回<br/>顺序 for 循环]
    Q1 --> Q3[合并去重 + 重新精排 Top10<br/>⚠ 当前绕过 L3 缓存]
    Q2 --> Q3
    Q3 --> O2[二次充分性判断]
    O2 --> EXP
    EXP --> P[LLM生成答案<br/>L4缓存 get/set]
    L --> R[多步检索聚合]
    R --> P
    P --> S[引用溯源 CitationExtractor]
    S --> T[事实一致性校验]
    T --> U[返回结果给用户]
    U --> V[记录数据飞轮<br/>predicted_lane / user_lane / lane]
```

**当前实现关键点**：
1. 多轮对话：`execute_query` 首先加载历史（`MAX_HISTORY_TURNS`），有历史时调用 `CoreferenceResolver` 消解指代
2. 澄清查询（`refined_query` 非空）跳过笼统度评估，仅做术语标准化
3. 路由：关键词规则（`Router`） + 用户覆盖（`user_lane`），`predicted_lane` 来自预处理 LLM 建议
4. 查询拆解：`is_multi_aspect_query` 为真且非对比查询时才拆解，快车道仅拆同主题多方面查询
5. HyDE 生成与 QueryRewriter 扩展通过 `asyncio.gather` 并行执行
6. 过滤放宽优先级：`voltage_level → category → doc_type → standard_no`（召回数 < 3 时逐步丢弃）
7. **已知问题**：retry 路径直接调用 `reranker.rerank()` 未走 L3 缓存，导致重复重排（参见 `24-快车道延迟诊断报告.md`）
8. 数据飞轮记录三个字段：`predicted_lane`（LLM建议）、`user_lane`（用户覆盖）、`lane`（最终执行）

### 1.2 阶段B两次请求流程（序列图）

```mermaid
sequenceDiagram
    participant User as 用户
    participant Frontend as 前端
    participant API as API服务
    participant Preprocessor as 预处理层
    participant CorefResolver as 指代消解
    participant LLM as 豆包Pro
    participant Router as 路由层
    participant FastLane as 快车道
    participant SlowLane as 慢车道
    participant Generator as 生成层

    Note over User,Generator: 第一次请求：预处理 + 路由建议
    User->>Frontend: 输入查询
    Frontend->>API: POST /query/preprocess
    API->>Preprocessor: 术语标准化
    Preprocessor->>LLM: 一体化调用<br/>评估笼统度 + 识别缺失维度 + 路由判断
    LLM-->>Preprocessor: vagueness_score / missing_dimensions<br/>options / lane_suggestion / lane_reason
    Preprocessor-->>API: PreprocessingOutput
    API-->>Frontend: HTTP 200 + 预处理结果
    Frontend->>Frontend: 展示确认面板<br/>路由建议 + 澄清选项
    
    Note over User,Generator: 用户确认阶段
    User->>Frontend: 选择澄清选项 / 修改路由 / 直接提交
    
    Note over User,Generator: 第二次请求：执行查询
    Frontend->>API: POST /query<br/>携带 refined_query / user_lane / conversation_id
    
    Note over API,CorefResolver: 多轮对话处理（有 conversation_id 时）
    API->>API: 加载对话历史<br/>query_log_repo.get_conversation_history
    alt 有历史 & 非澄清查询
        API->>CorefResolver: resolve(query, conversation_history)
        CorefResolver-->>API: resolved_query（消解后的查询）
    end
    
    API->>Preprocessor: 术语标准化（仅）
    Preprocessor-->>API: optimized_query
    
    alt user_lane 存在
        API->>API: 使用 user_lane 覆盖系统路由
    else 使用系统路由
        API->>Router: route(optimized_query)
        Router-->>API: lane = fast/slow
    end
    
    alt 快车道
        API->>FastLane: execute(optimized_query, strategy_params)
        Note over FastLane: 查询拆解 → 元数据提取<br/>QueryRewriter + HyDE 并行扩展<br/>三路召回 + 过滤放宽<br/>两阶段重排（L3缓存）<br/>充分性判断 → 可选二次检索<br/>子块扩展（ChildChunkExpander）
        FastLane-->>API: FastLaneResult
    else 慢车道
        API->>SlowLane: execute(optimized_query, strategy_params)
        SlowLane-->>API: SlowLaneResult
    end
    
    API->>Generator: generate(query, chunks, history=conversation_history)
    Generator-->>API: answer + citations
    API->>API: 记录数据飞轮<br/>predicted_lane / user_lane / lane
    API-->>Frontend: QueryResponse
    Frontend-->>User: 显示答案
```

**关键时序**：
1. **第一次请求**：仅预处理，返回路由建议（不执行检索）
2. **多轮对话**：第二次请求携带 `conversation_id`，后端自动加载历史并做指代消解（`CoreferenceResolver`）
3. **用户确认**：前端展示面板，用户可修改路由
4. **第二次请求**：携带用户选择，执行实际检索，对话历史也传入生成层
5. **数据飞轮**：每次查询记录 `predicted_lane`、`user_lane`、`lane` 三字段

### 1.3 快车道详细流程（含缓存层）

```mermaid
sequenceDiagram
    participant API as API服务
    participant FastLane as 快车道
    participant LLM_ext as LLM改写
    participant Redis as Redis缓存
    participant Embedder as Embedder
    participant VectorDB as Qdrant
    participant ES as Elasticsearch
    participant MySQL as MySQL
    participant Reranker as 重排器
    participant ChildExp as 子块扩展
    participant LLM as 生成模型

    API->>FastLane: execute(query, strategy_params)

    Note over FastLane: Step 1: 元数据提取
    FastLane->>FastLane: MetadataExtractor.extract()<br/>standard_no / category / voltage_level 等过滤条件

    Note over FastLane: Step 1.5: 查询拆解
    FastLane->>FastLane: is_multi_aspect_query() & !is_comparison_query()?<br/>是 → decompose() 拆为 sub_queries 列表

    Note over FastLane,LLM_ext: Step 2: 查询扩展 + HyDE 并行（asyncio.gather）
    par 并行执行
        FastLane->>FastLane: QueryRewriter.rewrite()<br/>生成 2-3 个扩展变体
    and
        FastLane->>LLM_ext: HyDE: generate(query, category)<br/>（if enable_hyde=True）
        LLM_ext-->>FastLane: hyde_query（假设文档摘要）
    end

    Note over FastLane,Redis: Step 3: 三路召回（含过滤放宽）
    FastLane->>Redis: L2 GET recall:{md5(query|filters|hyde_flag)}
    alt L2 命中
        Redis-->>FastLane: 返回缓存召回结果
    else L2 未命中
        Note over Embedder,Redis: L1 Embedding 缓存（24h TTL）
        FastLane->>Embedder: encode(hyde_query 或 query)
        Embedder->>Redis: GET/SET embedding:dense:{md5(text)} TTL=24h
        Embedder-->>FastLane: query_vector

        par 三路并行召回（初次，带过滤条件）
            FastLane->>VectorDB: 向量召回 Top20（dense+sparse hybrid）
            FastLane->>ES: 关键词召回 Top20（BM25）
            FastLane->>MySQL: 结构化召回 Top10
        end

        alt 召回数 < 3（过滤放宽触发）
            Note over FastLane: 按优先级逐步丢弃过滤条件<br/>voltage_level → category → doc_type → standard_no
            FastLane->>FastLane: 移除一个过滤条件
            FastLane->>VectorDB: 重新三路召回
            FastLane->>ES: 重新三路召回
            FastLane->>MySQL: 重新三路召回
        end

        FastLane->>FastLane: RRF 融合 + 基础去重
        FastLane->>Redis: SET recall:{md5(query|filters|hyde_flag)} TTL=1h
    end

    Note over FastLane: Step 2.5: 精排前去重
    FastLane->>FastLane: _deduplicate_candidates()<br/>过滤短块(< 20字) + 目录页(≥3行页码结构)<br/>精确内容去重 + 高分版本保留

    Note over FastLane,Redis: Step 4: 两阶段重排（首轮）
    FastLane->>Redis: L3 GET rerank:{md5(query|sorted_chunk_ids)}
    alt L3 命中
        Redis-->>FastLane: 返回缓存重排结果 Top8
    else L3 未命中
        FastLane->>Reranker: 粗排（bge-reranker-base）全量→Top20
        FastLane->>Reranker: 精排（bge-reranker-large）Top20→Top8
        FastLane->>Redis: SET rerank:{md5(query|sorted_chunk_ids)} TTL=1h
    end

    Note over FastLane: Step 5: 充分性判断
    FastLane->>FastLane: SufficiencyChecker.check()<br/>规则优先（top分≥0.7且分差≥0.2）<br/>不满足则 LLM 兜底（超时1.5s默认充分）

    alt 召回充分
        Note over FastLane,ChildExp: Step 6: 子块扩展
        FastLane->>ChildExp: expand(parent_chunks, query)
        ChildExp->>MySQL: 查询父块对应子块
        ChildExp-->>FastLane: expanded_results（父块+高相关子块）
        FastLane-->>API: FastLaneResult（Top8 + 子块扩展）
    else 召回不充分（触发二次检索）
        FastLane->>FastLane: ReferenceExtractor<br/>从 gaps + chunks 提取被引用标准号
        FastLane->>LLM_ext: gap 改写：_refine_query_for_gaps()<br/>融合 gaps + 标准号生成 retry_query
        LLM_ext-->>FastLane: retry_query

        FastLane->>FastLane: _multi_path_recall([retry_query], filters)<br/>三路二次召回

        Note over FastLane,MySQL: 被引用标准精确召回（顺序 for 循环）
        loop 每个 standard_no
            FastLane->>MySQL: StructuredRecall.search(filters={standard_no})
            MySQL-->>FastLane: 最多 Top10 chunks/标准
        end

        FastLane->>FastLane: _merge_deduplicate()<br/>合并原召回 + 二次召回（chunk_id去重）
        FastLane->>FastLane: _deduplicate_candidates()<br/>再次内容去重

        Note over FastLane,Reranker: ⚠ retry 路径直接调用 reranker，绕过 L3 缓存
        FastLane->>Reranker: rerank(query, merged_chunks, top_k=10)<br/>粗排→Top20→精排→Top10（无缓存检查）

        FastLane->>FastLane: SufficiencyChecker.check()<br/>二次充分性判断

        Note over FastLane,ChildExp: Step 6: 子块扩展
        FastLane->>ChildExp: expand(parent_chunks, query)
        ChildExp->>MySQL: 查询父块对应子块
        ChildExp-->>FastLane: expanded_results

        FastLane-->>API: FastLaneResult（Top10 + 子块扩展，retry_triggered=True）
    end

    Note over API,LLM: Step 4: 生成（service 层）
    API->>Redis: L4 GET generation:{md5(query|chunks)}
    alt L4 命中
        Redis-->>API: 返回缓存答案 + 引用
    else L4 未命中
        API->>LLM: generate(query, chunks, history=conversation_history)
        LLM-->>API: answer + citations
        API->>Redis: SET generation:{md5(query|chunks)} TTL=12h
    end
    API-->>FastLane 调用方: 最终结果（answer + citations + cache_hit）
```

**缓存层说明**：
| 级别 | Key | TTL | 节省操作 |
|------|-----|-----|---------|
| L4 生成缓存 | `generation:{md5(query\|chunks\|conv_id)}` | 12h | 跳过全部检索+生成 |
| L3 重排缓存 | `rerank:{md5(query\|sorted_ids)}` | 1h | 跳过两阶段重排（**仅首轮走缓存**） |
| L2 召回缓存 | `recall:{md5(query\|filters\|hyde_flag)}` | 1h | 跳过三路并行召回 |
| L1 Embedding 缓存 | `embedding:dense:{md5(text)}` | 24h | 跳过向量化推理 |

**已知问题（`24-快车道延迟诊断报告.md`）**：retry 路径在 `fast_lane.py:240` 直接调用 `reranker.rerank()`，未走 L3 缓存，当 retry 召回到完全相同的 chunk 集合时会导致约 42s 的重复计算。

#### 时序图

```mermaid
sequenceDiagram
    participant API as API服务
    participant SlowLane as 慢车道
    participant LLM_dec as LLM决策
    participant MultiPath as MultiPathRecall
    participant MySQL as MySQL
    participant Reranker as 重排器
    
    API->>SlowLane: execute(query, strategy_params)
    
    Note over SlowLane: 初始化：accumulated_metadata = []
    
    loop 工具调用循环（最多3步，总超时10分钟）
        Note over SlowLane,LLM_dec: Step N: LLM决策下一步
        SlowLane->>LLM_dec: _llm_decide(query, current_chunks, accumulated_metadata)<br/>携带已发现标准清单（list_related_standards结果）
        LLM_dec-->>SlowLane: {"action": "continue", "tool": "工具名", "params": {...}}<br/>或 {"action": "sufficient"}
        
        alt action = sufficient
            SlowLane->>SlowLane: 信息充分，退出循环
        else action = continue
            alt tool = retrieve_standard
                Note over SlowLane,MultiPath: 标准内容语义检索（单步超时2分钟）
                SlowLane->>MultiPath: recall(query, filters={standard_no: [...]})
                MultiPath-->>SlowLane: Top15 chunks
                SlowLane->>SlowLane: 记录 metadata（query, standard_ids）
            else tool = retrieve_clause
                Note over SlowLane,MySQL: 精确条款定位
                SlowLane->>MySQL: SELECT FROM chunks WHERE standard_no=X AND clause=Y
                MySQL-->>SlowLane: 精确匹配的 chunk（score=1.0）
                SlowLane->>SlowLane: 记录 metadata（standard_id, clause_number）
            else tool = list_related_standards
                Note over SlowLane,MySQL: 列出相关标准清单（不返回内容）
                SlowLane->>MySQL: SELECT FROM documents WHERE title CONTAINS keyword
                MySQL-->>SlowLane: 标准清单（standard_no, title, doc_count）
                SlowLane->>SlowLane: 记录到 accumulated_metadata.standards<br/>供下一步 LLM 决策使用
            end
            
            SlowLane->>SlowLane: all_chunks.extend(new_chunks)
            SlowLane->>SlowLane: steps_taken += 1
        end
    end
    
    Note over SlowLane: 信息聚合与去重
    SlowLane->>SlowLane: _aggregate_chunks()<br/>chunk_id去重 + 按score排序 + 限制Top20
    
    Note over SlowLane,Reranker: 两阶段重排（与快车道一致）
    SlowLane->>Reranker: rerank(query, aggregated_chunks, top_k=10)
    Reranker->>Reranker: 粗排（bge-reranker-base）
    Reranker->>Reranker: 精排（bge-reranker-large）
    Reranker-->>SlowLane: Top10 reranked chunks
    
    SlowLane-->>API: SlowLaneResult<br/>status / chunks / reasoning_steps / retrieval_time
```

**工具说明**：
- `retrieve_standard`：标准内容语义检索，调用 `MultiPathRecall` 三路召回（可指定 `standard_ids` 过滤），单步返回 Top15
- `retrieve_clause`：精确条款定位，MySQL 精确查询 `standard_no + clause`，返回单条 chunk（score=1.0）
- `list_related_standards`：列出相关标准清单，仅返回元信息（`standard_no`, `title`, `doc_count`），**不返回 chunks**，结果保存到 `accumulated_metadata` 供下一步 LLM 决策使用

**控制约束**：
- 最大步数：3 步
- 单步超时：2 分钟（包含 LLM 决策 30s + 工具调用 120s）
- 总超时：10 分钟
- LLM 决策超时：30 秒（超时默认 `action=sufficient`）

**关键设计**：
1. **metadata 串联**：`list_related_standards` 的标准清单通过 `accumulated_metadata` 传递给下一步 LLM，辅助 `retrieve_standard` 的 `standard_ids` 参数选择
2. **重排一致性**：慢车道最后使用与快车道相同的两阶段重排器（`bge-reranker-base` → `bge-reranker-large`）
3. **充分性判断**：由 LLM 在每步决策中判断（`action: sufficient`），无独立 `SufficiencyChecker`

### 2.2 智能分块策略（当前实现）

当前分块逻辑（`ingest_markdown.py::chunk_section`）：

```

    ↓

               ↓
```

## 四、Loop Engineering闭环流程

> ⚠️ **规划中·未实现**：以下流程为系统设计目标，当前尚未开发。

### 4.1 周优化循环（5大闭环）

```mermaid
graph LR
    A[每周定时触发<br/>Airflow DAG] --> B[数据采集<br/>日志/反馈]
    B --> C[问题诊断]
    C --> D[闭环1: Prompt优化]
    C --> E[闭环2: 术语库扩展]
    C --> F[闭环3: 难例分析]
    C --> T[闭环4: 测试集扩充]
    D --> G[闭环5: A/B测试]
    E --> G
    F --> G
    T --> G
    G --> H{效果验证}
    H -->|显著提升 >5%| I[自动全量上线]
    H -->|无显著差异 2-5%| J[人工决策]
    H -->|效果变差| K[自动回滚]
    I --> L[更新监控指标]
    J --> L
    K --> L
    L --> M[生成周报]
```

**5大闭环说明**：
| 闭环 | 目标 | 自动化策略 |
|------|------|-----------|
| 闭环1 Prompt优化 | 降低笼统度误判率 | 置信度>0.7自动注入Few-shot |
| 闭环2 术语库扩展 | 挖掘新术语/俗称 | 频次≥5自动加入，≤2自动丢弃 |
| 闭环3 难例分析 | 定位召回失败根因 | 分块/嵌入/重排/缺失分类 |
| 闭环4 测试集扩充 | 防止效果退化 | 用户好评样本自动加入 |
| 闭环5 A/B决策 | 加速迭代 | 显著差异自动全量/下线 |

**数据依赖**：`query_logs`（笼统度、策略、二次检索）、`clarification_logs`（用户选择、自定义输入）、`badcase_tracking`（难例根因）
