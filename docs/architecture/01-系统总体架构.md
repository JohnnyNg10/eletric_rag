# 系统总体架构

## 一、架构概述

本系统是一个**工业级电力专业知识库RAG系统**，面向国家标准和电力专业书籍两类核心数据源，采用前后端分离、微服务化的架构设计，实现高召回准确率、高事实一致性的专业知识问答服务。

### 核心设计理念

1. **分层解耦**：采用七层架构，各层职责清晰，独立部署，弹性扩展
2. **前后端分离**：前端负责交互体验，后端负责业务逻辑和数据处理
3. **快慢双通道**：90%+ 查询走快车道（固定流水线），复杂查询走慢车道（自适应检索）
4. **可观测性优先**：全链路追踪、监控告警、质量评测
5. **持续优化**：Loop Engineering 闭环机制，自动迭代提升

### 量化目标

| 指标 | 目标值 |
|------|--------|
| Top-5 召回准确率 | ≥92% |
| 答案事实一致性 | ≥95% |
| P95 响应时间 | ≤3s |
| 并发支持 (QPS) | ≥50 |
| 服务可用性 | ≥99.9% |

## 三、层次职责说明

### 第一层：业务应用层

**职责**：提供用户交互界面和外部系统接口

**组成部分**：
- **Web前端应用**：基于 React/Vue 的单页应用，提供搜索、问答、历史记录等功能
- **移动端H5**：响应式设计，适配移动设备
- **OpenAPI接口**：RESTful API，供第三方系统集成
- **企业内部系统集成**：与OA、ERP等系统对接

**交互方式**：
- 用户 → 前端 → 后端API（HTTP/HTTPS + WebSocket）
- 第三方系统 → OpenAPI（Token认证）

---

### 第二层：检索生成服务层

**职责**：核心业务逻辑，处理查询请求，协调各子模块完成检索与生成

**核心模块**：

1. **查询预处理模块**
   - 术语归一化（电力术语词典映射）
   - 结构化识别（标准号、条款号、电压等级提取）
   - 提问优化（笼统度判断、澄清对话、智能补全）

2. **路由分发模块**
   - 复杂度评估（规则+分类器）
   - 快车道路由（90%+ 简单查询）
   - 慢车道路由（<10% 复杂查询）

3. **快车道检索模块**
   - 三路并行召回（向量+关键词+结构化）
   - 两阶段重排（粗排+精排）
   - 召回充分性判断
   - 二次检索补救（最多1次）

4. **慢车道检索模块**
   - 工具调用循环（最多3步）
   - 多跳推理支持
   - 跨标准引用处理

5. **答案生成模块**
   - 调用生成大模型
   - 引用溯源标注
   - 事实一致性校验

**技术栈**：
- 框架：FastAPI（异步高性能）
- 任务队列：Celery（长时任务）
- 缓存：Redis（会话、缓存）
- 配置中心：Apollo/Nacos

---

### 第三层：大模型引擎层

**职责**：提供AI能力，包括文本生成、向量嵌入、排序等

**模型清单**：

| 模型类型 | 模型名称 | 用途 | 调用方式 |
|---------|---------|------|---------|
| 生成大模型 | 豆包Pro / 通义千问Turbo | 答案生成、提问优化、查询改写 | API调用 |
| 嵌入模型 | bge-large-zh-v1.5 | 文本向量化 | 本地推理 |
| 重排模型 | bge-reranker-large | 文档重排序 | 本地推理 |
| OCR模型 | PaddleOCR企业版 | 扫描件识别 | 本地推理 |

**模型服务化**：
- 本地模型：使用 vLLM / TorchServe 部署
- 云端模型：通过 SDK 调用（带重试、降级）
- 模型版本管理：MLflow 跟踪

---

### 第四层：索引存储层

**职责**：存储和检索知识库数据

**存储组件**：

1. **向量数据库 - Qdrant**
   - 存储：文档块的稠密向量 + 稀疏向量（BM42）
   - 索引：HNSW图索引 + Scalar Quantization量化
   - 部署：3节点Raft分布式集群
   - 容量：预估100万+向量（约8GB内存）

2. **全文检索引擎 - Elasticsearch**
   - 存储：文档块原始文本
   - 索引：自定义电力术语分词器
   - 查询：BM25相关性排序、短语匹配
   - 部署：3节点集群（1主2副本）

3. **关系数据库 - MySQL 8.0**
   - 存储：文档元数据、用户数据、系统配置
   - 表结构：documents, chunks, queries, feedbacks 等
   - 部署：主从架构 + 读写分离

4. **缓存数据库 - Redis**
   - 热点数据：高频查询结果、用户会话
   - 过期策略：LRU淘汰，TTL 1小时~24小时
   - 部署：哨兵模式（1主2从）

5. **对象存储 - MinIO**
   - 存储：原始PDF、图片、处理后的Markdown
   - 桶设计：raw-docs（原始）、processed-docs（处理后）
   - 部署：分布式模式

---

### 第五层：知识加工层

**职责**：将原始文档转化为可检索的结构化知识

**处理流水线**：

```
原始文档 → 版面解析 → 文本提取 → 结构重建 → 智能分块 
  → 向量化 → 元数据挂载 → 入库索引
```

**核心模块**：

1. **文档解析模块**
   - PDF解析：PyMuPDF（文字版）+ PaddleOCR（扫描版）
   - 版面分析：LayoutLMv3（识别标题、表格、公式）
   - 格式转换：统一转为Markdown

2. **智能分块模块**
   - 国家标准：按条款粒度分块（保留条款号）
   - 专业书籍：按语义知识点分块（保留上下文）
   - 父子块机制：父块512~1024 token，子块128~256 token

3. **元数据增强模块**
   - 基础属性：文档名、标准号、版本号、发布日期
   - 分类属性：专业分类、电压等级、知识类型
   - 权重属性：权威等级、引用频次

4. **术语标准化模块**
   - 术语词典：5000+ 电力专业术语映射
   - 同义词处理：PT→电压互感器，刀闸→隔离开关
   - 缩写展开：自动识别并标注全称

**编排工具**：
- Apache Airflow：定时任务、流程编排
- DAG调度：文档更新检测 → 解析 → 分块 → 入库

---

### 第六层：数据源层

**职责**：提供原始知识数据

**数据源清单**：

| 类型 | 数量（MVP→生产） | 格式 | 更新频率 |
|-----|----------------|------|---------|
| 国家标准 | 10本 → 50+本 | PDF | 季度更新 |
| 专业教材 | 3本 → 10+本 | PDF | 年度更新 |
| 行业规程 | 待扩充 | PDF/Word | 按需更新 |
| 设备手册 | 待扩充 | PDF | 按需更新 |

**版本管理**：
- 标准版本追踪：记录实施日期、废止日期、替代关系
- 自动更新检测：对接国标委API（如有）
- 多版本并存：支持查询历史版本

---

### 第七层：运维管控层

**职责**：保障系统稳定运行，持续优化效果

**核心模块**：

1. **监控告警**
   - 指标采集：Prometheus（QPS、延迟、错误率、召回率）
   - 可视化：Grafana仪表盘
   - 告警规则：P95延迟>3s、错误率>1%、召回率<90%

2. **日志链路追踪**
   - 日志采集：ELK（Elasticsearch + Logstash + Kibana）
   - 链路追踪：Jaeger（分布式trace）
   - 日志规范：结构化日志（JSON格式）

3. **质量评测**
   - 离线评测：RAGAS框架（每周自动跑批）
   - 测试集：200+ 人工标注样本
   - 指标：Recall@3、Recall@5、MRR、事实一致性

4. **Loop Engineering**
   - Prompt自动迭代：每周分析误判case
   - 术语库动态扩展：从用户输入挖掘新术语
   - 难例驱动优化：badcase根因诊断
   - A/B测试自动决策：效果显著时自动全量

5. **权限审计**
   - 用户权限：RBAC（角色-权限）
   - 操作审计：记录关键操作日志
   - 数据脱敏：敏感字段加密存储

## 四、前后端分离架构

```
┌──────────────────┐          ┌──────────────────┐
│                  │          │                  │
│   前端应用层      │  HTTP/   │   后端服务层      │
│   (React/Vue)    │  WS      │   (FastAPI)      │
│                  │ ◄──────► │                  │
│  - 界面渲染      │          │  - 业务逻辑      │
│  - 状态管理      │          │  - 数据处理      │
│  - 路由控制      │          │  - 权限校验      │
│                  │          │                  │
└──────────────────┘          └────────┬─────────┘
                                       │
                              ┌────────▼─────────┐
                              │                  │
                              │   数据存储层      │
                              │  (DB/Cache)      │
                              │                  │
                              └──────────────────┘
```

### 前端职责

- **视图渲染**：组件化UI，响应式布局
- **状态管理**：全局状态（用户信息、配置），局部状态（表单、对话）
- **用户交互**：搜索框、澄清对话、历史记录、反馈收集
- **性能优化**：代码分割、懒加载、缓存策略

### 后端职责

- **API网关**：统一入口，路由分发，限流熔断
- **业务服务**：检索服务、生成服务、用户服务、管理服务
- **数据访问**：ORM封装，连接池管理
- **任务调度**：异步任务（文档入库、批量评测）

### 通信协议

- **HTTP/HTTPS**：RESTful API，标准CRUD操作
- **WebSocket**：流式输出（实时返回生成的文本）
- **数据格式**：JSON（请求/响应体）
- **认证方式**：JWT Token（Bearer Token）

## 五、数据流转示意

```
用户查询 → 前端 → 后端API → 查询预处理 → 路由分发
                                  ↓
                    ┌─────────────┴─────────────┐
                    ↓                           ↓
               快车道检索                    慢车道检索
                    ↓                           ↓
               召回+重排                    工具调用循环
                    ↓                           ↓
               充分性判断                   多步检索
                    ↓                           ↓
             (不充分→二次检索)              结果聚合
                    ↓                           ↓
                    └─────────────┬─────────────┘
                                  ↓
                            答案生成（LLM）
                                  ↓
                            引用溯源 + 校验
                                  ↓
                            返回前端（流式/非流式）
                                  ↓
                            前端渲染展示
```

## 六、技术架构特点

### 1. 高性能

- **异步处理**：FastAPI异步框架，高并发支持
- **缓存策略**：多级缓存（本地内存 + Redis）
- **数据库优化**：索引优化、读写分离、连接池
- **向量检索**：HNSW索引，毫秒级响应

### 2. 高可用

- **无状态服务**：支持水平扩展
- **容器化部署**：Kubernetes编排，自动重启
- **降级策略**：高峰时段自动减少召回数量
- **熔断机制**：下游服务异常时快速失败

### 3. 可扩展

- **模块化设计**：各模块独立部署
- **插件化架构**：新增数据源、检索策略无需改动核心代码
- **配置驱动**：通过配置文件调整参数，无需重新发布

### 4. 可观测

- **全链路追踪**：每个请求分配trace_id
- **结构化日志**：统一日志格式，便于检索分析
- **实时监控**：关键指标实时大屏展示
- **自动告警**：异常情况自动通知（邮件/钉钉/企微）

## 七、安全设计

### 1. 认证授权

- **用户认证**：JWT Token + 刷新令牌机制
- **权限控制**：RBAC模型（管理员/普通用户/只读用户）
- **API限流**：按用户限流（100次/分钟）

### 2. 数据安全

- **传输加密**：HTTPS + TLS 1.3
- **存储加密**：敏感字段AES-256加密
- **SQL注入防护**：ORM参数化查询
- **XSS防护**：前端输入过滤、后端输出转义

### 3. 审计日志

- **操作记录**：记录用户所有关键操作
- **敏感操作**：删除文档、修改配置需二次确认
- **日志保留**：审计日志保留180天

## 八、部署架构

### 开发环境
- 单机 Docker Compose 部署
- 所有服务运行在容器内
- 使用 SQLite / 单节点 Qdrant（简化配置）

### 生产环境
- Kubernetes 集群部署
- 服务多副本（2~3个）
- 数据库集群（主从/分片）
- 负载均衡（Nginx Ingress）
